# 百万 token 上下文下的长视频理解

> 一段 1 小时的 4K 视频，以 24 FPS 进行 patch 和嵌入后，会产生约 6000 万个 token。一集 2 小时的播客转录后约 30,000 个 token。一部完整的蓝光电影，即使经过激进池化压缩，也有数十万个 token。Google 的 Gemini 1.5（2024 年 3 月）以 1000 万 token 上下文开启了这个时代，在小时级视频上实现了可靠的"大海捞针"召回。LWM（Liu 等人，2024 年 2 月）展示了环形注意力的扩展路径。LongVILA 和 Video-XL 进一步扩展了摄入能力。VideoAgent 用智能体检索替代了原始上下文。每种方案在计算、召回和工程复杂度上都有不同的权衡。本课将对它们进行并行解读。

**类型：** 构建
**语言：** Python（标准库，大海捞针模拟器 + 智能体检索路由器）
**前置要求：** 第 12 阶段 · 第 17 课（视频时序 token）
**所需时间：** 约180分钟

## 学习目标

- 计算不同 FPS 和池化方案下长视频的总视觉 token 数量。
- 解释三种扩展路径：暴力上下文（Gemini 1.5）、环形注意力（LWM）、token 压缩（LongVILA / Video-XL）。
- 比较原始上下文视频 VLM 与智能体检索视频 VLM（VideoAgent）在精度和延迟上的差异。
- 为 30 分钟视频设计一个"大海捞针"测试并测量特定分钟的召回率。

## 问题所在

Qwen2.5-VL 规格的 patch 在 384 原生分辨率下，单帧约 729 个 token。3x3 池化后每帧 81 个 token。30 分钟片段，1 FPS = 1800 帧 = 145,800 个 token。2025 年的开放 VLM 可以处理，但很紧张。2 FPS 下为 291,600 个 token——只有最大的上下文窗口才能容纳。

2 小时电影，1 FPS 下为 583k 个 token。超出了 2026 年大多数开放模型的能力；需要 Gemini 2.5 Pro 或更激进的池化。

三条扩展路径应运而生。

## 概念说明

### 路径 1：暴力上下文（Gemini 1.5、Claude Opus）

用硬件暴力解决问题。将上下文扩展到数百万 token，在一次前向传播中处理所有内容。

Gemini 1.5 Pro 以 1M token 启动；Gemini 1.5 Ultra 扩展到 10M；2026 年的 Gemini 2.5 Pro 可以可靠处理数小时的视频。论文（arXiv:2403.05530）记录了在约 9.5M token 范围内 99.7% 的大海捞针召回率。

工程实现：使用内存层级（局部 + 全局 + 稀疏）的自定义注意力实现，加上 MoE 专家路由以提高长上下文效率。未完整公开。未开源。

### 路径 2：环形注意力（LWM、LongVILA）

环形注意力将长序列分布在设备上形成"环"，每台设备持有一个块。全序列注意力通过每台设备将其块以环形模式发送给下一台设备来实现，计算部分注意力，然后聚合。

LWM（Liu 等人，2024）以这种方式训练了 1M token 上下文模型。训练计算量与上下文线性增长，而非二次方——注意力的二次方开销被环中各设备分摊。

LongVILA（arXiv:2408.10188）将此模式适配到 VLM。1400 帧视频，每帧 192 个 token = 268k 上下文，使用 8 路并行的环形注意力训练。

### 路径 3：token 压缩（Video-XL、LongVA）

比暴力上下文更便宜：在 LLM 看到序列之前进行激进压缩。

Video-XL（arXiv:2409.14485）使用视觉摘要 token：每 N 帧的片段产生一个"摘要"token，对这 N 帧进行交叉注意力。推理时，LLM 每个片段只看到一个摘要 token，大幅缩减上下文。

LongVA 通过"长上下文迁移"技术将 LLM 上下文从 200k 扩展到 2M。在长上下文文本上训练，通过共享表示迁移到长上下文视频。

token 压缩以特定时间戳的召回为代价换取可扩展性。模型大体知道发生了什么，但有时会错过确切帧。

### 路径 4：智能体检索（VideoAgent）

不要将完整视频喂给 LLM。相反，将视频视为数据库，用 LLM 来查询它。

VideoAgent（arXiv:2403.10517）：

1. LLM 阅读问题。
2. LLM 向检索工具请求相关片段（"给我看有猫的片段"）。
3. 工具返回匹配片段的时间戳。
4. LLM 通过 VLM 阅读这些片段。
5. LLM 组织答案或提出后续查询。

这是 LLM-as-Agent 模式在长视频上的应用。推理更便宜（只编码相关片段），工程更复杂（检索质量成为瓶颈）。

### 大海捞针基准测试

标准长上下文测试：在视频的随机位置插入一个独特的视觉或文本标记，然后提出需要回忆它的查询。

指标：跨视频长度和标记位置的 Recall@k。

Gemini 2.5 Pro 在长达 90 分钟的视频上得分 >99% 召回率。开放 72B 模型（Qwen2.5-VL-72B、InternVL3-78B）在 30 分钟时得分约 85-90%，超过 60 分钟后开始下降。

VideoAgent 可以在 2 小时以上匹配或超越原始上下文模型，因为如果工具质量好，检索能找到"针"。

### 如何选择路径

对于 15 分钟片段、要求前沿精度：开放 72B + 原生上下文通常可行。选择 Qwen2.5-VL-72B。

对于 30 分钟到 1 小时内容：开放模型选 LongVILA 或 Video-XL；闭源模型选 Gemini 2.5 Pro。质量标准很重要——前沿水平通常选闭源。

对于 2 小时以上内容：VideoAgent 或类似检索模式。或者，先摘要为较小块，再分层摘要。

### 2026 年生产模式

实际生产中，长视频管道是混合式的：

1. 对整个视频运行动态 FPS 采样 + 激进池化（获得 100k token 的全局表示）。
2. 传给 72B VLM 生成全局摘要。
3. 如果用户提出详细问题，使用摘要作为索引运行智能体检索。

这结合了暴力上下文的全局理解和检索的局部细节。

## 练习

1. 一段 45 分钟的讲座，1 FPS，每帧 81 个 token。总 token 数是多少？能装进哪些模型的上下文？

2. 设计一个大海捞针测试：在第几分钟注入标记？查询格式是什么？

3. 在 1 小时视频上比较暴力上下文 Qwen2.5-VL-72B（80k 上下文）与 VideoAgent（Claude 3.5 + 检索）。哪个召回率更高？哪个延迟更低？

4. 环形注意力的内存成本与序列长度线性增长，与设备数量线性增长。解释原因，以及如果去掉环形旋转阶段会发生什么。

5. 阅读 Gemini 1.5 第 5 节关于大海捞针的内容。论文在 1M vs 10M token 边界上的召回率发现了什么？

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------|----------|
| 暴力上下文 | "更多 token" | 将 LLM 上下文扩展到数百万 token；一次处理所有内容 |
| 环形注意力 | "LWM 风格并行" | 分布式注意力模式，每台设备持有一个块并轮转 |
| token 压缩 | "摘要 token" | 通过学习的压缩器在 LLM 之前减少每片段的 token 数 |
| 大海捞针 | "NIH 测试" | 在随机位置插入独特标记，让模型在测试时回忆 |
| 智能体检索 | "LLM 作为查询规划器" | LLM 向检索工具请求相关片段，通过 VLM 阅读，组织答案 |
| VideoAgent | "视频检索模式" | 标准智能体检索设计：问题 → 工具 → 片段 → 答案 |

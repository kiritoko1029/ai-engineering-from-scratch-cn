# Show-o 与离散扩散统一模型

> Transfusion 混合了连续和离散表示。Show-o（Xie 等人，2024 年 8 月）则走了一条相反的路线：文本 token 使用因果式下一 token 预测，图像 token 使用基于 MaskGIT 思路的掩码离散扩散。两者共存于同一个 Transformer 中，通过混合注意力掩码协调工作。最终在单一骨干网络上统一了视觉问答（VQA）、文本生成图像（T2I）、图像修复（Inpainting）和混合模态生成——每种模态各一个 tokenizer，统一的损失公式（将下一 token 预测扩展为掩码预测）。本课将深入 Show-o 的设计——为什么掩码离散扩散是一种并行、少步数的图像生成器——并将其与 Transfusion 和 Emu3 进行对比。

**类型：** 学习
**语言：** Python（标准库，掩码离散扩散采样器）
**前置要求：** 第 12 阶段 · 第 13 课（Transfusion）
**所需时间：** 约120分钟

## 学习目标

- 解释掩码离散扩散：一种均匀掩码 token 并让 Transformer 恢复它们的调度方案。
- 比较并行图像解码（Show-o、MaskGIT）与自回归图像解码（Chameleon、Emu3）在速度和质量上的差异。
- 列出 Show-o 在单一检查点中处理的三种任务：T2I、VQA、图像修复。
- 选择一种掩码调度方案（余弦、线性、截断）并分析其对样本质量的影响。

## 问题所在

Transfusion 的双损失训练虽然有效，但动态特性更复杂——连续扩散损失与离散 NTP 损失处于不同的数值尺度上。平衡损失权重本身就是一个超参数搜索过程。架构虽然有效但较为复杂。

Show-o 的回答是：保持两种模态均为离散形式（类似 Chameleon），但通过掩码离散扩散而非逐 token 顺序生成来并行生成图像。训练目标变成统一的掩码 token 预测，自然地泛化了下一 token 预测。

## 概念说明

### 掩码离散扩散（MaskGIT）

Chang 等人（2022）提出的 MaskGIT 技巧非常优雅。从完全掩码的图像开始（每个 token 都是特殊的 `<MASK>` ID）。每一步中，对所有被掩码的 token 进行并行预测，保留置信度最高的 top-K 个预测结果，重新掩码其余部分。经过约 8-16 次迭代后，所有 token 都被填充完毕。每步揭开多少 token 的调度方案需要调优——余弦调度效果良好。

训练过程很简单：从 [0, 1] 均匀采样一个掩码比例，将其应用于图像的 VQ token，训练 Transformer 恢复被掩码的 token。这与 BERT 对文本所做的完全一致，只是扩展到了图像生成领域。

### Show-o：单一 Transformer，混合掩码

Show-o 将 MaskGIT 嵌入因果语言模型 Transformer 中。注意力掩码的设计如下：

- 文本 token：因果式（标准 LLM）。
- 图像 token：在图像块内部完全双向（使被掩码的 token 在预测时可以看到所有其他图像 token）。
- 文本到图像：文本关注先前的图像，图像关注先前的文本。

训练在以下三种模式之间交替：
1. 对文本序列进行标准 NTP。
2. T2I 样本：文本 → 图像，图像 token 被掩码，使用掩码 token 预测损失。
3. VQA 样本：图像 → 文本，文本 token 被掩码（本质上就是 NTP）。

统一损失是对 `<MASK>` token 的交叉熵，它同时覆盖了文本 NTP（只有最后一个 token 被"掩码"）和图像掩码扩散（随机子集被掩码）。

### 并行采样

Show-o 生成一张图像只需约 16 步，而非约 1000 步（逐 token 自回归）或约 20 步（扩散）。每一步中，对所有被掩码的 token 进行并行预测；保留置信度最高的 top-K 个结果；重复此过程。

对比：
- Chameleon / Emu3（逐 token 自回归）：N_tokens 次前向传播，通常每张图像需要 1024-4096 次。
- Transfusion（连续扩散）：约 20 步，每步一次完整的 Transformer 前向传播。
- Show-o（掩码离散扩散）：约 16 步，每步一次完整的 Transformer 前向传播。

在相近规模的模型上，Show-o 比 Chameleon 更快，步数大致与 Transfusion 相当，但每步成本更低（离散词汇表 logits vs 连续 MSE 损失）。

### 单一检查点支持多种任务

Show-o 在推理时支持四种任务，通过提示格式选择：

- 文本生成：标准自回归文本输出。
- VQA：输入图像，输出文本。
- T2I：输入文本，通过掩码离散扩散输出图像。
- 图像修复：输入部分 token 被掩码的图像，填充缺失部分。

修复能力是掩码预测训练的"免费赠品"。掩码 VQ token 网格中的某个区域，将其余部分加上文本提示一起输入，预测被掩码的 token。

### 掩码调度

每步揭开多少 token 的调度方案影响生成质量。Show-o 推荐余弦调度：

```
mask_ratio(t) = cos(pi * t / (2 * T))   # t = 0..T
```

在第 0 步时，所有 token 被掩码（比例 1.0）。在第 T 步时，无掩码。余弦函数将概率质量集中在中间范围，此时预测最具信息量。线性调度也可行，但更快达到平台期。

### Show-o2

Show-o2（2025 年后续版本，arXiv 2506.15564）对 Show-o 进行了扩展：更大的 LLM 基座、更好的 tokenizer、改进的掩码调度。架构模式保持一致。

### Show-o 在分类体系中的位置

在 2026 年的分类体系中：

- 离散 token + NTP：Chameleon、Emu3。简单但推理慢。
- 离散 token + 掩码扩散：Show-o、MaskGIT、LlamaGen、Muse。并行采样，仍受限于 tokenizer 的有损压缩。
- 连续 + 扩散：Transfusion、MMDiT、DiT。质量最高，训练更复杂。
- 连续 + VLM 中的流匹配：JanusFlow、InternVL-U。最新方案。

按任务选择：当你需要在单一开放模型中同时获得 T2I + 修复 + VQA 且速度合理时，选择 Show-o；当质量至上且你能承受双损失管道的复杂度时，选择 Transfusion。

## 练习

1. 掩码离散扩散采样约需 16 步。为什么不是 1 步？如果在第 0 步就揭开所有 token 会怎样？

2. 掩码扩散天然支持修复功能。提出一个产品用例（真实或假设），其中 Show-o 的修复能力优于专业模型。

3. 余弦调度 vs 线性调度：在 T=8 时追踪每步揭开的 token 数量。哪种更均衡？

4. 一张 512x512 的 Show-o 图像包含 1024 个 token。在词汇表大小 K=16384 时，模型输出 1024 * log2(16384) = 14,336 比特（约 1.75 KiB）的数据。Stable Diffusion 输出 512*512*24 比特 = 6,291,456 比特（约 768 KiB）的原始像素。压缩比是多少？质量表现如何？

5. 阅读 LlamaGen（arXiv:2406.06525）。LlamaGen 的类别条件自回归图像模型与 Show-o 的掩码方法有何不同？

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------|----------|
| 掩码离散扩散 | "MaskGIT 风格" | 训练模型预测被掩码的 token；推理时迭代式揭开置信度最高的预测 |
| 余弦调度 | "揭开调度" | 推理步数中掩码比例的衰减方式；将置信度增长集中在中间范围 |
| 并行解码 | "一次生成所有 token" | 每步通过一次前向传播预测完整的被掩码 token 序列，然后提交 top-K |
| 混合注意力 | "因果 + 双向" | 对文本 token 使用因果掩码，在图像块内部使用双向掩码 |
| 图像修复 | "填充式生成" | 以部分 token 被掩码的图像为条件，预测缺失部分；来自训练目标的天然能力 |
| 提交率 | "每步 top-K" | 每次迭代中被声明"完成"的 token 数量；控制推理速度与质量的权衡 |

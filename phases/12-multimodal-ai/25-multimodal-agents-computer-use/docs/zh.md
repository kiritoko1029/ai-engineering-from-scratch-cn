# 多模态智能体与计算机使用（毕业项目）

> 2026 年的前沿产品是一个多模态智能体，它能阅读截图、点击按钮、导航 Web UI、填写表单并端到端完成工作流。SeeClick 和 CogAgent（2024）证明了 GUI 定位原语。Ferret-UI 扩展到移动端。ChartAgent 引入了图表的视觉工具使用。VisualWebArena 和 AgentVista（2026）是前沿追逐的基准测试——即使是 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的困难任务上也只得分约 30%。这个毕业项目汇集了第 12 阶段的每条线索：感知（高分辨率 VLM）、推理（带工具使用的 LLM）、定位（坐标输出）、长时域记忆和评估。

**类型：** 毕业项目
**语言：** Python（标准库，动作 schema + 智能体循环骨架）
**前置要求：** 第 12 阶段 · 第 05 课（LLaVA），第 12 阶段 · 第 09 课（Qwen-VL JSON），第 14 阶段（智能体工程）
**所需时间：** 约240分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。
- 构建 VLM 可以输出为 JSON 的 GUI 定位输出 schema（点击坐标、输入文本、滚动、拖拽）。
- 比较仅截图智能体 vs 无障碍树智能体 vs 混合智能体。
- 在小型 VisualWebArena 切片上设置多模态智能体基准评估。

## 问题所在

一个订票网站的工作流："帮我找 4 月 15 日去东京的航班，靠过道座位，800 美元以下，订它。"

多模态智能体需要：

1. 截取浏览器截图。
2. 将截图 + URL + 目标解析为计划。
3. 输出结构化动作：点击（在 x,y）、输入"Tokyo"（在元素 E）、向下滚动、选择（单选按钮）。
4. 将动作应用到浏览器。
5. 观察新状态（下一张截图）。
6. 重复直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析的 JSON。错误在步骤间累积，因此恢复很重要。

## 概念说明

### GUI 定位——原语

GUI 定位是：给定一张截图和自然语言指令，输出要点击的 (x, y) 坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是首个大规模的开放结果：在合成 + 真实 GUI 数据上微调 VLM，以纯文本 token 输出坐标。有效。

CogAgent（arXiv:2312.08914）为密集 UI 增加了 1120x1120 高分辨率编码。得分：Web 导航约 84%。

Ferret-UI（arXiv:2404.05719）聚焦移动端 UI，集成 iOS 无障碍数据。

输出格式通常是 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于恢复：如果坐标在截图之间漂移，语义提示让系统可以重新定位。

### 动作 schema

典型动作 schema 有 6-10 种动作类型：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

智能体每步输出一个动作。浏览器包装器执行并返回新状态。

### 仅截图 vs 无障碍树

两种输入模式：

- 仅截图：完整图像，无结构信息。最通用；适用于任何应用。
- 无障碍树：结构化的 DOM / iOS 无障碍信息。定位更可靠；在树可用时有效。
- 混合：两者兼有，树作为原子动作的可靠定位器，截图提供语义上下文。

生产智能体在可能时使用混合模式。浏览器自动化（Selenium + 无障碍）始终有树；桌面应用有时有。

### 长时域记忆

20 步工作流生成 20 张截图。VLM 的上下文很快填满。三种压缩策略：

- 摘要链：每 5 步后，总结已发生的事情，丢弃旧截图。
- 跳帧：保留第一帧、最后一帧和每第 3 帧截图。
- 工具记录日志：执行动作，保留文本日志记录已完成的操作；不再回看旧截图。

Claude 的计算机使用 API 使用日志模式。更简单，更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）引入了图表理解的视觉工具使用：裁剪、缩放、OCR、调用外部检测。智能体可以输出"裁剪到区域 (100, 200, 300, 400) 然后调用 OCR"作为工具调用。工具返回文本；VLM 继续推理。

此模式可推广：集合标记提示、区域注释和外部检测工具都适合相同的"输出工具调用，接收结构化响应"schema。

### 2026 年基准测试

- ScreenSpot-Pro。约 1000 张 Web 截图上的 GUI 定位。开放 SOTA Qwen2.5-VL-72B 约 85%。前沿约 90%。
- VisualWebArena。端到端 Web 任务（商店、论坛、分类广告）。开放 SOTA 约 20%。Gemini 3 Pro 约 27%。
- AgentVista（arXiv:2602.23166）。2026 年最困难的基准测试。跨 12 个领域的真实工作流。前沿模型得分 27-40%；开放模型 10-20%。
- WebArena / WebShop。较旧的基准测试；已被前沿饱和。

### 为什么仍然困难

智能体性能瓶颈：

1. 细粒度视觉定位。"点击小 X"在移动端分辨率下经常失败。
2. 长时域规划。10 个动作后，智能体偏离目标。
3. 错误恢复。当点击失败（错误按钮）时，检测 + 恢复很少被训练数据覆盖。
4. 跨页面上下文。在标签页之间跳转或长表单会丢失状态。

研究方向：记忆架构、显式重规划、多模态验证（截图匹配验证动作成功）。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------|----------|
| GUI 定位 | "点击坐标" | 模型在截图上输出指令目标的 (x,y) 坐标 |
| 动作 schema | "工具定义" | 有效动作（点击、输入、滚动、拖拽）的 JSON 描述 |
| 无障碍树 | "结构化 DOM" | 来自浏览器/iOS API 的机器可读 UI 层级 |
| 混合智能体 | "截图 + 树" | 同时使用图像和结构化信息；比单独使用任一更可靠 |
| 视觉工具使用 | "缩放/裁剪/检测" | 智能体在计划中调用外部视觉工具（OCR、检测） |
| 摘要链 | "记忆压缩" | 定期文本摘要替代长截图历史 |
| VisualWebArena | "端到端 Web 基准" | 2024 年端到端 Web 任务基准测试 |
| AgentVista | "2026 困难基准" | 12 领域真实工作流；即使是 Gemini 3 Pro 也只得分约 30% |

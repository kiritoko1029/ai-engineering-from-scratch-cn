# 失败模式：智能体为何崩溃

> MASFT（伯克利，2025）将 14 种多智能体失败模式归入 3 个类别。微软的分类法记录了现有 AI 失败如何在智能体场景中被放大。行业实地数据汇聚于五种反复出现的模式：幻觉操作、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置要求：** 第 14 阶段 · 05（Self-Refine 与 CRITIC），第 14 阶段 · 24（可观测性）
**所需时间：** 约60分钟

## 学习目标

- 说出 MASFT 的三个失败类别以及每个类别中至少四种具体模式。
- 解释为什么智能体失败会放大现有的 AI 失败模式（偏见、幻觉）。
- 描述五种行业反复出现的模式及其缓解措施。
- 实现一个标准库检测器，为智能体追踪标注失败模式标签。

## 问题所在

团队发布的智能体在 90% 的追踪上能工作。那 10% 的失败不是随机噪声 — 它们落入少数反复出现的类别。一旦你能命名它们，就能监控并修复它们。

## 概念说明

### MASFT（伯克利，arXiv:2503.13657）

多智能体系统失败分类法。14 种失败模式聚类为 3 个类别。标注者间 Cohen's Kappa 为 0.88 — 这些类别可以可靠区分。

核心主张：失败是多智能体系统的基本设计缺陷，而非可以通过更好的基础模型修复的 LLM 局限性。

### 微软智能体 AI 系统失败模式分类法

- 现有的 AI 失败（偏见、幻觉、数据泄露）在智能体场景中被放大。
- 自主性带来新的失败：大规模非预期操作、工具误用、任务漂移。
- 白皮书是智能体产品的风险登记册。

### 智能体 AI 中的故障特征（arXiv:2603.06847）

- 失败源于编排、内部状态演化和环境交互。
- 不仅仅是"代码有问题"或"模型输出有问题"。

### LLM 智能体幻觉综述（arXiv:2509.18970）

两种主要表现：

1. **指令遵循偏差** — 智能体不遵循系统提示词。
2. **长程上下文误用** — 智能体忘记或误用早期轮次的上下文。

子意图错误：遗漏（缺失步骤）、冗余（重复步骤）、乱序（步骤顺序错误）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain 2024-2026 年实地分析汇聚于：

1. **幻觉操作。** 智能体调用不存在的工具或编造参数。
2. **范围蔓延。** 智能体将任务扩展到用户要求之外（创建额外 PR、发送额外邮件）。
3. **级联错误。** 一个错误调用触发下游影响。一个幻觉的 SKU 触发四次 API 调用 — 多系统事故。
4. **上下文丢失。** 长程任务忘记早期轮次的约束。
5. **工具误用。** 用错误参数调用正确的工具，或完全调用错误的工具。

级联是致命的。智能体无法区分"我失败了"和"任务不可能完成"，经常在 400 错误上幻觉出成功消息来结束循环。

### 缓解：每步设置验证门

在推理链的每一步设置自动验证门，根据环境状态检查事实依据。具体来说：

- 每步安全分类器（第 21 课）。
- 工具调用参数验证（第 06 课）。
- 将检索内容与已知事实交叉检查（第 05 课，CRITIC）。
- 通过重新探测状态检测成功幻觉（文件真的被创建了吗？）。

### 失败监控出问题的地方

- **只标记崩溃。** 大多数智能体失败产生看起来正常的输出。需要内容级检查。
- **没有基线。** 漂移检测需要一个最近已知正常状态；没有它你就无法判断"情况在变差"。
- **过度告警。** 每个失败都产生告警。应聚类并限流。

## 开始构建

`code/main.py` 实现了一个标准库失败模式标记器：

- 覆盖五种模式的合成追踪数据集。
- 每种模式的检测函数（工具调用、输出、重复操作的签名模式）。
- 标记器为每条追踪打标签并报告模式分布。

运行方式：

```
python3 code/main.py
```

输出：每条追踪的标签 + 聚合分布，是 Phoenix 追踪聚类功能的廉价复现。

## 使用建议

- **Phoenix** — 生产漂移聚类（第 24 课）。
- **Langfuse** — 会话回放 + 标注。
- **自定义** — 你的可观测性平台无法检测的领域特定签名。

## 交付产物

`outputs/skill-failure-detector.md` 生成针对你领域的失败模式检测器，接入追踪存储。

## 练习

1. 为"成功幻觉"添加一个检测器：智能体返回成功但目标状态未变。
2. 标记你构建过的产品的 100 条真实追踪。哪种模式占主导？修复它的成本是多少？
3. 实现一个"级联半径"指标：给定第 N 步的失败，它影响了多少下游步骤？
4. 阅读 MASFT 的 14 种失败模式。挑选三种适用于你产品的模式。编写检测器。
5. 将一个检测器接入 CI 任务：如果 >=5% 的追踪标记了某模式则构建失败。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| MASFT | "多智能体失败分类法" | 伯克利 14 模式分类 |
| 级联错误 | "涟漪失败" | 一个早期错误传播经过 N 步 |
| 上下文丢失 | "忘记约束" | 长程轮次丢失早期轮次的事实 |
| 工具误用 | "错误工具/错误参数" | 有效的调用，错误的使用 |
| 成功幻觉 | "伪造完成" | 智能体在 400 错误上声称成功；状态未变 |
| 范围蔓延 | "越界" | 智能体做了超出要求的事 |
| 指令遵循偏差 | "不服从" | 忽略系统提示词或用户约束 |
| 子意图错误 | "计划缺陷" | 计划执行中的遗漏、冗余、乱序 |

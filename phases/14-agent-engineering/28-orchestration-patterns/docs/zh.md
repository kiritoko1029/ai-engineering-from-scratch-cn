# 编排模式：主管、群组、层级

> 四种编排模式在 2026 年的框架中反复出现：主管-工作者、群组/对等、层级、辩论。Anthropic 的指导："关键在于构建适合你需求的系统。"从简单开始；只有当单个智能体加五种工作流模式不够时才添加拓扑。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置要求：** 第 14 阶段 · 12（工作流模式），第 14 阶段 · 25（多智能体辩论）
**所需时间：** 约60分钟

## 学习目标

- 说出四种反复出现的编排模式及其适用场景。
- 描述 2026 年 LangChain 的推荐：基于工具调用的监督 vs 主管库。
- 解释 Anthropic 的"构建适合你的系统"规则及其如何决定拓扑选择。
- 在标准库中针对通用脚本化 LLM 实现全部四种模式。

## 问题所在

团队在真正需要之前就追求"多智能体"。四种模式在各框架中反复出现；一旦你能命名它们，就能选择正确的那一种 — 或者完全跳过拓扑。

## 概念说明

### 主管-工作者

- 中央路由 LLM 分派到专家智能体。
- 决定：循环回自身、交给专家、终止。
- 专家之间不通信；所有路由都经过主管。

框架：LangGraph `create_supervisor`、Anthropic 编排器-工作者、CrewAI 层级流程。

**2026 年 LangChain 推荐：** 通过直接工具调用而非 `create_supervisor` 进行监督。提供更精细的上下文工程控制 — 你决定每个专家看到什么。

### 群组/对等

- 智能体通过共享工具面直接交接。
- 无中央路由器。
- 延迟低于主管（更少跳数）。
- 更难推理（没有单一控制点）。

框架：LangGraph 群组拓扑、OpenAI Agents SDK 交接（当所有智能体都能相互交接时）。

### 层级

- 主管管理子主管管理工作者。
- 在 LangGraph 中实现为嵌套子图；在 CrewAI 中实现为嵌套 crew。
- 以运营复杂性为代价扩展到大规模智能体群。

适用场景：当单个主管的上下文预算无法容纳所有专家的描述时。

### 辩论

- 并行提议者 + 迭代交叉批评（第 25 课）。
- 并非真正的编排 — 更多是验证 — 但在框架中作为拓扑选择出现。

### CrewAI Crew vs Flow

CrewAI 将两种部署模式形式化：

- **Flow** — 确定性事件驱动自动化（生产推荐起点）。
- **Crew** — 自主的基于角色的协作。

这与上述四种模式正交，但映射到拓扑：Flow 通常是主管或层级；Crew 通常是带 LLM 路由的主管。

### Anthropic 的指导

"在 LLM 领域的成功不是关于构建最复杂的系统，而是关于构建适合你需求的系统。"

决策顺序：

1. 单个智能体 + 工作流模式（第 12 课）— 从这里开始。
2. 主管-工作者 — 当你有 2-4 个专家时。
3. 群组 — 当延迟比推理清晰度更重要时。
4. 层级 — 仅当主管上下文预算不足时。
5. 辩论 — 当准确率比成本更重要时。

### 这个模式出问题的地方

- **拓扑优先思维。** 在确定多智能体解决什么问题之前就"我们需要多智能体"。
- **群组中来回交接。** A -> B -> A -> B。使用跳数计数器。
- **假层级。** 因为"企业级"搞三层；实际只有两个团队。合并。

## 开始构建

`code/main.py` 在标准库中针对脚本化 LLM 实现全部四种模式：

- `Supervisor` — 中央路由器。
- `Swarm` — 带直接交接的对等网络。
- `Hierarchical` — 主管的主管。
- `Debate` — 并行提议者 + 批评。

每种模式处理相同的三意图任务（退款 / 故障 / 销售）。追踪形态各不相同。

运行方式：

```
python3 code/main.py
```

输出：每种模式的追踪 + 操作数。主管最清晰；群组最短；层级最深；辩论最昂贵。

## 使用建议

- **LangGraph** — 主管和层级（嵌套子图）。
- **OpenAI Agents SDK** — 工具形式的交接（主管形态）。
- **CrewAI Flow** — 生产确定性场景。
- **自定义** — 辩论或需要精确控制时。

## 练习

1. 将主管-工作者转换为群组，移除路由器。什么会出问题？什么会改善？
2. 为群组添加跳数计数器：3 次交接后拒绝。它能捕捉 A->B->A 的来回跳转吗？
3. 为 12 个专家的领域构建一个两层层级系统。没有嵌套时上下文预算在哪里不够用？
4. 在生产形态的工作负载上对四种模式进行性能分析。哪种在哪项指标上胜出（延迟、成本、准确率、可调试性）？
5. 阅读 Anthropic 的"Building Effective Agents"文章。将你的每个生产流程映射到四种模式之一。有没有不好映射的？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| 主管-工作者 | "路由器 + 专家" | 中央 LLM 分派到专家；专家之间不通信 |
| 群组 | "对等网络" | 通过共享工具直接交接；无中央路由器 |
| 层级 | "主管的主管" | 用于大规模智能体群的嵌套子图 |
| 辩论 | "提议者 + 批评" | 并行提议者、交叉批评（第 25 课） |
| 基于工具调用的监督 | "无库的主管" | 将主管实现为直接工具调用以控制上下文 |
| Crew | "自主团队" | CrewAI 基于角色的协作模式 |
| Flow | "确定性工作流" | CrewAI 事件驱动的生产模式 |

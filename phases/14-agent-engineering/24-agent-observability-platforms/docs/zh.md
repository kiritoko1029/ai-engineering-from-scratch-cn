# 智能体可观测性：Langfuse、Phoenix、Opik

> 三个开源智能体可观测性平台在 2026 年占据主导地位。Langfuse（MIT）— 月安装量 600 万+，提供追踪 + 提示词管理 + 评估 + 会话回放。Arize Phoenix（Elastic 2.0）— 深度智能体专用评估、RAG 相关性、OpenInference 自动检测。Comet Opik（Apache 2.0）— 自动提示词优化、护栏、LLM 评委幻觉检测。

**类型：** 学习
**语言：** Python（标准库）
**前置要求：** 第 14 阶段 · 23（OTel GenAI）
**所需时间：** 约45分钟

## 学习目标

- 说出三大开源智能体可观测性平台及其许可证。
- 区分各自的最强项：Langfuse（提示词管理 + 会话）、Phoenix（RAG + 自动检测）、Opik（优化 + 护栏）。
- 解释为什么 89% 的组织报告到 2026 年已具备智能体可观测性。
- 实现一个标准库追踪到仪表盘的管道，包含 LLM 评委评估。

## 问题所在

OTel GenAI（第 23 课）提供了模式。你仍然需要一个能摄取 span、运行评估、存储提示词版本并暴露回归的平台。三个竞争者各自侧重生命周期的不同部分。

## 概念说明

### Langfuse（MIT）

- 月 SDK 安装量 600 万+，GitHub 星标 19k+。
- 功能：追踪、带版本控制和沙盒的提示词管理、评估（LLM 评委、用户反馈、自定义）、会话回放。
- 2025 年 6 月：原先的商业模块（LLM 评委、标注队列、提示词实验、沙盒）以 MIT 开源。
- 最强项：端到端可观测性与紧密的提示词管理循环。

### Arize Phoenix（Elastic License 2.0）

- 更深入的智能体专用评估：追踪聚类、异常检测、RAG 检索相关性。
- 原生 OpenInference 自动检测。
- 可与托管的 Arize AX 配合用于生产。
- 无提示词版本管理 — 定位为更广泛平台之外的漂移/行为回归工具。
- 最强项：RAG 相关性、行为漂移、异常检测。

### Comet Opik（Apache 2.0）

- 通过 A/B 实验实现自动提示词优化。
- 护栏（PII 脱敏、主题约束）。
- 评委幻觉检测。
- Comet 自身的基准测量：Opik 日志 + 评估耗时 23.44s vs Langfuse 327.15s（约 14 倍差距）— 厂商基准仅供参考方向。
- 最强项：优化循环、自动实验、护栏执行。

### 行业数据

根据 Maxim（2026 年实地分析）：89% 的组织已具备智能体可观测性；质量问题是首要生产障碍（32% 的受访者提及）。

### 如何选择

| 需求 | 选择 |
|------|------|
| 一体化且带提示词管理 | Langfuse |
| 深度 RAG 评估 + 漂移 | Phoenix |
| 自动优化 + 护栏 | Opik |
| 开放许可证，不要 ELv2 | Langfuse（MIT）或 Opik（Apache 2.0） |
| Datadog / New Relic 集成 | 任意 — 它们都导出 OTel |

### 这个模式出问题的地方

- **没有评估策略。** 没有评估的追踪只是昂贵的日志。
- **自建 LLM 评委缺乏依据。** CRITIC 模式（第 05 课）适用 — 评委需要外部工具进行事实验证。
- **提示词版本未关联追踪。** 生产回归时，你无法二分定位到导致问题的提示词。

## 开始构建

`code/main.py` 实现了一个标准库追踪收集器 + LLM 评委评估器：

- 摄取 GenAI 格式的 span。
- 按会话分组，标记失败运行（护栏触发、低置信度评估）。
- 脚本化的 LLM 评委，按评分标准对智能体响应打分。
- 类似仪表盘的摘要：失败率、首要失败原因、评估分数分布。

运行方式：

```
python3 code/main.py
```

输出：每会话的评估分数和失败分类，与 Langfuse/Phoenix/Opik 展示的内容一致。

## 使用建议

- **Langfuse** 自托管或云端；通过 OTel 或其 SDK 接入。
- **Arize Phoenix** 自托管；自动检测 OpenInference。
- **Comet Opik** 自托管或云端；自动优化循环。
- **Datadog LLM Observability** 适用于已运行 Datadog 的运维 + ML 混合团队。

`outputs/skill-obs-platform-wiring.md` 选择一个平台并将追踪 + 评估 + 提示词版本接入现有智能体。

## 练习

1. 将一周的 OTel 追踪导出到 Langfuse 云端（免费层）。哪些会话失败了？为什么？
2. 为你的领域编写一份 LLM 评委评分标准（事实正确性、语气、范围遵守）。在 50 条追踪上测试。
3. 比较 Langfuse 提示词版本管理与 Phoenix 的追踪聚类。哪个能更快告诉你什么出了问题？
4. 阅读 Opik 的护栏文档。为你的一个智能体运行接入 PII 脱敏护栏。
5. 在你的语料库上对三个平台进行基准测试。忽略厂商发布的数据；自己测量。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| 追踪 | "Span 收集器" | 摄取 OTel / SDK span；按会话索引 |
| 提示词管理 | "提示词 CMS" | 与追踪关联的版本化提示词 |
| LLM 评委 | "自动评估" | 独立 LLM 按评分标准为智能体输出打分 |
| 会话回放 | "追踪回放" | 逐步回放历史运行以调试 |
| RAG 相关性 | "检索质量" | 检索到的上下文是否匹配查询 |
| 追踪聚类 | "行为分组" | 聚类相似运行以检测漂移 |
| 护栏执行 | "日志时策略" | 对记录内容进行 PII/毒性/范围检查 |

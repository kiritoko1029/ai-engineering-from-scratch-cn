# 为何选择 Transformer——RNN 的局限性

> RNN会逐个处理标记，而Transformer则能一次性处理所有标记。这一架构上的抉择改变了2017年之后深度学习领域的所有发展曲线。

**类型：** 学习
**语言：** Python
**先修课程：** 第3阶段（深度学习核心）、第5·09阶段（序列到序列模型）、第5·10阶段（注意力机制）
**时长：** 约45分钟

## 问题所在

在2017年之前，全球所有最先进的序列模型——无论是语言处理、翻译还是语音识别领域——都属于循环神经网络。LSTM和GRU在长达半十年的时间里一直霸占着类似ImageNet标准的翻译评测榜单的榜首。它们是当时人们唯一可用的工具。

然而这些模型存在三个致命缺陷。由于采用顺序计算方式，无法沿时间轴进行并行处理：`t+1`时刻的token需要依赖`t`时刻的隐藏状态。对于一个包含1,024个token的序列，在每周期可执行1,000,000次浮点运算的GPU上也需要进行1,024次串行计算。在专为并行处理设计的硬件上，训练时间会与序列长度呈线性增长。

梯度消失问题意味着距离当前位置50个token远的信息早已经过50次非线性变换而被严重压缩。虽然门控循环单元（LSTM、GRU）在一定程度上缓解了这一问题，但并未彻底解决。长距离依赖关系——例如“我去年夏天在去京都的飞机上看的那本书是……”这类描述——往往无法被准确处理。

固定宽度的隐藏状态意味着编码器会在解码器看到任何信息之前，就将整个源序列压缩为一个向量。无论源序列包含5个token还是500个token，其瓶颈都在于相同的向量结构。

2017年发表的论文《Attention Is All You Need》提出了一种激进的理念：完全摒弃循环结构，让每个位置都能并行地关注其他所有位置。通过一次大规模矩阵乘法完成训练，而非之前的1,024次串行运算。

到2026年，这种架构已主导了所有模态的任务处理——包括语言处理（GPT-5、Claude 4、Llama 4）、视觉处理（ViT、DINOv2、SAM 3）、音频处理（Whisper）、生物学研究（AlphaFold 3）以及机器人技术（RT-2）。核心结构相同，仅输入数据不同。

## 概念概述

![RNN序列计算与Transformer并行注意力机制对比](../assets/rnn-vs-transformer.svg)

**循环结构的瓶颈。** RNN通过公式 `h_t = f(h_{t-1}, x_t)` 进行计算，每一步都依赖于前一步的结果。因此无法在计算出 `h_4` 之前就计算 `h_5`。在拥有10,000多个并行核心的现代GPU上，处理长序列时会导致99%的芯片资源被浪费。

**注意力机制的广播特性。** 自注意力机制会同时为每一对 `(i, j)` 计算 `output_i = sum_j(a_ij * v_j)` 的结果。整个N×N的注意力矩阵可以通过一次批量矩阵乘法完成填充，各步骤之间互不依赖，非常适合GPU处理。

**加速效果并非恒定不变。** 其本质在于串行深度从 `O(N)` 变为 `O(1)` 之间的差异。在实际应用中，在配置相同的硬件上，当序列长度N为512时，Transformer的每轮训练速度是RNN的5到10倍；且随着序列长度的增加，这一差距会进一步拉大，直至遇到注意力机制的`O(N²)`内存限制（该问题后来通过Flash Attention得到解决——详见第12课）。

**Transformer的代价。** 注意力机制所需的内存随序列长度呈`O(N²)`增长。对于2K上下文长度尚可接受，但若达到128K，则需要采用滑动窗口、RoPE外推、Flash Attention分块或线性注意力变体等技术。而循环结构在时间和内存消耗上均为`O(N)`；Transformer则是用时间换取内存，再通过并行处理重新赢回时间优势。

**归纳偏见的转变。** RNN假设数据的局部性和近期性特征，而Transformer则不做任何预设——任意数据对都可能成为注意力的目标。正因如此，Transformer需要更多数据才能训练出良好性能，但一旦获得足够数据就能实现更好的扩展能力。Chinchilla（2022）对此进行了形式化证明：在参数量相同的情况下，只要token数量足够，Transformer的总性能总会优于RNN。

## 构建它

此处没有使用神经网络——我们通过数值方法模拟核心瓶颈，以便您在笔记本电脑上亲身体验其中的差异。

### 步骤 1：测量串行深度

请参阅 `code/main.py`。我们在该文件中实现了两个函数。一个函数将序列编码为加法链的形式（串行结构，类似 RNN）；另一个函数则将其编码为并行求和形式（广播结构，类似注意力机制）。数学原理相同，但依赖图不同。

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # can't parallelize: h depends on previous h
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # every x is independent
```

我们在长度高达 100,000 个元素的序列上对这两种方法进行了计时测试。RNN 版本的时间复杂度为 O(N)，且仅依赖单个 CPU 流水线。即便在纯 Python 环境中，当序列长度 ≥ 1,000 时，基于注意力机制的简化方法也能更快完成计算，因为 Python 的 `sum()` 函数是用 C 语言实现的，在每次迭代过程中无需承担解释器的额外开销。

### 步骤 2：统计理论操作次数

这两种算法都需要执行 N 次加法操作。二者的区别在于*依赖深度*：即在下一次操作开始之前，必须依次完成多少次操作。RNN 的深度为 N；而注意力机制的深度在采用树形归约时为 log(N)，在并行扫描时则为 1。决定 GPU 计算时间的因素是深度而非操作次数。

### 步骤 3：长序列的实证级联训练

我们会输出一张时间对比表，以直观展示 O(N) 的差异。在 2026 年款 Mac 笔记本电脑上，元素数量少于 1,000 的序列速度过快，难以进行精确测量。而包含 100,000 个元素的序列则能展现出清晰的线性扫描特征。若将这一模型规模扩展到相当于 16,384 个标记的 Transformer 模型以及 12 层 LSTM 模型，就能明白为何在 2016 年训练时间会成为一个重大障碍。

## 使用它

2026年仍应选择RNN的场景：

| 场景 | 推荐模型 |
|-----------|----------|
| 流式推理，逐个处理标记，内存需求恒定 | RNN或状态空间模型（Mamba、RWKV） |
| 序列长度极长（>100万标记），注意力机制导致内存爆炸 | 线性注意力、Mamba 2、Hyena |
| 边缘设备且无矩阵乘法加速器 | 深度可分离RNN在FLOPs/瓦特效率上仍具优势 |
| 其他场景（训练、批量推理、上下文长度达128K） | Transformer |

像Mamba这样的状态空间模型本质上是具有结构化参数化的RNN，这种设计使其兼得了两者的优点：`O(N)`级别的扫描内存需求，以及通过选择性扫描实现并行训练。它们能在保持90%Transformer性能的同时，更好地处理长上下文问题。2026年，大多数前沿实验室都在训练混合型的SSM+Transformer模型（如Jamba、Samba）——递归结构并未消亡，它依然是AI模型的重要组成部分。

## 练习题

1. **简单。** 从 `code/main.py` 中获取 `rnn_style`，并将标量隐藏状态替换为长度为 64 的隐藏状态向量。再次进行测量。随着隐藏状态维度的增加，串行处理的开销会增加多少？
2. **中等难度。** 使用纯 Python 实现并行前缀和计算（Hillis-Steele 扫描）。验证其在长度为 1024 的情况下产生的数值结果与串行扫描一致，并统计其深度。
3. **高难度。** 将注意力机制风格的降维操作移植到 GPU 上的 PyTorch 环境中。在序列长度从 64 变化到 65,536 的过程中分别测量两种方法的运行时间，绘制曲线并解释曲线的形状特征。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 循环性 | “RNN 是顺序处理的” | 指步骤 `t` 取决于步骤 `t-1`，迫使计算沿着时间轴依次执行。 |
| 串行深度 | “图的深度是多少” | 指依赖操作的最长链；即使在无限算力下也会存在时间上限。 |
| 注意力机制 | “让各个标记相互查看” | 表示加权求和 `sum_j a_ij v_j`，其中 `a_ij` 来自位置 i 与 j 之间的相似度得分。 |
| 上下文窗口 | “模型能看到多少内容” | 指注意力层可接收的输入位置数量；内存成本会随之呈二次方增长。 |
| 归纳偏见 | “架构中内置的假设” | 关于数据特征的先验假设；CNN 假设平移不变性，RNN 假设近期性。 |
| 状态空间模型 | “带有代数基础的 RNN” | 通过结构化的状态空间矩阵对循环性进行参数化，以实现并行训练。 |
| 二次方瓶颈 | “为何上下文处理成本如此之高” | 注意力机制的内存消耗与序列长度成 `O(N²)` 关系；Flash Attention 只是隐藏了常数项，并未改变这种增长趋势。 |

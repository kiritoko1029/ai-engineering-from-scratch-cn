# 标度律

> Kaplan 在 2020 年的论文中指出：模型规模越大，损失越低。Hoffmann 在 2022 年的论文则认为问题出在训练不足。计算量可划分为参数和令牌两类，但二者之间的划分标准并不明确。

**类型：** 学习
**语言：** Python
**先修要求：** 第 7 阶段 · 05（完整 Transformer 模型），第 7 阶段 · 07（GPT）
**时长：** 约 45 分钟

## 问题所在

当你的训练算力为 C FLOPs，且希望获得最优模型时，需要调整两个关键参数：

1. **参数数量（N）**：模型规模越大，容量越高。
2. **训练数据量（D）**：数据越多，对容量的利用率越高。

FLOPs 的计算公式大致为 `6 × N × D`。你可以选择提升 N 而降低 D，或者提升 D 而降低 N。哪种方式更好？

在 2022 年之前，答案是“大幅增加 N”。GPT-3（2020 年）拥有 1750 亿个参数，基于约 3000 亿个训练样本进行训练，参数与数据量的比例约为 1.7。Kaplan 缩放定律也支持了这一结论。

Hoffmann 等人（2022 年）在训练名为 Chinchilla 的一系列小型模型时发现了不同的结果：最优的参数与数据量比例更接近 **每参数 20 个样本**。这意味着 GPT-3 的训练程度不足 10 倍。Chinchilla（700 亿参数，1.4 太字节数据量）在所有基准测试中的表现均优于 GPT-3（1750 亿参数，3000 亿样本），且推理成本仅为后者的 2.5 倍。

到 2026 年，Chinchilla 将成为主流选择——但有一个重要变化。Llama 3 8B 的训练数据量达到了 15 万亿个样本，参数与数据量的比例为 1,875，是 Chinchilla 最优比例的 94 倍。对于那些将大规模应用的模型而言，推理成本比训练成本更为关键，因此为了获得更小的部署规模而过度训练（超过 Chinchilla 的最优水平）将成为 2026 年的默认策略。

## 概念概述

![Chinchilla 曲线：不同 N/D 比例下的损失值与计算量关系](../assets/scaling-laws.svg)

### 霍夫曼定律

根据 Chinchilla 的论文，损失函数如下：

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = 参数（非嵌入参数）。
- `D` = 训练令牌数。
- `α ≈ 0.34`，`β ≈ 0.28`（大致对称）。
- `E ≈ 1.69`，即不可再降低的损失上限。
- `A ≈ 406`，`B ≈ 411`。

在模型规模扩大的过程中，有两个项会相互制约。在计算资源固定（C = 6ND）的条件下，对 `N` 求导并求解：

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

计算最优配置：每个参数 20 个令牌。

### 为何要过度训练呢

Chinchilla-optimal 模型能在每 FLOP 的训练成本下将损失降至最低。但其训练成本仅需支付一次，而推理成本则需持续承担。

对于每月需要处理万亿个令牌的聊天机器人而言，推理成本在总成本中占据主导地位。Llama 的解决方案是训练规模更小但序列长度更长的模型。80 亿参数、支持 15 万亿个令牌的模型经过深度优化以适应推理场景：

- 可运行在消费级 GPU 上。
- 延迟仅为 Chinchilla-optimal 700 亿参数模型的几分之一。
- 对于大多数任务而言，其性能已足够达标。

DeepMind 在 2024 年的论文《过度训练才是新的最优策略》中正式提出了这一观点。对于以推理为主的工作负载，根据服务量不同，每个参数对应的理想令牌比例通常在 100 到 500 之间。

### 涌现性与平滑性

观点：某些能力（算术、多步骤推理、思维链遵循）会在达到某一规模时突然“出现”。

Schaeffer 等人（2023）认为这是一种测量伪象：这类“涌现”指标采用离散评分方式（完全匹配、阈值下的准确率），从而掩盖了底层逻辑斯蒂值中持续稳定的提升趋势。而连续型指标（如交叉熵）则能呈现平滑的曲线。

到 2026 年，学界共识已形成：基于连续损失函数的预测更为可靠。基准测试中的数值跃升往往只是评分方式带来的伪象。应依据连续型指标来规划资源预算。

### 2026年的发展态势

缩放定律依然适用，但存在以下变化：

| 因素 | 变化方式 |
|------|----------|
| 数据质量 | 通过筛选“优质”令牌（类似 Phi 方法）可使曲线在有效计算量上发生超过 2 倍的偏移 |
| MoE 架构 | 总参数数与实际活跃 FLOPs 解耦；缩放定律不再基于总 FLOPs，而是基于每活跃 FLOP 的数值 |
| 训练后优化 | 某些能力（如指令遵循、代码生成）在经过 SFT+RLHF 优化后的变化幅度大于预训练阶段 |
| 多模态处理 | 图像与文本令牌的规模呈同步增长趋势；但每种模态仍具有独立的曲线特征 |
| 合成数据 | 模型可自行生成训练数据，这可能导致有效计算量出现叠加效应 |

Muon 优化器（Kimi Moonlight，2024 年发布）在数据量相当的情况下，其带来的有效计算量提升约为 AdamW 的 2 倍。2026 年的部分训练任务将默认使用 Muon 优化器。该优化器仅改变缩放定律中的绝对常数，而不影响其整体形态。

## 构建它

请参阅 `code/main.py`。我们在不同的计算预算下实现 Chinchilla 损失函数，并求解最优的 `(N, D)` 值。

### 步骤 1：Chinchilla 损失函数

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

在固定参数 `C = 6ND` 的条件下，将 `L` 作为 `(N, D)` 平面上的等高线图进行绘制。求出其最小值。

### 步骤 2：计算最优前沿

对于计算量预算在 `1e17` 到 `1e25` 次浮点运算之间的情况，需在约束条件 `6ND = C` 下寻找能够使损失最小的 `(N, D)` 值。同时需要验证比值 `D/N ≈ 20` 是否成立。

### 步骤 3：过拟合成本

计算训练规模为最优模型 1/10（参数量 N 为最优值的 1/10，数据量 D 为最优值的 10 倍）的模型时需额外承担的损失。同时会报告相应的推理 FLOP 开销节省量（与 N 成正比）。

### 步骤 4：与真实模型进行对比

插入已知的 GPT-3、Chinchilla、Llama 3 8B、DeepSeek-V3（活跃参数量）的 `(N, D)` 对，并对比预测损失值与报告的损失值。

## 使用它

你几乎不可能自行训练前沿模型。但缩放律可以为你提供以下指引：

1. **微调所需数据量是否充足。** 如果针对特定任务的数据量低于基础模型每个参数20个token，预计损失值会在某个水平达到饱和。
2. **是否应选择更大的基础模型。** 如果将所有预算都用于推理，建议选用规模较小但训练时间更长的模型。
3. **收益下降的临界点。** 当性能提升超过Chinchilla模型的1000倍后，对数损失的变化便仅属于噪声范畴。

**2026年的研究方向：**

- **数据受限场景。** 网络上高质量token的数量是有限的（过滤后约5–10万亿个英文token）。前沿预训练已接近这一上限，因此合成数据、多语言数据、多模态数据以及经过RLHF优化的微调成为后续的研究重点。
- **提升计算效率的技巧。** Muon优化器、MoE架构以及更精细的数据筛选——这些方法仅能改变绝对常数，无法改变性能增长的渐近趋势。
- **强化学习领域的缩放律。** 目前仍为开放性问题。早期证据表明强化学习样本也遵循幂律分布，但其指数与预训练的指数存在显著差异。

## 练习题

1. **简单。** 运行 `code/main.py`，针对计算预算 `1e20`、`1e22`、`1e24` 输出 Chinchilla 算法最优的 `(N, D)` 值，并与真实模型表格进行对比。
2. **中等难度。** 实现以计算量为自变量的 Hoffmann 损失函数曲线，绘制计算最优前沿下的损失值与 `log10(C)` 的关系图。确定根据该规律，在使交叉熵再降低 0.1 时需要多少 FLOPs 才能满足要求。
3. **高难度。** 在同一数据集上训练的 5 个参数量在 100K 到 10M 之间的小型模型上，拟合出属于自己的缩放定律。估算参数 `α` 和 `E` 的值，并比较你的指数与已发表结果的吻合程度。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------|----------|
| 参数量 (N) | “模型大小” | 非嵌入权重总数；决定模型的容量。 |
| 分词数 (D) | “训练数据量” | 已处理的训练分词数量；决定参数的利用效率。 |
| 计算量 (C) | “消耗的 FLOPs 数量” | 对于标准 Transformer，其值约为 `6 × N × D`。 |
| Chinchilla 最优比例 | “D/N ≈ 20” | 能使预训练每单位 FLOPs 的损失降至最低的比例。 |
| 过度训练 | “超出 Chinchilla 比例” | 为节省推理时的 FLOPs 而投入额外的训练 FLOPs；此时 D/N >> 20。 |
| 不可降低的损失 | “下限值” | 规模定律中的 `E` 项；即数据本身的熵值。 |
| 演化出的能力 | “规模扩大时的突然提升” | 通常为评分工具产生的假象；实际损失曲线是平滑的。 |
| 实际有效计算量 | “训练效率倍增因子” | 更优质的数据、优化器或架构能够提升单位 FLOPs 所带来的性能提升幅度。 |

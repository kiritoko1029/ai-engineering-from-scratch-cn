# T5、BART——编码器-解码器模型

> 编码器负责理解输入，解码器负责生成输出。将二者结合，即可构建出用于处理输入→输出任务的模型：翻译、摘要生成、重写文本、语音转文字等。

**类型：** 学习
**语言：** Python
**先修课程：** 第7阶段 · 05（完整Transformer）、第7阶段 · 06（BERT）、第7阶段 · 07（GPT）
**时长：** 约45分钟

## 问题所在

仅解码器的 GPT 与仅编码器的 BERT 均是对 2017 年架构的简化，但目的各异。然而许多任务本质上是输入到输出的转换：

- 翻译：英语 → 法语。
- 摘要生成：5,000 个标记的文章 → 200 个标记的摘要。
- 语音识别：音频标记 → 文本标记。
- 结构化信息提取：散文 → JSON。

对于这类任务，编码器-解码器架构最为适用。编码器会生成源文本的密集表示，解码器则在每一步通过交叉注意力机制参考该表示来生成输出。训练时在输出端采用逐位偏移的方式，损失函数与 GPT 相同，只是以编码器的输出作为条件。

有两篇论文确立了现代此类架构的标准范式：

1. **T5**（Raffel 等人，2019 年）。“文本到文本的转换 Transformer。”将所有自然语言处理任务重新定义为输入为文本、输出也为文本的形式。采用单一架构、统一词汇表及相同损失函数，并通过掩码片段预测任务进行预训练（在输入中破坏部分片段，要求在输出中还原它们）。
2. **BART**（Lewis 等人，2019 年）。“双向与自回归 Transformer。”属于去噪自编码器类型：通过多种方式破坏输入数据（如打乱顺序、加掩码、删除内容、旋转），并要求解码器重建原始内容。

到了 2026 年，当输入结构具有重要意义时，编码器-解码器架构依然广泛使用：

- Whisper（语音 → 文本）。
- Google 的翻译系统。
- 一些具有特定上下文与编辑结构的代码补全/修复模型。
- 用于结构化推理任务的 Flan-T5 及其变体。

尽管仅解码器的架构更受关注，但编码器-解码器架构从未消失。

## 概念概述

![带有交叉注意力机制的编码器-解码器](../assets/encoder-decoder.svg)

### 前向循环

```
source tokens ─▶ encoder ─▶ (N_src, d_model)  ──┐
                                                 │
target tokens ─▶ decoder block                   │
                 ├─▶ masked self-attention       │
                 ├─▶ cross-attention ◀───────────┘
                 └─▶ FFN
                ↓
              next-token logits
```

关键在于，编码器针对每个输入仅运行一次。解码器则采用自回归方式处理数据，但在每一步都会对*相同的*编码器输出进行交叉注意力计算。对于较长的输入序列，缓存编码器输出无需额外成本即可提升处理速度。

### T5预训练——跨度损坏

从输入中随机选取片段（平均长度为3个标记，占总量的15%）。将每个选中的片段替换为一个唯一的哨兵值：<extra_id_0>、<extra_id_1>等。解码器仅输出被篡改的片段及其前缀形式的哨兵值：

```
source: The quick <extra_id_0> fox jumps <extra_id_1> dog
target: <extra_id_0> brown <extra_id_1> over the lazy
```

相比预测整个序列，其计算成本更低。在 T5 论文的消融实验中，其性能可与 MLM（BERT）和前缀 LM（UniLM）相媲美。

### BART预训练——多噪声去噪

BART 会尝试五种噪声生成函数：

1. 令牌掩码。
2. 令牌删除。
3. 文本填充（对某段文本进行掩码处理，解码器会插入相应长度的字符）。
4. 句子重排。
5. 文档旋转。

将文本填充与句子重排结合使用，能够获得最佳的下游性能指标。解码器始终能够重构出原始内容。BART 的输出是完整的序列，而不仅仅是被破坏的那部分——因此其预训练所需的计算量高于 T5。

### 推理

采用与 GPT 相同的自回归生成方式。支持贪心采样、束搜索和 top-p 采样。在翻译和摘要任务中，通常使用宽度为 4–5 的束搜索，因为此类任务的输出分布比聊天任务更为集中。

### 2026年何时选择各版本

| 任务 | 编码器-解码器架构？ | 原因 |
|------|------------------|-----|
| 翻译 | 是，通常为该架构 | 源序列清晰；输出分布固定；束搜索适用 |
| 语音转文本 | 是（Whisper） | 输入模态与输出不同；编码器用于处理音频特征 |
| 聊天/推理 | 否，仅解码器架构 | 不存在持续的“输入”——对话本身即构成序列 |
| 代码补全 | 通常不是该架构 | 仅解码器架构配合长上下文即可胜出；如 Qwen 2.5 Coder 等代码模型也属于仅解码器架构 |
| 摘要生成 | 两种架构均可使用 | BART、PEGASUS 超过了早期的仅解码器架构基准模型；现代仅解码器架构的大语言模型也能与之媲美 |
| 结构化信息提取 | 两种架构均可使用 | T5 的优势在于“文本→文本”的转换方式可适配任何输出格式 |

自 2022 年以来的趋势：仅解码器架构逐渐取代原本由编码器-解码器架构处理的任务，原因如下：<br>（a）通过指令微调的仅解码器架构大语言模型可通过提示词泛化处理各类任务；<br>（b）单一架构比双架构更易于扩展；<br>（c）强化学习从人类反馈中优化也以解码器为前提。而当输入模态不同（如语音、图像）或需要依赖束搜索保证质量时，编码器-解码器架构仍具有优势。

## 构建它

请参阅 `code/main.py`。我们在一个小型语料库上实现了 T5 风格的跨度破坏机制——这是本课中最实用的内容，因为从那以后，所有编码器-解码器预训练方案都会采用这一方法。

### 步骤 1：span 数据损坏

```python
def corrupt_spans(tokens, mask_rate=0.15, mean_span=3.0, rng=None):
    """Pick spans summing to ~mask_rate of tokens. Return (corrupted_input, target)."""
    n = len(tokens)
    n_mask = max(1, int(n * mask_rate))
    n_spans = max(1, int(round(n_mask / mean_span)))
    ...
```

目标格式为 T5 规范：<sent0> span0 <sent1> span1 …。损坏的输入会将未改变的标记与位于指定位置的哨兵标记交错排列。

### 步骤 2：验证往返传输

给定被损坏的输入和目标，重建原始句子。如果这种损坏是可逆的，则前向传播过程是明确定义的。这是一项合理性检查——实际训练中不会进行此类操作，但由于成本较低，它能有效检测出在分词记录过程中出现的“偏移一”错误。

### 步骤 3：BART 噪声注入

## 使用它

HuggingFace 参考资料：

```python
from transformers import T5ForConditionalGeneration, T5Tokenizer
tok = T5Tokenizer.from_pretrained("google/flan-t5-base")
model = T5ForConditionalGeneration.from_pretrained("google/flan-t5-base")

inputs = tok("translate English to French: Attention is all you need.", return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=32)
print(tok.decode(out[0], skip_special_tokens=True))
```

T5的巧妙之处在于：任务名称会被直接纳入输入文本中。由于所有任务均为“文本输入、文本输出”的形式，同一模型即可处理数十种不同的任务。尽管在2026年这种模式已被经过指令微调的纯解码器模型所推广，但T5却是首个实现该理念的模型。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 编码器-解码器 | “Seq2seq transformer” | 包含两个模块：用于输入的双向编码器，以及用于输出的带有交叉注意力机制的因果解码器。 |
| 交叉注意力 | “源序列与目标序列交互的地方” | 解码器的 Q 向量与编码器的 K/V 向量的运算；这是编码器信息进入解码器的唯一途径。 |
| 区间损坏 | “T5 的预训练技巧” | 用特殊标记替换随机区间，随后由解码器输出这些区间内容。 |
| 去噪目标函数 | “BART 的设计思路” | 对输入序列施加噪声函数，训练解码器重构出原始的纯净序列。 |
| 特殊标记 | “`<extra_id_N>` 占位符” | 用于在源序列中标识损坏区间，并在目标序列中对它们进行重新标记的特殊符号。 |
| Flan | “经过指令微调的 T5” | 在超过 1,800 个任务上对 T5 进行微调，使其在指令遵循任务中的表现可与编码器-解码器模型相媲美。 |
| 梁搜索 | “解码策略” | 在每一步保留 top-k 个最佳部分序列；是翻译和摘要生成任务中的常用方法。 |
| 教师强制法 | “训练时的输入方式” | 在训练过程中，向解码器提供真实的上一轮输出标记，而非随机采样的标记。 |

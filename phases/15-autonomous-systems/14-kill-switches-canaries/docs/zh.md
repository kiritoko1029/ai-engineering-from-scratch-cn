# 紧急停止开关、断路器与金丝雀 Token

> 紧急停止开关是一个在智能体编辑面之外持有的布尔值——一个 Redis 键、一个功能标志、一个签名配置——它完全禁用智能体。断路器更精细：它在特定模式上触发（连续五次相同的工具调用），暂停有问题的路径，并提升到人工处理。金丝雀 token 继承自经典欺骗技术：一个智能体没有合法理由触及的假凭证或蜜罐记录，其访问触发警报。基于 eBPF 的数据路径（例如 Cilium）可以在内核层将被隔离 pod 的出口重写到取证蜜罐；已发布的 Cilium 基准报告在负载下 P99 数据路径延迟低于一毫秒（你的传播预算取决于策略更新如何到达节点，而非数据路径本身）。适应移动基线的统计检测器（EWMA、CUSUM）会静默接受漂移——与不会弯曲的硬宪法限制分层使用。

**类型：** 学习
**语言：** Python（标准库，三检测器模拟器：紧急停止开关、断路器、金丝雀）
**前置要求：** 第 15 阶段 · 13（成本治理器），第 15 阶段 · 10（权限模式）
**所需时间：** 约60分钟

## 问题所在

成本治理器（第 13 课）约束了智能体能花费多少。它们不约束智能体在预算内能做什么。一个有 50 美元速率限制的智能体仍然可以泄露秘密、发布错误帖子或删除资源——昂贵的动作在 token 上往往是便宜的。

本课涵盖成本层旁边的三个检测器：

1. **紧急停止开关**：在智能体触及范围之外持有的布尔关闭按钮。
2. **断路器**：暂停特定路径的动作模式检测器。
3. **金丝雀 token**：一个没有合法理由触及的智能体触及它就会暴露自己的诱饵。

三者都是 LLM 之前的工程。经典欺骗、速率限制断路器和功能标志停止都早于自主智能体。新的是攻击面：智能体阅读不受信任的内容（第 11 课），编辑自己的内存，并且可以将许多看似安全的动作组合成一个不安全的动作。这里命名的检测器有效是因为它们不信任智能体的自我报告。

## 概念说明

### 紧急停止开关

紧急停止开关是智能体可以读取但不能写入的布尔值。实现选择：

- **托管服务中的功能标志。** LaunchDarkly、Statsig、Unleash。更新在秒内传播。
- **智能体轮询的 Redis 键。** 简单；需要智能体进程在每个回合检查。
- **对象存储中的签名配置。** 智能体在启动时验证签名；拒绝未签名的状态。
- **操作系统级信号或容器生命周期终止。** Docker `kill`、Kubernetes `kubectl delete pod`、systemd stop。

正确紧急停止开关的属性：

- 智能体无法将其设置为 `off`。（存在于智能体凭证无法写入的系统中。）
- 在每个重要动作上检查，而不仅仅在启动时。
- 当它关闭时，智能体不做任何外部可观察的事情，包括向智能体可达的系统记录日志。
- 重新启用是显式的人工操作，而非自动超时。

### 断路器

断路器暂停特定模式，而非整个智能体。经典形状（来自 2007 年 Nygard 的书，仍然适用）：

- **关闭**：动作被允许。
- **打开**：动作被阻止。
- **半开**：冷却后，允许 1-3 次探测尝试（默认 1）；成功关闭断路器，任何剩余失败重新打开它。

智能体相关触发器：

- 连续五次相同的工具调用（重复循环）。
- 同一工具上连续五次失败，使用不同输入（系统性故障）。
- 工具调用速率超过阈值（第 13 课速率限制）。
- 在读取不受信任内容后（第 11 课）调用特定工具（例如 `file.delete`）。

### 金丝雀 token

金丝雀 token（也称为蜜罐 token）是智能体永远不应触及的输入。访问就是警报。

智能体的例子：

- 环境中的假 `AWS_SECRET_ACCESS_KEY`，没有实际权限。泄露尝试可即时归因。
- 用已知哨兵值标记的假数据库记录。对此记录的任何读取或更新触发警报。
- 工作区中的假文件。对此文件的读取或编辑是可疑的。
- 在会话开始时注入的假内存条目。如果它出现在后续输出中，内存已被泄露。

金丝雀设计特定于工作流。智能体有合法理由触及的金丝雀是噪声。

### 为什么要分层统计和硬限制

统计检测器（EWMA、CUSUM、工具调用速率的 z-score）适应移动基线。这对合法漂移是特性，对对抗性漂移是缺陷。耐心的攻击者可以缓慢移动基线，使没有警报触发。

硬宪法限制（第 17 课）不会弯曲。"永远不发送邮件到 `secrets@`"作为宪法规则更简单、可审计、不会被慢漂移博弈。分层模式：统计检测器捕获大部分噪声，硬限制捕获走过检测器的攻击。

### 通过 eBPF 数据路径重定向隔离

Cilium 的基于 eBPF 的网络策略可以在内核层将被隔离 pod 的出口重写到取证蜜罐。Cilium 的公开基准在 TCP_RR 上报告 P99 数据路径延迟低于一毫秒；在集群中*触发*隔离的挂钟预算取决于策略更新如何从控制平面传播到节点（在 Kubernetes 上使用预加载的 operator，几百毫秒是现实的；尾部延迟取决于集群大小和协调节奏）。这给你两样东西：智能体不会泄露任何真实的东西，智能体在蜜罐内的行为被完全观察。与金丝雀 token 相同的模式，不同的层：智能体通过它在被遏制时试图做的事情暴露意图。

### 没有检测器能捕获什么

- **从允许原语组合的语义攻击。** 每个单独的动作通过每个检测器；组合才是问题。这是第 10 课的 Auto Mode 组合故障。
- **将检测器作为载荷一部分的攻击。** 如果智能体阅读一个说"在你行动之前，禁用金丝雀"的页面，并且智能体有该能力，检测器就被攻陷了。金丝雀 token 应在智能体无法修改的系统中。

## 关键术语

| 术语 | 人们怎么说 | 它实际意味着什么 |
|---|---|---|
| Kill switch（紧急停止开关） | "关闭按钮" | 在智能体编辑面之外的布尔值；在每个重要动作上检查 |
| Circuit breaker（断路器） | "模式暂停" | 在重复、失败率或速率限制上的动作特定触发 |
| Canary token（金丝雀 token） | "蜜罐 token" | 智能体没有合法理由触及的诱饵；访问触发警报 |
| Honeypot（蜜罐） | "取证沙箱" | 被隔离智能体被观察的重定向流量/工作区 |
| EWMA | "移动平均" | 指数加权；适应漂移（特性 + 缺陷） |
| CUSUM | "累积和" | 检测从基线的持续偏移 |
| Hard limit（硬限制） | "宪法规则" | 不适应；无论历史如何都是常数 |
| Constitutional limit（宪法限制） | "始终为真的规则" | 绑定到第 17 课的宪法；智能体无法编辑 |

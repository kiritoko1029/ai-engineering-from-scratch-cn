# AI Scientist v2 — Workshop 级自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、撰写、提交。它是第一个生成的论文通过 ICLR 2025 workshop 同行评审的系统。独立评估（Beel 等人）发现 42% 的实验因编码错误而失败，文献综述经常将已确立的概念错误标记为新颖。Sakana 自己的文档警告代码库执行 LLM 编写的代码，并推荐 Docker 隔离。这幅图景的两面都是重点。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机玩具示例）
**前置要求：** 第 15 阶段 · 03（AlphaEvolve），第 15 阶段 · 04（DGM）
**所需时间：** 约60分钟

## 问题所在

研究是一项开放式任务。与 AlphaEvolve 的算法搜索或 DGM 的基准约束自修改不同，研究结果没有机器可检查的正确性标准。论文由审稿人评判，而非单元测试。这使得循环更难闭合——如果闭合了也更有价值，因为研究是复合进步所在的地方。

AI Scientist v1（Sakana，2024）通过从人工编写的模板开始来闭合循环。LLM 在固定脚手架内填充实验。AI Scientist v2（Yamada 等人，2025）通过使用带有视觉语言模型批评循环的智能体树搜索来消除模板要求。该系统生成想法、实现实验、产生图表、撰写论文，并根据审稿反馈进行迭代。

同行评审结论：一篇 v2 生成的论文被 ICLR 2025 workshop 接收（已披露来源）。独立评估结论：该系统远未可靠。两者都是事实。

## 概念说明

### 架构

1. **想法生成。** LLM 根据主题和先前文献提出研究想法。v1 使用模板；v2 使用在假设空间上的智能体搜索。
2. **新颖性检查。** 文献检索步骤检查该想法是否已被发表。这是 Beel 等人评估发现错误标记的步骤——已确立的方法经常被归类为新颖。
3. **实验计划。** 智能体起草实验方案并编写代码。
4. **执行。** 代码在沙箱中运行。失败被反馈到重试循环中。在 Beel 等人的测量中，42% 的实验在此阶段因编码错误而失败。
5. **图表生成。** 视觉语言模型阅读生成的图表并重写以提高清晰度。这是 v2 的关键技术新增。
6. **撰写。** LLM 起草论文，与内部审稿人迭代。
7. **可选：提交。** 论文被提交到某个会议。

### Workshop 接收结果意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 workshop 的同行评审。作者向程序委员会披露了论文的来源。这个接收是一个数据点；它不是一个声称该系统"做研究"的许可证。

重要背景：workshop 论文的标准低于主会议论文。同行评审是有噪声的；一小部分提交在任何给定日期被接受。一次成功是概念验证，而非可靠性声明。Nature 2026 年的论文记录了端到端循环，本身由人类研究人员共同撰写；它不是"系统写了一篇 Nature 论文"。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误（错误导入、形状不匹配、未定义变量）而失败。重试循环捕获了一些，但不是全部。
- **新颖性错误标记。** 文献检索步骤经常将已确立的概念标记为新颖。这是研究领域的幻觉等价物。
- **呈现质量差距。** 视觉语言图表批评产生了出版级视觉效果，掩盖了底层的实验弱点。

最后一条发现对本阶段很重要。一个在没有进行令人信服的研究的情况下产生令人信服的输出的系统，比一个明显失败的系统更危险，而非更安全。评估必须触及底层主张，而非止步于图表。

### 沙箱逃逸隐忧

Sakana 自己的仓库 README 警告：

> 由于此软件的性质，即执行 LLM 生成的代码，我们无法保证安全。存在危险包、不受控制的 web 访问和生成意外进程的风险。自行承担风险并考虑 Docker 隔离。

这是自主性在未验证领域中的运行形态。LLM 编写代码；代码运行；代码可以做进程被允许做的任何事情。如果没有对文件系统、网络和进程操作进行硬限制的沙箱，任何自导向的研究智能体都可以泄露数据、烧掉算力或重写自己。

AlphaEvolve 的沙箱故事更容易，因为它的评估器很严格。AI Scientist v2 的循环以开放式目标运行开放式代码。这就是为什么它需要更强的隔离（至少 Docker；首选 seccomp / gVisor）以及在每次提交离开系统之前进行人工审查。

### v2 在前沿栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知故障 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元 + 基准 | 受评估器严谨性约束 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励黑客攻击 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、错误标记、美化掩盖弱点 |

v2 是三者中自动评估器最弱、输出面最广、通往公共制品路径最短的。运行控制（沙箱、审查、披露）承担了大部分安全工作。

## 开始构建

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 撰写 → 评审 → 接收或迭代。每个状态都有从 Beel 等人发现中提取的可配置失败概率。运行模拟器 N 个循环并计数：

- 多少想法到达提交阶段。
- 多少提交会有精美的论文掩盖的关键实验缺陷。
- 重试预算如何在质量和产量之间权衡。

## 交付产出

`outputs/skill-ai-scientist-sandbox-review.md` 是研究循环智能体产出在离开沙箱之前的两道审查清单。

## 练习

1. 使用默认参数运行 `code/main.py`。多少比例的循环运行产生"干净"的论文？多少比例的论文有图表批评美化掩盖的实验失败缺陷？

2. 默认值已使用 Beel 等人的 42% / 25%。使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 重新运行，然后使用 `--experiment-failure 0.60 --novelty-mislabel 0.40`。精美的但有缺陷的份额在两次运行之间如何变化？

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 关于沙箱要求的内容。说出你会在多天自主运行中应用的两个额外限制（Docker 之外）。

4. 阅读 Beel 等人第 4 节关于呈现质量差距的内容。设计一个额外的评估器来捕获看起来精美但实验有缺陷的论文。

5. 为研究智能体输出提出一个比"博士阅读每篇论文"更具扩展性的人工审查协议。识别瓶颈并围绕它进行设计。

## 关键术语

| 术语 | 人们怎么说 | 它实际意味着什么 |
|---|---|---|
| AI Scientist v1 | "Sakana 的模板化研究智能体" | 在固定脚手架中填充实验 |
| AI Scientist v2 | "无模板研究智能体" | 带有 VLM 图表批评的智能体树搜索 |
| Agentic tree search（智能体树搜索） | "分支研究智能体" | 并行扩展多个实验计划；由内部批评者剪枝 |
| Vision-language critique（视觉语言批评） | "VLM 图表美化" | 多模态模型阅读图表并重写以提高清晰度 |
| Literature retrieval（文献检索） | "新颖性检查" | 搜索先前工作以确认想法新颖性——有记录的错误标记 |
| Polish masking（美化掩盖） | "漂亮的论文，破碎的研究" | 呈现质量超过实验质量；隐藏弱点 |
| Sandbox escape（沙箱逃逸） | "LLM 代码突破" | 智能体执行的代码做了循环设计者未预期的事情 |

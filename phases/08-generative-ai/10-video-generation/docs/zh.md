# 视频生成

> 图像是一种二维张量，而视频则是三维张量。其理论基础相同，但计算难度要高出10到100倍。OpenAI在2024年2月推出的Sora证明了这一点的可行性。到2026年，Veo 2、Kling 1.5、Runway Gen-3、Pika 2.0以及WAN 2.2已能够实现从文本生成1080p分辨率的商用级视频——而那些开源模型系列（CogVideoX、HunyuanVideo、Mochi-1、WAN 2.2）则落后了12个月。

**类型：** 构建
**语言：** Python
**先修要求：** 第8阶段·07（潜在扩散模型）、第7阶段·09（ViT）、第8阶段·06（DDPM）
**耗时：** 约45分钟

## 问题所在

24帧/秒、1080p分辨率的10秒视频包含240帧，每帧尺寸为1920×1080×3像素。这意味着每个视频片段约需1.5 GB的原始数据量。在像素级进行扩散处理是不可行的。为此需要：

1. **时空压缩**：使用VAE将视频而非单帧编码为一系列时空块。
2. **时间连贯性**：不同帧之间需要在内容、光照及物体识别方面保持一致性，模型必须能够模拟运动。
3. **计算资源限制**：在模型规模相同的情况下，视频训练的成本是图像训练的10到100倍。
4. **条件引导**：可基于文本、首帧图像、音频或其他视频作为条件输入。大多数实用模型支持这四种类型。

解决上述问题的架构是将**扩散变换器（Diffusion Transformer, DiT）**应用于时空块，并在包含提示词、字幕及视频的庞大数据集上进行训练。其损失函数与第06课中的相同。

## 概念概述

![视频扩散模型：patchify、DiT、解码过程](../assets/video-generation.svg)

### Patchify

使用3D VAE对视频进行编码（采用学习到的时空压缩技术）。其潜在空间的形状为 `[T_latent, H_latent, W_latent, C_latent]`。随后将该空间分割成大小为 `[t_p, h_p, w_p]` 的块。对于Sora风格的模型，`t_p` 的值为 1（逐帧划分块）或 2（每隔一帧划分块）。一段时长为10秒、分辨率为1080p的视频通常会被压缩为约20,000至100,000个块。

### 时空DiT模型

Transformer 模型会对扁平化的补丁序列进行处理。每个补丁都包含三维位置嵌入（时间维度 + y 轴维度 + x 轴维度）。注意力机制通常被分解为以下几部分：

- 每一帧内各补丁之间的**空间注意力**。
- 具有相同空间位置的各帧之间的**时间注意力**。
- 完整的**三维注意力**的计算成本是其前两者的 16 到 100 倍；仅在低分辨率场景或研究工作中使用。

### 文本条件化

采用大型文本编码器实现的跨注意力机制（Sora 使用 T5-XXL，CogVideoX-5B 则使用 T5-XXL）。较长的提示语至关重要——Sora 的训练集包含由 GPT 生成的密集式字幕，每段视频的平均长度约为 200 个标记。

### 训练

基于时空隐变量的标准扩散损失函数（用于预测 ε 或 v）。数据来源：网络视频、约 1 亿个精选片段以及合成的文本字幕。计算成本：即便只是进行小型研究实验，也需要 1 万多个 GPU 小时；而达到 Sora 级别的模型则需要 10 万多个 GPU 小时。

## 构建它

`code/main.py` 模拟了核心的时空 DiT 思想：将一个小型合成视频分割为多个小块，为每个块添加位置嵌入，然后通过基于块的 Transformer 风格注意力机制对整个序列进行去噪处理。该实现不使用 NumPy，仅依赖纯 Python。实验表明，即使在一维场景中，只要相邻帧的块共享同一个去噪器与位置嵌入，时间一致性依然能够得以保持。

### 步骤 1：对合成的 1 维“视频”进行 patchify 处理

```python
def make_video(T_frames=8, rng=None):
    # a "video" is a sequence of 1-D values following a smooth trajectory
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 步骤 2：为每一帧生成位置嵌入

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 步骤 3：去噪器会查看整个序列

我们的小型网络不会单独对每一帧进行去噪处理，而是将所有帧的数值及其位置嵌入拼接在一起，从而共同预测所有帧的噪声。

### 步骤 4：时间一致性测试

训练完成后，抽取一个视频样本。测量帧与帧之间的差异值。如果模型已学习到时间结构，这些差异值将小于单独采样每一帧时的差异值。

## 常见陷阱

- **逐帧独立采样 = 画面闪烁。** 如果对每一帧分别进行图像扩散处理，由于每帧的噪声是独立的，输出会出现闪烁现象。视频扩散通过注意力机制或共享噪声将各帧关联起来，从而解决此问题。
- **简单的3D注意力机制 = 内存溢出。** 对10秒长、1080p分辨率的潜在表示应用完整的3D注意力机制需要数百亿次运算。应将其分解为空间维度与时间维度的处理。
- **数据字幕的重要性高于数据量大小。** Sora相比之前的模型，其主要改进在于使用了约多10倍详细程度的字幕（由GPT-4重新标注的片段）。OpenAI的技术报告对此有明确说明。
- **首帧条件设定。** 大多数实际应用中的模型也支持将图像作为首帧输入。这就是“图像转视频”模式，训练过程也会包含这种变体。
- **物理规律偏差。** 过长的视频片段（>10秒）会逐渐出现细微的不一致性。采用滑动窗口生成方法并结合关键帧锚定有助于解决这一问题。

## 练习题

1. **简单。** 在 `code/main.py` 中，分别对 (a) 独立逐帧采样和 (b) 联合序列采样两种方式计算帧与帧之间的差异值，并报告这些差异值的均值与方差。
2. **中等难度。** 增加首帧约束条件：将第 0 帧固定为指定值，然后对其余帧进行采样。测量该固定值在后续帧中的传播情况。
3. **高难度。** 使用 HuggingFace diffusers 在本地 GPU 上运行 CogVideoX-2B 模型。针对长度为 6 秒、分辨率为 720p 的视频片段，计时执行 20 步推理过程，并对时空注意力机制进行性能分析，以定位性能瓶颈所在。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 视频变分自编码器 | “3-D VAE” | 将 `(T, H, W, C)` 格式的输入压缩为时空隐变量的编码器。 |
| 图块 | “标记单元” | 隐变量中的固定尺寸三维块，作为 DiT 模型的输入。 |
| 分解式注意力 | “空间 + 时间” | 先对空间维度应用注意力，再对时间维度应用注意力；避免使用完整的三维注意力机制。 |
| 图像转视频（I2V） | “为这张照片添加动画” | 该模型接收一张图片及文本描述，生成以该图片为起始内容的视频。 |
| 关键帧条件控制 | “锚定帧” | 通过指定特定帧来控制视频的叙事走向。 |
| 运动画笔 | “方向提示工具” | 用户可在图像上绘制运动向量的一种界面输入方式。 |
| 重新添加字幕 | “密集式字幕生成” | 利用大语言模型为训练片段重新标注带有详细提示的字幕。 |
| 闪烁现象 | “时间维度伪影” | 帧与帧之间的不一致性；通过联合去噪方法加以解决。 |

## 生产注意事项：视频延迟问题本质上是内存带宽不足所致。

24 帧/秒、1080p 分辨率下长度为 10 秒的视频片段，其原始像素数据量为 240 帧 × 1920 × 1080 × 3 ≈ 1.5 GB。经过 4× 视频 VAE 压缩（`2 × 空间维度 × 2 × 时间维度`）后，每次请求的潜在表示大小约为 100 MB。若在批次处理中对该潜在表示使用时空 DiT 模型进行 30 步推理，每步将通过 HBM 移动约 3 GB 的数据——此时瓶颈在于内存带宽而非浮点运算次数。

以下三个参数直接取自生产环境推理相关文献中的章节：

- **DiT 跨层并行度（TP）。** 文本到视频模型通常具有 ≥100 亿个参数。在 4 台 H100 上设置 TP=4 是常见配置；而对于 4050 亿参数级别的模型，则设置为 PP=2 × TP=2。在达到全连接聚合阶段之前，每步的延迟大致与 TP 成线性关系下降。
- **帧级批量处理 = 连续批量处理。** 在生成过程中，视频从概念上讲是由注意力机制连接的帧序列构成的批次。若模型架构支持滑动窗口生成，则可采用连续批量处理（即边返回帧 `t-1` 边开始渲染帧 `t+1`）。
- **片段级预填充缓存。** 对于图像到视频任务，首帧的条件输入类似于大语言模型的提示词预填充：只需计算一次，即在后续的时间解码器迭代中重复使用。这实际上相当于视频领域的 KV 缓存。

# 图像修复、图像扩展与图片编辑

> 文本生成图像用于创造新内容，而修复画技则用于改进现有作品。在实际生产环境中，70%的计费图像处理工作都属于编辑类任务——更换背景、移除标志、扩展画布尺寸或重新生成手部结构等。正是在这些修复场景中，扩散模型才真正展现出其价值。

**类型：** 构建
**语言：** Python
**先修要求：** 第8阶段·07（潜在扩散模型）、第8阶段·08（ControlNet与LoRA）
**耗时：** 约75分钟

## 问题所在

有客户发送了一张完美的产品照片，但背景中有一个干扰性的标志。你需要擦除该标志，同时保持其余所有内容完全一致。你无法从头开始进行文本生成图像——那样得到的结果颜色、光线和产品角度都会不同。你需要仅重新生成被遮盖的区域，并且要求重建结果能够尊重周围的上下文。

这就是修复填充技术。其变体包括：

- **修复填充。** 在掩码区域内进行重新生成，保留掩码外的像素。
- **扩展填充。** 在掩码区域外（或超出画布范围）进行重新生成，保留掩码内的内容。
- **图像编辑。** 重新生成整张图片，但保持与原图在语义或结构上的一致性（如 SDEdit、InstructPix2Pix）。

2026 年的所有扩散模型框架均配备了修复填充功能，例如 Flux.1-Fill、Stable Diffusion Inpaint、SDXL-Inpaint 以及 DALL-E 3 Edit。它们的工作原理都是相同的。

## 概念概述

![图像修复：基于掩码的去噪技术及上下文保留的重注入机制](../assets/inpainting.svg)

### 朴素的方法（及其错误原因）

运行带掩码的标准文本转图像生成。在每个采样步骤中，用前向扩散得到的清晰图像替换噪声潜空间中未被掩码的区域。不过这种方法的效果……很差。由于模型无法获取掩码区域内的信息，边界伪影会渗透出来。

### 正确的图像修复模型

训练一个经过修改的 U-Net，使其使用 9 个输入通道而非 4 个：

```
input = concat([ noisy_latent (4ch), encoded_image (4ch), mask (1ch) ], dim=channel)
```

这些额外的通道包含 VAE 编码后的源图像副本以及单通道掩码。在训练阶段，会随机对图像的某些区域进行掩蔽，并训练模型仅对被掩蔽的区域进行去噪处理，而未被掩蔽的区域则作为干净的条件信号提供给模型。在推理时，模型能够“看到”掩蔽区域周围的景象，从而生成连贯的补全结果。

SD-Inpaint、SDXL-Inpaint 和 Flux-Fill 均采用这种 9 通道（或类似结构）的输入格式。对应的扩散模型为 `StableDiffusionInpaintPipeline` 和 `FluxFillPipeline`。

### SDEdit（Meng等人，2022）——免费编辑工具

在原始图像中加入噪声，直至达到某个中间值 `t`，然后使用新的提示词从 `t` 开始向下递归处理至 0。无需重新训练。起始值 `t` 的选择需要在图像保真度与创作自由度之间取得平衡：

- `t/T = 0.3` → 几乎与原始图像相同，仅有细微的风格变化
- `t/T = 0.6` → 中等程度的编辑，保留大致结构
- `t/T = 0.9` → 基于近乎纯噪声的输入生成，几乎不保留原始特征

### InstructPix2Pix（Brooks等人，2023年）

针对 `(input_image, instruction, output_image)` 三元组对扩散模型进行微调。在推理阶段，同时以输入图像和文本指令作为条件（如“将其设置为日落场景”、“添加一条龙”）。该模型包含两个CFG缩放参数：图像缩放系数与文本缩放系数。

### RePaint（Lugmayr等人，2022年）

保留一个标准的无条件扩散模型。在每个反向步骤中，进行重采样——偶尔跳回噪声更大的状态并重新生成。这样可以避免出现边界伪影。当没有训练好的修复模型时使用此方法。

## 构建它

`code/main.py` 实现了一种针对 5 维数据的简化版一维图像修复算法。我们首先在由两个簇各产生的 5 个浮点数样本构成的 5 维混合数据上训练 DDPM 模型。在推理阶段，我们会“屏蔽”这 5 个维度中的 2 个，在每一步中注入未被屏蔽的另外 3 个维度的含噪前向版本，最后仅重新生成被屏蔽的维度。

### 步骤 1：5 维 DDPM 数据

```python
def sample_data(rng):
    cluster = rng.choice([0, 1])
    center = [-1.0] * 5 if cluster == 0 else [1.0] * 5
    return [c + rng.gauss(0, 0.2) for c in center], cluster
```

### 步骤 2：在全部 5 个维度上训练去噪模型

标准 DDPM。针对 5 维含噪输入，输出 5 维的噪声预测值。

### 步骤 3：在推理阶段，进行掩码感知的逆操作

```python
def inpaint_step(x_t, mask, clean_image, alpha_bars, t, rng):
    # replace unmasked dims with a freshly noised version of the clean source
    a_bar = alpha_bars[t]
    for i in range(len(x_t)):
        if not mask[i]:
            x_t[i] = math.sqrt(a_bar) * clean_image[i] + math.sqrt(1 - a_bar) * rng.gauss(0, 1)
    # ...then run the normal reverse step on x_t
```

这是一种简单的处理方法，仅适用于理想化的1维数据。而真实的图像修复则需要使用9通道输入，因为纹理一致性更为重要。

### 步骤 4：外延上色

外绘技术实际上是反相后的内绘技术：通过遮罩覆盖新的（之前不存在的）画布区域，然后用原始内容填充剩余部分。其训练目标与内绘技术完全相同。

## 常见陷阱

- **接缝问题。** 直接的方法会导致可见的边界，因为梯度信息无法在掩码之间传递。解决方案：将掩码膨胀 8–16 像素，或使用合适的修复模型。
- **掩码泄漏问题。** 若条件图像中未加掩码的区域质量较低或存在噪声，会污染掩码内的生成结果。应对措施是对该区域进行去噪处理或轻微模糊处理。
- **CFG 参数与掩码尺寸的关联。** 在较小的掩码上使用过高的 CFG 值会导致生成区域颜色饱和度过高。在进行微小修改时应降低 CFG 值。
- **SDEdit 的保真度突变问题。** 当 `t/T` 的值从 0.5 变为 0.6 时，主体特征可能会丢失。建议通过逐步调整参数并定期保存检查点来规避此问题。
- **提示词不匹配问题。** 提示词应描述*整幅*图像，而不仅仅是新增内容。正确的表述应为“一只坐在椅子上的猫”，而非仅写“一只猫”。

## 使用它

| 任务 | 流水线 |
|------|----------|
| 移除物体、小范围遮罩 | SD-Inpaint 或 Flux-Fill，使用标准提示词 |
| 替换天空 | SD-Inpaint + “日落时的蓝色天空” |
| 扩展画布尺寸 | 使用 SDXL 的 outpaint 模式（8px 鸭嘴笔刷效果）或带有外延遮罩的 Flux-Fill |
| 重新生成手部/面部 | 使用描述目标对象的提示词进行 SD-Inpaint 处理，并结合 ControlNet-Openpose |
| 更改某区域的风格 | 在被遮罩的区域使用 SDEdit，参数设置为 `t/T=0.5` |
| “将其设定为日落场景” | 使用 InstructPix2Pix 或 Flux-Kontext |
| 背景替换 | 先生成 SAM 遮罩，再使用 SD-Inpaint 进行处理 |
| 超高保真度处理 | 对于最复杂的案例，可使用 Flux-Fill 或托管版的 GPT-Image |

SAM（Meta 的 Segment Anything，2023年发布）结合扩散式重绘技术是 2026 年的背景移除主流方案。SAM 2（2024年发布）则支持视频处理。

## 发布它

将文件保存为 `outputs/skill-editing-pipeline.md`。该技能工具接收原始图像、编辑描述以及可选的掩码（或 SAM 提示词），并输出：掩码生成方法、基础模型、CFG 缩放值（针对图像与文本）、SDEdit-t 模式或重绘模式，以及质量检查清单。

## 练习题

1. **简单。** 在 `code/main.py` 中，将被遮蔽维度的比例从 0.2 更改为 0.8。在何种比例下，修复后的质量（即被遮蔽维度中的残差）与直接生成的结果相当？
2. **中等难度。** 实现 RePaint 算法：在每进行 10 次反向操作后，回退 5 步（添加噪声），然后再进行去噪处理。测量该算法是否能降低遮罩边缘处的边界残差。
3. **高难度。** 使用 Hugging Face 的 diffusers 库对以下模型在 20 个面部重建任务上的表现进行对比：SD 1.5 Inpaint + ControlNet-Openpose 与 Flux.1-Fill。分别评估姿态保持程度和身份保留效果。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 内部修复 | “填补空洞” | 在掩码区域内重新生成图像；保留外部像素不变。 |
| 外部扩展 | “扩大画布” | 在画布外部区域重新生成图像；保留内部内容不变。 |
| 9通道U-Net | “理想的修复模型” | 以 `noisy \| encoded-source \| mask` 作为输入的U-Net结构。 |
| SDEdit | “带噪声级别的图转图工具” | 根据时间`t`添加噪声，再通过新提示词进行去噪处理。 |
| InstructPix2Pix | “仅文本编辑” | 基于（图像、指令、输出）三元组进行微调的扩散模型。 |
| RePaint | “无需重新训练” | 在反向生成过程中定期重新添加噪声，以减少接缝痕迹。 |
| SAM | “任意形状分割” | 通过点击或框选生成掩码的工具；通常与内部修复功能配合使用。 |
| Flux-Kontext | “带上下文编辑” | 支持输入参考图像及编辑指令的Flux模型变体。 |

## 生产注意事项：编辑流水线对延迟敏感。

用户编辑图像时期望的往返时间应在 5 秒以内。在 L4 硬件上，对 1024² 分辨率的图像进行 30 步的 SDXL-Inpaint 处理需要 3-4 秒，此外还需进行 SAM 边界框生成（约 200 毫秒）以及 VAE 编码/解码操作（合计约 500 毫秒）。在实际生产环境中，性能瓶颈主要来自总处理时间而非吞吐量——应采用单批次处理、降低并发度，并尽可能优化每个处理阶段：

- **SAM-H 是性能瓶颈所在。** 在 1024² 分辨率下，SAM-H 的处理时间约为 200 毫秒；而 SAM-ViT-B 的处理时间约为 40 毫秒，但图像质量会有轻微下降。SAM 2（用于视频）会增加时间开销，因此不适用于单张图片的编辑。
- **尽可能跳过编码步骤。** `pipe.image_processor.preprocess(img)` 函数会将图像编码为潜在表示。如果已有上一次生成得到的潜在表示（在迭代式编辑界面中很常见），可直接通过 `latents=...` 参数传入，从而省去一次 VAE 编码。
- **掩码的膨胀程度也会影响吞吐量。** 若掩码范围较小，则 U-Net 的大部分计算都会被浪费（因为未覆盖的像素最终也会被固定）。而 `diffusers` 库中的 `StableDiffusionInpaintPipeline` 会执行完整的 U-Net 计算；只有那些支持 9 通道精确填充功能的版本才能充分利用掩码进行高效计算。
- **Flux-Kontext 是 2025 年的理想解决方案。** 它只需对 `(source_image, instruction)` 进行一次前向传播——无需单独生成掩码，也无需进行 SDEdit 噪声扫描。在 H100 硬件上，其完成单次编辑的时间约为 1.5 秒。这一设计带来的核心启示是：应尽量减少中间处理步骤。

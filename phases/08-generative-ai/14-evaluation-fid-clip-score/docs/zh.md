# 评估指标 —— FID、CLIP 分数与人类偏好度

> 每个生成模型排行榜都会列出 FID、CLIP 分数以及来自人工偏好测试场的胜率。这些数值都存在被研究人员利用的失效模式。若不了解这些失效模式，就无法区分真正的改进与人为操纵的结果。

**类型：** 构建
**语言：** Python
**先修课程：** 第 8 阶段 · 01（分类法）、第 2 阶段 · 04（评估指标）
**耗时：** 约 45 分钟

## 问题所在

生成模型的评估标准为*样本质量*与*条件遵循度*。这两项指标均不存在封闭形式的衡量方法。模型需要生成10,000张图像，必须有人为这些图像打分；同时还需要在不同模型系列、不同分辨率以及不同架构之间对这些分数保持信任。在2014年至2026年的测试中，有三种指标脱颖而出：

- **FID（Fréchet Inception Distance，弗雷歇·英伟达Inception距离）**：指真实数据分布与生成数据分布在英伟达Inception网络特征空间中的距离。数值越低表示质量越好。
- **CLIP分数**：生成图像的CLIP图像嵌入向量与提示词的CLIP文本嵌入向量之间的余弦相似度。数值越高表示模型对提示词的遵循程度越好，同时也用于衡量条件遵循度。
- **人类偏好评分**：让两个模型针对同一提示词进行竞争，由人类（或类似GPT-4级别的模型）选出更优的模型，再通过汇总计算得出Elo分数。

您还将见到其他评估指标，如IS（Inception Score，现已基本不再使用）、KID、CMMD、ImageReward、PickScore、HPSv2以及MJHQ-30k。这些指标分别弥补了前代方法的不足之处。

## 概念概述

![FID、CLIP与偏好度：三个维度，不同的失效模式](../assets/evaluation.svg)

### FID — 样本质量

Heusel 等人（2017）。步骤如下：

1. 为 N 张真实图像和 N 张生成图像提取 Inception-v3 特征（维度为 2048-D）。
2. 为每个特征池拟合高斯分布：计算均值 `μ_r, μ_g` 和协方差 `Σ_r, Σ_g`。
3. FID 的计算公式为：`||μ_r - μ_g||² + Tr(Σ_r + Σ_g - 2 · (Σ_r · Σ_g)^0.5)`。

含义说明：即特征空间中两个多元高斯分布之间的弗雷歇距离。数值越低，表示两种分布的相似度越高。

常见缺陷：
- **对较小的 N 值存在偏差**。FID 是基于特征分布的均方值——当 N 较小时，协方差会被低估，从而导致 FID 值出现虚高的情况。建议始终使用 N ≥ 10,000。
- **依赖于 Inception 模型**。Inception-v3 是在 ImageNet 数据集上训练的，对于与 ImageNet 领域差异较大的数据（如人脸、艺术作品、文本图像），使用该模型计算出的 FID 值没有实际意义。此时应采用针对特定领域的特征提取器。
- **存在“作弊”现象**。过度拟合 Inception 模型的先验分布会导致 FID 值降低，但视觉质量并未随之提升。可通过下述的 CMMD 方法来解决这一问题。

### CLIP 分数——提示词遵循度

Radford 等人（2021）。针对生成的图像与提示词：

```
clip_score = cos_sim( CLIP_image(x_gen), CLIP_text(prompt) )
```

基于30,000张生成图像的平均值 → 一种可用于模型间比较的标量数值。

失效模式：
- **CLIP自身的局限性。** CLIP在构图推理方面表现较弱（例如“蓝色球体上的红色立方体”这类描述往往无法正确处理）。某些模型可能在CLIP评分上表现优异，但实际上并未真正理解复杂的提示词。
- **短提示词偏差。** 在实际数据中，短提示词更容易找到与图像匹配的CLIP结果。而较长的提示词通常会导致CLIP评分下降。
- **提示词操纵行为。** 在提示词中加入“高质量、4K、杰作”等字眼虽能提升CLIP评分，却无法增强图像与文本之间的关联度。

CMMD（Jayasumana等人，2024年）解决了其中部分问题：它采用CLIP特征而非Inception网络，并使用最大均值差异度量而非Fréchet距离。因此更擅长检测细微的质量差异。

### 人类偏好——真实基准

选择一组提示词。使用模型 A 和模型 B 进行生成，然后将生成的配对结果展示给人类（或强大的 LLM 评分员）。将胜率汇总为 Elo 分数或 Bradley-Terry 分数。常用基准数据集包括：

- **PartiPrompts（Google）**：包含 1,600 个多样化的提示词，分为 12 个类别。
- **HPSv2**：拥有 107,000 条人类标注数据，常被用作自动化代理基准。
- **ImageReward**：包含 137,000 对提示词与图像的偏好配对数据，采用 MIT 许可协议。
- **PickScore**：基于 Pick-a-Pic 的 260 万条偏好数据训练而成。
- **Chatbot-Arena 风格的图像竞技场**：如 https://imagearena.ai/ 等。

可能出现的故障模式：
- **评分员差异**。非专家的偏好可能与专家不同，因此应同时使用专家与非专家的评分。
- **提示词分布不均**。若仅选择部分提示词，可能会偏向某一类结果，必须对所选提示词进行详细记录。
- **LLM 评分员被误导**。GPT-4 类型的评分员可能会被看似美观但实际错误的输出所欺骗，需通过人类评分进行交叉验证。

## 一起使用

生产环境评估报告应包含以下内容：

1. 基于保留的真实数据分布，对 1 万至 3 万个样本的 FID 值（用于衡量样本质量）。
2. 对相同样本及其对应提示词计算得到的 CLIP 分数或 CMMD 值（用于衡量一致性）。
3. 在盲测环境中与上一代模型相比的胜率（用于反映整体偏好度）。
4. 失效模式分析：随机抽取 50 个输出结果，标记其中存在的已知问题（如手部结构、文本渲染、物体数量不一致等）。

单一指标即属虚假数据。只有三项相互印证的指标结合定性分析，才能构成可靠结论。

## 构建它

`code/main.py` 实现了对合成“特征向量”的 FID、类 CLIP-score 的评分方法以及 Elo 聚合算法（我们使用 4 维向量作为 Inception 特征的替代）。代码中包含以下内容：

- 在较小样本量 N 和较大样本量 N 下计算 FID，以观察其偏差。
- 将“CLIP score”定义为特征向量池之间的余弦相似度。
- 基于合成偏好流应用的 Elo 更新规则。

### 步骤 1：四行 FID 计算

```python
def fid(real_features, gen_features):
    mu_r, cov_r = mean_and_cov(real_features)
    mu_g, cov_g = mean_and_cov(gen_features)
    mean_diff = sum((a - b) ** 2 for a, b in zip(mu_r, mu_g))
    trace_term = trace(cov_r) + trace(cov_g) - 2 * sqrt_cov_product(cov_r, cov_g)
    return mean_diff + trace_term
```

### 步骤 2：CLIP 风格的余弦相似度计算

```python
def clip_like(image_feat, text_feat):
    dot = sum(a * b for a, b in zip(image_feat, text_feat))
    norm = math.sqrt(dot_self(image_feat) * dot_self(text_feat))
    return dot / max(norm, 1e-8)
```

### 步骤 3：Elo 分数聚合

```python
def elo_update(r_a, r_b, winner, k=32):
    expected_a = 1 / (1 + 10 ** ((r_b - r_a) / 400))
    actual_a = 1.0 if winner == "a" else 0.0
    r_a_new = r_a + k * (actual_a - expected_a)
    r_b_new = r_b - k * (actual_a - expected_a)
    return r_a_new, r_b_new
```

## 常见陷阱

- **N=1000时的FID值。** 当N达到10k时，该启发式方法不可靠。那些报告低N值FID的论文可能存在数据造假。
- **不同分辨率下的FID对比。** 使用Inception模型进行299×299尺寸调整会改变特征分布，因此应仅在相同分辨率下进行比较。
- **仅报告一个种子值。** 最少需运行3个不同的种子并报告其标准差。
- **通过负面提示提升CLIP分数。** 某些处理流程会通过过度拟合提示词来提高CLIP得分，需检查图像是否存在过饱和现象。
- **因提示词重叠导致的Elo评分偏差。** 如果两个模型在训练过程中都接触过同一基准提示词，则Elo评分毫无意义，应使用独立保留的提示词集。
- **人工评估中付费众包群体的偏差。** Prolific和MTurk平台的标注者往往偏向年轻群体且更熟悉技术，需搭配招募的艺术/设计专家共同参与评估。

2026年生产环境评估方案：

| 评估维度 | 最低标准 | 推荐标准 |
|--------|---------|-------------|
| 样本质量 | 1万个样本与保留的真实样本的FID值 | +5千个样本的CMMD值 + 每类子集的FID值 |

## 练习题

1. **简单。** 运行 `code/main.py`，在相同的合成数据分布上分别计算 N=100 和 N=1000 时的 FID 值，并报告偏差的大小。
2. **中等难度。** 基于合成的 CLIP 风格特征实现 CMMD（公式参见 Jayasumana 等人，2024 年的研究），并比较其对质量差异的敏感度与 FID 的敏感度。
3. **高难度。** 复现 HPSv2 的实验设置：从 Pick-a-Pic 数据集中选取 1000 对图像-提示对，根据这些偏好对基于 CLIP 的小型评分模型进行微调，然后测量该模型与保留测试集之间的匹配程度。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| FID | “Fréchet Inception Distance” | 高斯分布拟合结果与真实及生成版 Inception 特征之间的 Fréchet 距离。 |
| CLIP score | “文本-图像相似度” | CLIP 的图像嵌入向量与文本嵌入向量之间的余弦相似度。 |
| CMMD | “FID 的替代方案” | 基于 CLIP 特征的 MMD；偏差更小，且无需高斯假设。 |
| IS | “Inception score” | Exp KL(p(y|x) || p(y))；在现代模型上的相关性较差，已被弃用。 |
| HPSv2 / ImageReward / PickScore | “学习型偏好代理” | 基于人类偏好训练的小型模型，用作自动评估工具。 |
| Elo | “国际象棋等级分” | 基于成对对战胜率的 Bradley-Terry 聚合算法。 |
| PartiPrompts | “基准提示集” | 由 Google 筛选的涵盖 12 个类别的 1,600 个提示语。 |
| FD-DINO | “自我监督学习的替代方案” | 基于 DINOv2 特征的 FD 方法；在 ImageNet 之外的数据集上表现更佳。 |

## 生产环境注意事项：评估任务同样属于推理工作负载。

在 10,000 个样本上运行 FID 测算意味着需要生成 10,000 张图像。对于基于 SDXL 的 50 层模型，在单台 L4 硬件上以 1024×1024 的分辨率进行计算时，单次请求的推理时间约为 11 小时。评估预算十分有限，且其场景完全等同于离线推理环境（目标为最大化处理速度，忽略总延迟时间）：

- **优先考虑批量处理，忽略延迟问题。** 离线评估时应采用静态批量处理方式，使用内存所能容纳的最大批次大小。在 80GB 的 H100 硬件上，通过 `pipe(...).images` 并设置 `num_images_per_prompt=8`，其实际运行速度比单次请求快 4 到 6 倍。
- **缓存真实特征向量。** 对真实的参考图像集进行 Inception（用于 FID 计算）或 CLIP（用于 CLIP-score、CMMD 计算）特征提取的操作只需执行一次，然后将结果保存为 `.npz` 格式的文件。在后续的每次评估中均无需重新计算。

针对持续集成与回归测试：每个代码提交时，在 500 个样本的子集上运行 FID 和 CLIP score 测算（耗时约 30 分钟）；每晚则需运行完整的 10,000 样本 FID、HPSv2 以及 Elo 指标计算。

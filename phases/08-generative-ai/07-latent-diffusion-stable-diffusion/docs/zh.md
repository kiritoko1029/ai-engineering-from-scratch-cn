# 潜在扩散模型与稳定扩散模型

> 在 512×512 的图像上进行像素级扩散运算简直就是一种计算上的“战争罪行”。Rombach 等人（2022）指出，生成图像其实并不需要全部 786k 个维度——只需足够捕捉语义结构的维度即可，其余部分则可通过独立的解码器处理。将扩散过程在 VAE 的潜在空间中运行，这一思路便是 Stable Diffusion 的诞生基础。

**类型：** 构建
**语言：** Python
**先修课程：** 第 8 阶段 · 02（VAE）、第 8 阶段 · 06（DDPM）、第 7 阶段 · 09（ViT）
**耗时：** 约 75 分钟

## 问题所在

在 512² 的像素空间进行扩散训练意味着 U-Net 需要在形状为 `[B, 3, 512, 512]` 的张量上运行。对于一个含有 500M 参数的 U-Net，每一步采样大约需要 100 GFLOPS 的计算能力。进行 50 步采样后，每张图像的处理成本为 5 TFLOPS。若要在十亿张图像上进行训练，其计算费用将高得离谱。

这些浮点运算中的大部分都用于在网络中传递那些从感知角度而言并不重要的细节——也就是那些通过有损 VAE 就可以被压缩掉的高频纹理。Rombach 的思路是：首先训练一个 VAE（即*第一阶段*），将其冻结，然后在 4 通道的 64×64 潜在空间中完全依靠扩散模型进行训练（即*第二阶段*）。虽然使用的仍是同一个 U-Net，但像素数量仅为原来的 1/16，因此在保持相近质量的前提下，所需的浮点运算量大约可减少 64 倍。

这便是 Stable Diffusion 的实现方案。SD 1.x / 2.x 使用的是在 `64×64×4` 潜在空间上运行的 860M 参数 U-Net，SDXL 则采用在 `128×128×4` 潜在空间上运行的 2.6B 参数 U-Net，而 SD3 则用带有流匹配功能的扩散变换器（DiT）取代了 U-Net。Flux.1-dev（Black Forest Labs，2024 年发布）则配备了 12B 参数的 DiT-MMDiT 模型。所有这些模型都基于相同的两阶段架构运行。

## 概念概述

![潜在扩散：VAE压缩 + 潜在空间中的扩散](../assets/latent-diffusion.svg)

**分为两个阶段，分别训练。**

1. **第一阶段 — VAE。** 编码器 `E(x) → z`，解码器 `D(z) → x`。目标压缩效果：在每个空间轴上缩小8倍分辨率，并调整通道数，使总潜在特征维度约为像素数的1/16。损失函数 = 重建损失（L1损失 + LPIPS感知损失）+ KL散度（权重较小，以避免过度强制 `z` 服从高斯分布，因为我们并不需要从 `z` 中进行精确采样）。通常会结合对抗性损失进行训练，以使解码后的图像更加清晰。

2. **第二阶段 — 对 `z` 进行扩散。** 将 `z = E(x_real)` 视为数据源。训练一个U-Net（或DiT）模型来对 `z_t` 进行去噪处理。在推理时：通过扩散过程采样得到 `z_0`，随后通过 `x = D(z_0)` 生成图像。

**文本条件控制。** 包含两个额外组件。一个是固定的文本编码器（SD 1.x版本使用CLIP-L，SD 2/XL版本使用CLIP-L+OpenCLIP-G，SD3及Flux版本使用T5-XXL）。另一个是交叉注意力注入机制：每个U-Net模块都会同时接收 `[Q = 图像特征, K = V = 文本令牌]`，并将二者混合。文本仅通过这些令牌来影响图像。

**损失函数与第06课相同。** 对噪声的DDPM / 流匹配MSE损失函数保持不变，只是数据域发生了替换。

## 构建它

`code/main.py` 在第06课介绍的DDPM模型之上叠加了一个简化的1维“VAE”（用于演示的恒等编码器+解码器；真正的VAE通常为卷积网络），并加入了无分类器的引导机制以实现类别条件控制。该示例证明了无论是在原始1维数据上还是经过编码的数据上运行，相同的扩散损失函数均有效——这正是其核心思想所在。

### 步骤 1：编码器/解码器

```python
def encode(x):    return x * 0.5          # toy "compression" to smaller scale
def decode(z):    return z * 2.0
```

真正的VAE拥有经过训练的权重。从教学角度而言，这个线性映射已足以说明扩散过程是在`z`空间上进行的，而无需考虑原始数据空间。

### 步骤 2：在 `z` 空间中进行扩散

与第06课使用的DDPM算法相同。网络接收的数据为`z = E(x)`。在采样得到`z_0`后，使用`D(z_0)`进行解码。

### 步骤 3：无分类器引导

在训练过程中，有10%的概率丢弃类别标签（用空值标记替代）。在推理时，计算 `ε_cond` 和 `ε_uncond` 的值，随后：

```python
eps_cfg = (1 + w) * eps_cond - w * eps_uncond
```

`w = 0` 表示无引导（完全随机），`w = 3` 为默认值，`w = 7+` 表示过饱和/过度锐化。

### 步骤 4：文本条件化（概念说明，非代码实现）

将类别标签替换为冻结文本编码器的输出。通过交叉注意力机制将该文本嵌入传递给U-Net：

```python
h = h + CrossAttention(Q=h, K=text_embed, V=text_embed)
```

这就是类条件扩散模型与 Stable Diffusion 之间唯一的实质性差异。

## 常见陷阱

- **VAE 缩放因子不匹配。** SD 1.x 系列的 VAE 在编码后会应用一个缩放常数（`scaling_factor ≈ 0.18215`）。若忽略此设置，U-Net 将在方差严重错误的潜在特征上训练。每个检查点都会附带该常数。
- **文本编码器存在隐性错误。** SD3 需要参数量 ≥128 的 T5-XXL 模型，而仅使用 CLIP 作为替代方案会导致质量损失。务必确保设置 `use_t5=True`，否则提示词的相关性会大幅下降。
- **潜在特征空间混用问题。** SDXL、SD3 和 Flux 均采用不同的 VAE。在 SDXL 的潜在特征上训练的 LoRA 模型无法用于 SD3。Hugging Face diffusers 0.30 及更高版本不会加载不匹配的检查点。
- **CFG 参数过高。** 当 `w > 10` 时，生成的图像会显得饱和且油腻，同时过度拟合提示词，从而降低多样性。最佳参数范围为 `w = 3-7`。
- **负面提示词泄露问题。** 空的负面提示词会成为空值标记；非空的负面提示词则会成为 `ε_uncond` 标记。二者并不相同，某些处理流程会默认使用空值标记。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 第一阶段 | “VAE” | 已训练好的编码器/解码器对；可将 512² 维空间压缩至 64² 维空间。 |
| 第二阶段 | “U-Net” | 在潜在空间上运行的扩散模型。 |
| CFG | “引导尺度” | 公式为 `(1+w)·ε_cond - w·ε_uncond`，用于调节条件控制的强度。 |
| 空令牌 | “空提示嵌入向量” | 用作 `ε_uncond` 的无条件嵌入向量。 |
| 交叉注意力 | “文本如何被输入” | 每个 U-Net 块会将文本标记作为键（K）和值（V）进行注意力计算。 |
| DiT | “扩散变换器” | 用基于潜在特征块的变换器替代 U-Net，性能表现更佳。 |
| MMDiT | “多模态 DiT” | SD3 的架构：包含文本流与图像流，并通过联合注意力机制进行处理。 |
| VAE 缩放因子 | “魔法数字” | 用于将潜在空间维度除以约 5.4，从而使扩散过程在单位方差空间中运行。 |

## 生产环境注意事项：在 8GB 容量的消费级 GPU 上运行 Flux-12B 模型

该参考用的 Flux 集成方案是验证“我拥有消费级 GPU，能否部署此模型？”这一问题的标准范例。其核心思路正是推理领域中常用的那三种优化策略，应用于扩散式 DiT 模型上：

1. **分阶段加载**。Flux 包含三个无需同时驻留在显存中的网络：T5-XXL 文本编码器（fp32 格式下约 10 GB）、CLIP-L（较小规模）、12B MMDiT 以及 VAE。首先对提示词进行编码，*删除* 编码器后加载 DiT 进行去噪处理，*删除* DiT 后再加载 VAE 进行解码。消费级 8GB GPU 一次仅能容纳其中一个阶段。
2. **通过 bitsandbytes 实现 4 位量化**。对 T5 编码器和 DiT 均使用 `BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.bfloat16)` 配置进行量化。此举可将内存占用降低 8 倍，根据 Aritra 的基准测试（见笔记本中的链接），其对文本转图像任务的质量影响几乎不可察觉。
3. **CPU 协同处理**。通过 `pipe.enable_model_cpu_offload()` 可在每次前向传播过程中自动在 CPU 和 GPU 之间切换模块。虽然会增加 10-20% 的延迟，但能让整个流程得以运行。

内存占用计算如下：量化后的 T5 为 `10 GB / 8 = 1.25 GB`，量化后的 DiT 参数量为 `12 B × 0.5 字节 ≈ 6 GB`，此外还需考虑激活值所占用的内存。用 stas00 的术语来说，这属于 TP=1 推理的极端情况——既不采用模型并行技术，也使用最高级别的量化策略。在生产环境中通常会在 H100 硬件上采用 TP=2 或 TP=4 的配置；而对于单台开发笔记本电脑而言，上述方案便是最佳选择。

# ControlNet、LoRA 与条件控制

> 仅凭文本作为控制信号效率极低。ControlNet 允许用户克隆预训练的扩散模型，并通过深度图、姿态骨架、草图或边缘图像来操控该模型。LoRA 则允许用户通过训练 1000 万个参数来实现对拥有 20 亿个参数的模型的微调。正是这两项技术将 Stable Diffusion 从一种实验性工具转变成了 2026 年所有设计机构都在使用的标准图像生成流程。

**类型：** 构建
**语言：** Python
**先修要求：** 第 8 阶段 · 07（潜在扩散模型），第 10 阶段（从零构建大语言模型 —— 作为 LoRA 的基础）
**耗时：** 约 75 分钟

## 问题所在

像“一个穿红裙子的妇女在繁忙的街道上牵着狗散步”这样的提示词无法让模型知晓狗位于*何处*、妇女处于*何种姿势*，以及街道的*视角*。仅通过文字就能明确图像特征的约10%，其余部分属于视觉信息，难以用语言高效描述。

针对每种信号（姿态、深度、Canny边缘检测、分割）从零开始训练新的条件模型成本极高。因此通常会保持26亿参数的SDXL主干网络不变，再附加一个小型侧网络来读取条件信息，并利用其微调主干网络的中间特征——这就是ControlNet的原理。

此外，人们还希望在不重新训练整个模型的情况下让模型学习新概念（如自己的面部、产品或风格），并实现100倍更小的参数增量。这就需要LoRA——一种能够插入现有注意力权重中的低秩适配器。

ControlNet + LoRA + 文本描述 = 2026年从业者的标准工具组合。大多数生产级图像处理流程会在SDXL / SD3 / Flux等基础模型之上叠加2到5个LoRA、1到3个ControlNet，以及一个IP-Adapter。

## 概念概述

![ControlNet 用于克隆编码器；LoRA 则用于添加低秩增量](../assets/controlnet-lora.svg)

### ControlNet（张等人，2023年）

选取一个预训练的 SD 模型。复制 U-Net 的编码器部分，同时冻结原始模型的对应部分。对复制的编码器进行训练，使其能够接收额外的条件输入（如边缘信息、深度数据、姿态信息）。通过零卷积跳接方式将复制的编码器与原始模型的解码器部分连接起来——这些零卷积为 1×1 卷积，初始权重设为零，起初不起作用，后续会学习出相应的差异值。

```
SD U-Net decoder:   ... ← orig_enc_features + zero_conv(controlnet_enc(condition))
```

零卷积初始化意味着 ControlNet 在初始阶段即为恒等映射——即使在训练前也不会造成任何不良影响。使用标准扩散损失，对 100 万个（提示词、条件、图像）三元组进行训练。

各模态的 ControlNets 以小型辅助模型的形式提供（SDXL 约 3.6 亿参数，SD 1.5 约 7000 万参数）。在推理时可以将其组合使用：

```
features += weight_a * control_a(depth) + weight_b * control_b(pose)
```

### LoRA（Hu等人，2021年）

对于模型中的任意线性层 `W ∈ R^{d×d}`，冻结 `W` 并添加一个低秩增量：

```
W' = W + ΔW,  ΔW = B @ A,  A ∈ R^{r×d},  B ∈ R^{d×r}
```

通过 `r << d` 的方式实现。注意力机制的秩通常为 4-16，而深度微调时的秩则为 64-128。新增参数数量为 `2 · d · r`，而非 `d²`。以 `d=640`、`r=16` 的 SDXL 注意力机制为例，每个适配器的参数量为 2 万，远低于原来的 41 万——实现了 20 倍的参数量缩减。在整个模型层面来看，LoRA 的大小通常在 20-200MB 之间，而基础模型的大小则为 5GB。

在推理阶段，可以对 LoRA 进行缩放：`W' = W + α · B @ A`。常规的 `α` 值范围为 0.5-1.5。多个 LoRA 可以以加法方式叠加（但需注意它们之间会以非线性方式产生交互）。

### IP适配器（Ye等人，2023年）

一种小型适配器，可接受*图像*作为条件输入（与文本一同使用）。它利用 CLIP 图像编码器生成图像令牌，并将这些令牌与文本令牌一起注入到交叉注意力机制中。每个基础模型大小约为 20MB。无需使用 LoRA 即可实现“按照此参考图像的风格生成新图像”的功能。

## 可组合性矩阵

| 工具 | 控制内容 | 大小 | 使用场景 |
|------|----------|------|----------|
| ControlNet | 空间结构（姿态、深度、边缘） | 70-360MB | 需要精确布局或构图时 |
| LoRA | 风格、主体、概念 | 20-200MB | 进行个性化定制或调整风格时 |
| IP-Adapter | 基于参考图像的风格或主体 | 20MB | 当文本无法描述所需视觉效果时 |
| Textual Inversion | 将单一概念作为新标记 | 10KB | 旧版技术，现已大多被 LoRA 取代 |
| DreamBooth | 对特定主体进行完整微调 | 2-5GB | 需要强烈独特性且计算资源充足时 |
| T2I-Adapter | 较轻量的 ControlNet 替代方案 | 70MB | 适用于边缘设备或计算资源受限的场景 |

ControlNet ≈ 空间层面控制。LoRA ≈ 语义层面控制。可同时使用两者。

## 构建它

`code/main.py` 在一维空间中模拟了这两种机制：

1. **LoRA。** 使用一个预训练的线性层 `W`，将其冻结。然后训练一个低秩矩阵 `B @ A`，使得 `W + BA` 能够与目标线性层相匹配。需要证明当秩 `r = 1` 时，即可完美地学习到秩为 1 的修正项。

2. **ControlNet-lite。** 包含一个“冻结的基础”预测器以及一个用于读取额外信号的“侧网络”。侧网络的输出由一个初始值为零的可学习标量进行控制（即我们实现的零卷积）。通过训练可以观察到该控制标量的值逐渐上升。

### 步骤 1：LoRA 数学原理

```python
def lora(W, A, B, x, alpha=1.0):
    # W is frozen; A, B are the trainable low-rank factors.
    return [W[i][j] * x[j] for i, j in ...] + alpha * (B @ (A @ x))
```

### 步骤 2：零初始化侧网络

```python
side_out = control_net(x, condition)
gated = gate * side_out  # gate initialized to 0
h = base(x) + gated
```

在步骤 0 时，输出与基准版本完全相同。早期训练阶段会缓慢更新 `gate` 参数——不会出现灾难性的偏差。

## 常见陷阱

- **过度扩展的 LoRAs。** 将 `α = 2` 或 `α = 3` 作为“增强模型性能”的常用手段，往往会导致输出风格过重或出现异常。请将 `α` 保持在 `≤ 1.5` 的范围内。
- **ControlNet 权重冲突。** 同时使用权重为 1.0 的姿态 ControlNet 和深度 ControlNet 通常会导致控制效果过度。将权重之和设定在约 1.0 是安全的默认值。
- **在错误的基础模型上使用 LoRA。** 由于注意力维度不匹配，SDXL 版本的 LoRAs 在 SD 1.5 模型上会无法正常工作且无任何提示。此类问题通常会在 0.30 秒后由扩散模型发出警告。
- **文本反演偏差。** 基于某个检查点训练的 Token 在其他检查点上可能会出现严重偏差。相比之下，LoRA 的兼容性更强。
- **LoRA 权重合并与存储。** 可以将 LoRA 合并到基础模型权重中以实现更快的推理速度（无需在运行时额外加载），但这样会失去在运行时调整 `α` 值的能力。建议同时保留两种版本。

## 练习题

1. **简单。** 在 `code/main.py` 中，将 LoRA 的秩 `r` 从 1 更改为 4。在哪个秩值下，LoRA 能够与秩为 2 的目标增量完全匹配？
2. **中等难度。** 对两个不同的目标变换分别训练两个独立的 LoRA 模型。将它们同时加载并展示它们的叠加效应。这种交互会在何时不再保持线性关系？
3. **高难度。** 使用扩散模型进行堆叠：SDXL-base + Canny-ControlNet（权重为 0.8）+ 一个风格 LoRA（α 值为 0.8）+ IP-Adapter（权重为 0.6）。随着各组分的权重发生变化，测量 FID 值与提示词遵循度之间的权衡关系。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| ControlNet | “空间控制” | 克隆编码器 + 零卷积跳过层；用于读取条件图像。 |
| Zero convolution | “初始为恒等映射” | 初始化为零的 1×1 卷积；ControlNet 在此阶段无实际作用。 |
| LoRA | “低秩适配器” | 表达式为 `W + B @ A`，其中 `r << d`；其参数量仅为完整微调的百分之一。 |
| rank r | “调节旋钮” | 用于控制 LoRA 的压缩程度；通常取值为 4-16，若需高度个性化则可设置为 64 及以上。 |
| α | “LoRA 强度” | 运行时对 LoRA 变化量的缩放系数。 |
| IP-Adapter | “参考图像” | 通过 CLIP 图像令牌实现的小型图像条件适配器。 |
| DreamBooth | “完整主体微调” | 使用该主体的约 30 张图片对整个模型进行训练。 |
| Textual Inversion | “新令牌学习” | 仅用于学习新的词嵌入；属于旧技术，现已大多被替代。 |

## 生产注意事项：LoRA 模型切换、ControlNet 路径配置、多租户服务架构

一个真正的文本生成图像 SaaS 平台会在同一个基础检查点上加载数百个 LoRA 模型以及十几个 ControlNet 模型。其服务架构与 LLM 多租户模式极为相似（相关生产级文献已从连续批处理、LoRAX 以及 S-LoRA 的角度探讨过 LLM 场景）：

- **热切换 LoRA，切勿合并。** 将 `W' = W + α·B·A` 的公式直接合并到基础模型中虽可使每步推理速度提升约 3-5%，但会锁定 `α` 值及基础模型本身。应将 LoRA 模型以秩差分的形式保留在 VRAM 中；扩散模型通过 `pipe.load_lora_weights()` 和 `pipe.set_adapters([...], adapter_weights=[...])` 函数在每次请求时动态激活这些 LoRA。切换成本为 `2 · d · r · num_layers` 量级的权重数据——规模可达数 MB，切换时间在亚秒级。
- **ControlNet 作为第二条注意力通道。** 复制的编码器会与基础模型并行运行。若同时使用两个权重均为 1.0 的 ControlNet 模型，则每步需要额外执行两次前向传播，而非一次合并后的传播。批量处理的容量将呈二次方级下降。对于每个处于活跃状态的 ControlNet 模型，需预留约 1.5 倍的步骤成本预算。
- **量化后的 LoRA 同样适用。** 若已对基础模型进行量化（参见第 07 课：8GB 内存的 Flux 模型量化），LoRA 的差分部分也可直接被清晰地量化为 8 位或 4 位格式。采用 QLoRA 风格的加载方式，即可在 4 位版本的 Flux 基础模型之上叠加 5-10 个 LoRA 模型，而不会导致内存溢出。

针对 Flux 的特殊说明：Niels 发布的 8GB 内存 Flux 实验笔记中将基础模型量化为 4 位；即便在该量化后的基础上加载风格类 LoRA 模型（通过 `pipe.load_lora_weights("user/style-lora")`），并指定权重文件名为 `weight_name="pytorch_lora_weights.safetensors"`，该方案依然可行。这正是 2026 年大多数 SaaS 服务提供商所采用的实现方案。

# 模型路由：降本增效的核心手段

> 动态路由代理会评估每一个请求（任务类型、token 长度、嵌入相似度、置信度），将简单查询发送到廉价模型，将复杂请求升级到前沿模型。这种做法也被称为模型级联（model cascading）。生产环境案例研究显示，在美国/英国/欧洲的部署中，质量持平的情况下可实现 20-60% 的成本降低；在高流量 SaaS 场景中，30% 的路由效率提升可转化为六位数的年化节省。2026 年的背景是 LLM 推理价格每年下降约 10 倍——从 2022 年末到 2026 年，一个 GPT-4 级别的 token 价格从 $20/M 降至约 $0.40/M。价格下降主要来自更优的服务栈（Phase 17 · 04-09），而非硬件。路由是你在不影响产品的前提下，将价格下降转化为利润的关键手段。失败模式是廉价模型漂移：路由将 40% 的流量推向较弱的模型，推理任务的质量下降 3-5%，一个季度都没人察觉。要用在线质量指标来把关路由，而不仅仅是离线评估集。

**类型：** 学习
**语言：** Python（标准库，玩具级级联路由模拟器）
**前置要求：** Phase 17 · 01（托管 LLM 平台），Phase 17 · 19（AI 网关）
**所需时间：** 约 60 分钟

## 学习目标

- 解释模型级联机制：廉价优先并进行置信度检查，低置信度时升级。
- 列举四种路由信号（任务分类、提示词长度、与已知难题集的嵌入相似度、首轮自信心）。
- 计算在目标路由分配比例和质量损失容忍度下的预期混合成本。
- 识别漂移监控指标（在线质量门控），用于捕捉廉价模型的悄悄渗透。

## 问题所在

你的服务每月在 GPT-5 上花费 $80k。分析数据显示 70% 的查询是简单的："巴黎现在几点？""改写这句话。"一个 Haiku 级模型能以 3% 的成本完美处理这些请求。30% 的查询需要 GPT-5 的推理能力——编码、数学、多步规划。

如果你将 70% 的流量路由到廉价模型，30% 路由到昂贵模型，你的账单将降低约 65%，且产品质量不变。这就是路由。关键在于在不降低质量的前提下构建路由代理。

## 概念说明

### 四种路由信号

1. **任务分类**：简单/复杂/代码生成/数学/聊天。可以是基于规则的分类器、一个小型 LLM（Haiku 级，$0.25/M），或与标注桶的嵌入相似度。输出：路由 = cheap / balanced / frontier。

2. **提示词长度**：超过 4K token 的提示词通常需要前沿模型来保证连贯性。低于 500 token 的提示词通常不需要。

3. **与已知难题集的嵌入相似度**：如果查询与已知难题桶接近（余弦相似度 > 0.88），直接升级到前沿模型。

4. **首轮自信心**：先发送到廉价模型；如果模型的 log-probs 显示低置信度，或模型拒绝回答，或输出含糊语言，则在前沿模型上重试。这会对约 10% 的流量增加 P95 延迟，但在其余 90% 上节省 50% 以上。

### 三种模式

**预路由**（前置分类器）：增加约 5-10ms 延迟；总体最快。

**级联**（廉价优先，低置信度升级）：中位延迟约 1.2 倍（廉价运行加验证），升级时约 2 倍。质量下限最优。

**集成路由**（并行运行廉价和前沿模型，奖励模型择优）：质量最高，成本最高；仅用于关键 A/B 测试。

### 实现方式

AI 网关（Phase 17 · 19）提供路由能力。LiteLLM 具有 `router` 配置，支持回退和成本路由。Portkey 提供防护和路由功能。Kong AI Gateway 提供基于插件的路由。OpenRouter 的模型市场提供推荐 API。

开源方案：RouteLLM（LMSYS）、Not Diamond（商业）、Prompt Mule。

### 2026 年价格曲线

| 模型级别 | 2022 年末 | 2026 年 | 变化 |
|----------|----------|---------|------|
| GPT-4 级质量 | ~$20/M | ~$0.40/M | 便宜 50 倍 |
| 前沿（GPT-5，Claude 4） | — | ~$3-10/M | 新层级 |

大部分改进来自服务效率——Phase 17 · 04-09 的核心经验转化为供应端的成本下降。路由让你在应用层获取这些收益，而不是等待所有用户迁移到廉价层级。

### 漂移是真正的风险

你的路由将 40% 的流量发送到廉价模型。六个月后，任务分布发生了变化（用户变得更老练，提出更长的问题）。路由器没有察觉，因为它的分类器是基于第一季度的数据训练的。质量悄然下降。没有人足够大声地抱怨。你在竞争对手的基准测试中才发现自己已经落后了。

用在线质量指标来把关路由：

- 每条路由的用户点赞/点踩。
- 对每条路由的留存样本（5%）进行自动化 LLM 裁判评估。
- 升级率：如果级联的上行路由超过 30%，说明廉价模型被过度路由了。
- 每条路由的拒绝率。

### 需要记住的数字

- 2026 年质量持平下的路由节省：案例研究中为 20-60%。
- 2022-2026 年 LLM 价格下降：每年合计约 10 倍。
- GPT-4 级别 2022 vs 2026：~$20/M → ~$0.40/M。
- 级联延迟影响：中位约 1.2 倍，升级时约 2 倍（约占流量的 10%）。

## 练习

1. 运行 `code/main.py`。在什么准确率下限下，级联优于预路由？
2. 你的用户群中 30% 是企业用户（复杂查询），70% 是免费用户（简单查询）。设计路由分配方案。用什么在线指标来把关？
3. 某条路由使质量下降 2% 但节省 40%。是否应该上线？取决于产品——请分别论证两方观点。
4. 使用 OpenAI / Anthropic API 的 logprobs 实现置信度检查。你的起始阈值是多少？
5. 六个月内，升级率从 8% 攀升到 22%。诊断三个原因及各自的修复方案。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| 模型路由 | "成本代理" | 每个请求动态选择模型 |
| 模型级联 | "廉价优先升级" | 先运行廉价模型，低置信度时回退到前沿模型 |
| 预路由 | "先分类" | 前置分类器；无重跑 |
| 集成路由 | "并行择优" | 运行多个模型，奖励模型选择最佳 |
| 升级率 | "上行路由比例" | 级联请求中被升级的比例 |
| RouteLLM | "LMSYS 路由器" | 开源路由库 |
| Not Diamond | "商业路由器" | SaaS 模型路由产品 |
| 漂移 | "廉价渗透" | 分布变化但路由器未察觉 |
| 在线质量门控 | "实时检查" | 对实时流量进行自动化 LLM 裁判采样 |

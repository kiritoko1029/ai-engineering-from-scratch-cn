# 分块策略对比

> 分块决定了你的检索器能够返回什么。切分边界出错，无论嵌入模型、重排器还是 LLM 都无法在下游修复损坏。

**类型：** 构建
**语言：** Python
**前置要求：** 第11阶段 课程04（嵌入）、06（RAG）、07（高级 RAG）；第19阶段 Track B 基础（课程20-29）
**所需时间：** 约90分钟

## 学习目标

- 从零实现五种分块策略：固定窗口、句子、递归分割、语义聚类和结构化 Markdown 标题。
- 在带有标注答案区间的测试语料库上测量 recall@k，并解释为什么一种策略在散文上获胜，而另一种策略在技术文档上获胜。
- 阅读分块长度分布，识别每种策略注入的失败模式：孤立句子、符号中间切割、仅标题的分块、语义漂移。
- 通过检查三个属性（文档类型、平均段落长度、格式是否携带显式结构）为新语料库选择默认策略，而无需运行基准测试。

## 问题所在

每个 RAG 管道的第一步是将源文档切割成足够小的片段，使嵌入模型能放入，同时又足够大，使每个片段承载一个自包含的思想。在哪里切割的选择不是超参数。它是检索器能够返回内容的上限。

一个询问"预算中止阈值是什么样的"的查询，只有在包含中止阈值的分块可被检索到时才能成功。如果固定窗口分割器将阈值值从周围上下文中切出，嵌入会移动到不同的聚类，BM25 分数下降，重排器看到噪声，LLM 生成的答案就是错误的。2024 年的论文"LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs"测量到，仅因分块选择的不同，检索召回率就有 35 个百分点的绝对波动。2025 年关于上下文分块标题的后续工作缩小了差距，但并未消除。

本课并排构建五种策略，在带有标注答案区间的测试语料库上运行它们，让你自己阅读召回率数字。

### 固定窗口

暴力基线。每 N 个字符切割一次。可选择重叠，使在位置 N 被切割的句子在从位置 N - overlap 开始的分块中完整出现。快速、确定性、在边界处表现糟糕。用作对照组，而非默认方案。

### 句子

通过正则表达式或简单状态机在句子边界处分割。将一个或多个句子打包到一个分块中，直到达到目标字符预算。不会在单词中间切割。但仍然会在段落中间和章节中间切割。这是许多早期 RAG 管道中的默认方案，对于没有其他结构的散文是合理的选择。

### 递归分割

2023 年代库所推广的层级策略。首先尝试在最强分隔符处分割（双换行、段落），回退到下一个（单换行），然后是句子，最后是字符。当分块符合预算时递归终止。对于结构不一致的文档表现出色，因为它按区域自适应。

### 语义聚类

嵌入每个句子。将共享主题质心的连续句子聚类。当运行中的质心相似度低于阈值时切割。边界反映的是语义，而非字符。构建更慢，依赖嵌入模型，但对于在段落内切换主题的文档具有韧性。

### 结构化 Markdown 标题

对于携带显式结构的文档（Markdown、reStructuredText、RFC 风格的编号章节），在标题边界处切割。每个分块成为标题加上其下方直到同级或更高级别下一个标题的所有内容。每个主题的分块最小，但仅在语料库格式良好时可用。

### recall@k 如何衡量边界选择

一个标注了金标准的查询携带源文档中答案区间的精确字符偏移量。分块后，你问：检索器返回的前 k 个分块中是否有任何一个与金标准区间重叠？如果是，该查询的 recall@k 为 1。如果不是，为 0。在查询集上取平均。对每种策略运行相同的评估，分布会告诉你哪种边界策略能存活于你拥有的语料库。

## 开始构建

`code/main.py` 实现了：

- `fixed_window(text, size, overlap)` - 基线。
- `sentence_chunks(text, target)` - 简单的句子打包器。
- `recursive_split(text, separators, target)` - 层级递归。
- `semantic_chunks(text, similarity_threshold)` - 基于确定性模拟嵌入的质心聚类。
- `structural_markdown(text)` - 标题感知的分割器。
- `mock_embed(text, dim)` - 基于哈希的嵌入，使循环可以离线运行。
- `DenseIndex` - 与第19阶段 Track B 的混合检索课程中使用的相同形状。
- `eval_recall(strategy, corpus, queries, k)` - 对比循环。
- 一个 `main()` 函数，在测试语料库上运行每种策略并打印 recall@k 表。

运行：

```bash
python3 code/main.py
```

输出是一个小表，每种策略一行，每个 k 值一列。句子策略在结构化测试数据上表现不佳。结构化 Markdown 在 Markdown 测试数据上获胜。递归策略在混合测试数据上表现稳定，因为递归会自适应。语义聚类在没有有用结构线索的散文测试数据上获胜。

## 表格无法隐藏的失败模式

**孤立句子。** 句子打包产生缺少主题句的分块。嵌入随后指向错误的聚类。

**符号中间切割。** 固定窗口在代码或 YAML 中会将标识符切成两半。两半都嵌入为噪声。

**仅标题的分块。** 结构化 Markdown 会输出只包含 `## Title` 的分块。过滤掉它们或附加下一个分块的第一段。

**语义漂移。** 当语料库统一在同一主题上时，语义聚类切割不足。一个 5000 字符的分块将许多具体答案打包到一个分散的嵌入中。将语义与硬字符上限结合使用。

**过时的嵌入。** 语义聚类使用嵌入模型。如果你更改模型，你也更改了分块。将分块模型与检索模型分开固定，或一起重建索引。

## 不运行基准测试就能选择默认策略

三个属性决定了新语料库的默认分块器。

| 属性 | 值 | 默认方案 |
|------|-----|----------|
| 文档类型 | 无结构的散文 | 递归分割，目标 800 |
| 文档类型 | Markdown / RFC / API 文档 | 结构化 Markdown |
| 文档类型 | 代码 | AST 感知（超出范围；见第19阶段课程02） |
| 段落长度 | 长，单一主题 | 句子，目标 500 |
| 段落长度 | 短，混合主题 | 语义，阈值 0.6 |

有疑问时，选择递归分割。它是最强的单策略基线。

## 实际应用

生产模式：

- 在发布新管道之前运行评估；不要信任你的库默认的策略。
- 每次更改嵌入模型或语料库组合时重新运行评估；获胜者取决于语料库。
- 在每个分块的元数据中持久化策略名称，以便后续可以归因回归。

## 练习

1. 添加第六种策略：使用 `tiktoken` 而非字符计数的 token 窗口。在同一测试数据上与固定窗口对比。
2. 在散文测试数据中注入 30% 的代码块。重新运行表格。解释为什么除了结构化 Markdown 之外的每种策略都损失了召回率。
3. 将确定性嵌入替换为你的项目真实提供商的嵌入。测量语义聚类的召回率变化。报告策略之间的分布是变宽还是变窄。
4. 为每个分块添加 `summary` 字段：一句话的质心描述。将摘要附加到分块主体后重新运行评估。测量召回率提升。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|----------|
| Recall@k | "我们拿到正确的分块了吗？" | 前 k 个分块中任一与金标准答案区间重叠的查询比例 |
| 分块重叠 | "滑动窗口" | 在下一个分块中重新包含前一个分块的最后 N 个字符 |
| 结构化分割器 | "标题感知分块" | 在 H1/H2/H3 边界处切割；标题文本是分块的一部分 |
| 语义分块器 | "主题感知分块" | 嵌入句子，按质心相似度聚类，在漂移处切割 |
| 质心漂移 | "主题转换" | 运行均值与下一个句子之间的余弦相似度低于阈值 |

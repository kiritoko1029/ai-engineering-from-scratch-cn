# 流水线并行与气泡分析

> 张量并行将矩阵乘法拆分到各 rank 之间。流水线并行将模型拆分到各 rank 之间，每个 rank 一个阶段。微批次流过流水线。开头和结尾的空闲时间就是气泡；最小化它就是全部工艺。

**类型：** 构建
**语言：** Python
**前置要求：** 第19阶段 Track C 第42-49课
**所需时间：** 约90分钟

## 学习目标

- 将一个顺序模型拆分为 N 个阶段，在 N 个 rank 上模拟前向流水线。
- 使用 GPipe 调度（纯前向填充，然后反向）调度 M 个微批次通过流水线，计算气泡比例。
- 将气泡与 Megatron-LM 和 PipeDream 中使用的交错 1F1B 调度进行比较。
- 论证阶段分配：每阶段等量计算比每阶段等量参数更重要。

## 问题所在

一个 fp16 的 700 亿参数模型仅参数就需要 140 GB。没有消费级 GPU 放得下。ZeRO-3 将参数分片到各 rank，但仍需要每个 rank 为每个前向步 allgather 完整层，每层支付 log(N) 跳。流水线并行采取不同路线：将模型切成 N 个阶段，每个 rank 放一个阶段。第1层的前向在 rank 0 上完成，将激活张量交给 rank 1；rank 1 运行第2层，交给 rank 2；以此类推。反向反向流动。内存线性下降，因为每个 rank 只持有一个阶段；计算是顺序的，这就是气泡问题。

气泡是流水线开头的空闲时间（等待第一个微批次到达最后一个阶段）和结尾的空闲时间（等待最后一个微批次排回）。M 个微批次和 N 个阶段时，每阶段的气泡比例为 (N-1)/(M+N-1)。M=8、N=4 时是 27%。M=64、N=4 时是 4.5%。当每步有大量微批次时气泡缩小，这意味着小微批次大小，这是驱动微批次设计的约束。

```mermaid

  R0[rank 0: stage 0 / layer 0] --> R1[rank 1: stage 1 / layer 1]
  R1 --> R2[rank 2: stage 2 / layer 2]
  R2 --> R3[rank 3: stage 3 / loss]
  R3 -.backward.-> R2
  R2 -.backward.-> R1
  R1 -.backward.-> R0
```

### GPipe 调度

在启动任何反向前，先用所有 M 个微批次填充流水线前向；然后反向排空。每个微批次的激活必须保留到其反向，因此内存随 M 线性增长。前向需要 M+N-1 个周期，反向再需要 M+N-1 个周期。每阶段的有效工作是 2M 个周期；每阶段的气泡是 2(N-1) 个周期。当每个前向和反向各占一个时间单位时，气泡比例为 (N-1)/(M+N-1)。选择 M 远大于 N 可以隐藏气泡。

### 1F1B 调度

交错调度：一旦微批次的前向到达最后一个阶段，立即启动其反向并让它流回来。调度在每个阶段交替一个前向和一个反向。气泡仍是 N-1，但激活内存被流水线深度而非微批次数量约束。生产流水线使用 1F1B（Megatron、PipeDream）。本课先实现 GPipe 因为它更简单，1F1B 作为练习。

### 为什么每阶段等量计算很重要

如果阶段0需要 50 ms 而阶段1需要 100 ms，每个周期都被阶段1卡住。其他阶段每周期空闲 50 ms 等待阶段1释放。等量参数数量是错误的轴：Transformer 的计算由每层的注意力加 MLP 主导，嵌入层参数多但计算少。阶段分配应该平衡每阶段的 FLOPs，而非每阶段的权重数。

### 微批次与批次

流水线运行 M 个大小为 B 的微批次。有效批次大小为 M*B。流水线步结束时的梯度是 M*B 个示例组合的梯度。气泡比例取决于 M；优化器看到 M*B。调 M 意味着在气泡（高 M 时更低）和每微批次内存（GPipe 高 M 时激活内存更高）之间权衡。

## 生产中的实战模式

三种模式将流水线并行加固到可交付水平。

**激活检查点与流水线配合。** GPipe 中有 M 个微批次在飞，激活内存是 M 乘以一个微批次的内存。激活检查点在反向时重新计算前向，用计算换内存；两者的结合使流水线对长序列变得可行。

**阶段平衡是测量出来的，不是假设的。** 生产团队运行一次性能分析，在目标硬件上测量实际的逐层计算（FLOPs 和墙钟时间），然后按该测量分区。Megatron-LM 的 `--num-layers-per-stage` 标志接受一个列表，允许在每层成本不同的阶段使用不等的层数。

**收发调度必须避免死锁。** 让每个阶段先发后收的流水线会在线路上死锁。标准修复是交错：偶数 rank 阶段先发后收，奇数 rank 阶段先收后发。本课显式调度 rank 使模式可见。

## 实际使用

生产模式：

- **Megatron-LM。** 大规模流水线并行的参考实现。使用 1F1B，支持张量 + 流水线 + 数据并行组合。
- **DeepSpeed Pipeline。** 与 ZeRO 集成；ZeRO-1 + 流水线是最大开源模型的常见组合。
- **PyTorch Pipe。** PyTorch 原生流水线包装器，构建在 `torch.distributed.pipeline.sync.Pipe` 之上。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| Pipeline | "沿深度方向的模型并行" | 每个 rank 一个阶段，激活逐阶段流动 |
| Bubble | "流水线空闲时间" | 开头和结尾 (N-1) 步某些阶段无工作 |
| Microbatch | "批次的一片" | 一个前向/反向单元；M 增大时气泡缩小 |
| GPipe | "填充后排空" | 所有 M 个前向在任何反向之前；高激活内存 |
| 1F1B | "交错调度" | 每阶段一个前向一个反向；激活内存有界 |

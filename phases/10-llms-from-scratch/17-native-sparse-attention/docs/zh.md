# 原生稀疏注意力（DeepSeek NSA）

> 在 64k token 时，注意力消耗 70-80% 的解码延迟。每个开放模型实验室都有修复方案。DeepSeek 的 NSA（ACL 2025 最佳论文）是脱颖而出的那个：三个并行注意力分支——压缩的粗粒度 token、选择性保留的细粒度 token、以及用于局部上下文的滑动窗口——通过学习门控组合。它硬件对齐（kernel 友好）、原生可训练（在预训练中工作，而非推理时嫁接），并且在 64k 解码上比 FlashAttention 更快，同时匹配或超越全量注意力质量。本课程端到端构建三个分支，并展示为什么稀疏性是端到端可微分的。

**类型：** 构建
**语言：** Python（标准库）
**前置要求：** 第 7 阶段 · 12（KV 缓存、flash-attention），第 7 阶段 · 15（注意力变体），第 10 阶段 · 16（差分注意力）
**所需时间：** 约60分钟

## 学习目标

- 说出 NSA 三个注意力分支及其各自捕捉的内容。
- 解释为什么 NSA 是"原生可训练的"，而之前的稀疏注意力方法仅用于推理。
- 从压缩块大小和选择 top-k 的函数关系计算 NSA 相对于全量注意力在 64k 上下文下的注意力计算节省量。
- 在标准库 Python 中实现短合成序列上的三分支组合，并验证门控行为。

## 问题所在

序列长度 N 的全量注意力成本为 `O(N^2)` 时间和每层 `O(N)` KV 缓存。在 64k token 时，计算和内存带宽数字是灾难性的。NSA 论文的理论估计：在 64k 时注意力占总解码延迟的 70-80%。下游一切——TTFT、每秒 token 数、每百万 token 成本——都由注意力成本主导。

稀疏注意力是显而易见的答案。之前的尝试分为两类。固定模式稀疏（滑动窗口、步长、块局部）丢弃信息，在长程召回任务上失败。推理时稀疏（KV 缓存裁剪、H2O、StreamingLLM）应用于在全量注意力上预训练的模型，只能恢复一小部分潜在加速，因为模型从未被要求通过稀疏模式路由信息。

原生稀疏注意力（Yuan 等，DeepSeek + PKU + UW，ACL 2025 最佳论文，arXiv:2502.11089）两者兼得：一个在预训练期间学习的稀疏模式，实现为 kernel 对齐的算法，在推理时真正兑现计算节省。两年后，NSA 或其直接后代将成为每个前沿长上下文模型的默认注意力。

## 概念说明

### 三个并行分支

对于每个查询，NSA 运行三次注意力，针对 KV 缓存的三种不同视图：

1. **压缩分支。** Token 被分组为大小为 `l` 的块（通常 32 或 64）。每个块通过一个小型学习 MLP 压缩为单个摘要 token。查询在这些压缩 token 上注意力，获得整个序列的粗粒度视图。

2. **选择分支。** 使用压缩分支的注意力分数，识别与当前查询最相关的 top-k 个块。从这些块中读取细粒度（未压缩）token，查询在所有这些 token 上注意力。可以把压缩分支的注意力看作选择的路由信号。

3. **滑动窗口分支。** 查询在最近的 `W` 个 token（通常 512）上注意力以获取局部上下文。这个分支捕获另外两个可能遗漏的结构密集型短程模式（语法、局部共指）。

三个分支的输出通过学习的逐位置门控组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是来自查询上小型 MLP 的门控权重。它们不必求和为 1——可以独立加权分支。

### 为什么这是"原生可训练的"

选择步骤（top-k 块）是离散的。离散操作破坏梯度流。之前的稀疏注意力工作要么跳过选择的反向传播（限制训练），要么使用在推理时不给出真正稀疏的连续松弛。

NSA 回避了这个问题：压缩分支的注意力本身就是整个序列上的可微分粗粒度注意力。Top-k 操作只是复用压缩分支的 top 注意力分数来选择加载哪些细粒度块。梯度流通过压缩分支的分数（它同时影响压缩输出和选择逻辑），被选中块对最终输出的贡献也是可微分的。不可微分的 `top_k` 操作在前向计算图上是空操作——它只控制从内存加载哪些块。

这就是为什么 NSA 可以在预训练中端到端使用。模型学会联合通过三个分支路由信息，产生一个在推理时真正兑现加速承诺的稀疏模式。

### 硬件对齐 kernel

NSA 的 kernel 为现代 GPU 内存层次设计。kernel 按 GQA 组加载查询（外循环），为每组获取对应的稀疏 KV 块（内循环），在 SRAM 上运行注意力。因为每个查询组看到相同的选择块（选择是按查询组而非按查询头），KV 加载在组内摊销。算术强度保持高位。

论文报告 Triton kernel 在 64k 解码上比 FlashAttention 快 9 倍，加速比随序列长度增长。前向和反向 kernel 都已提供。

### 计算预算

令 `N` 为序列长度，`l` 为压缩块大小，`k` 为 top-k 选择数，`w` 为滑动窗口，`b` 为选择块大小（通常等于 `l`）。

- 压缩分支：每个查询 `O(N/l)` 个键，总计 `O(N * N / l)`。
- 选择分支：每个查询 `O(k * b)` 个键，总计 `O(N * k * b)`。
- 滑动分支：每个查询 `O(w)` 个键，总计 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

在 `N = 64k, l = 64, k = 16, b = 64, w = 512` 时：每查询成本为 `1000 + 1024 + 512 = 2536 个键`。全量注意力为 `64000 个键`。25 倍计算缩减。

在 `N = 128k, l = 64, k = 16, b = 64, w = 512` 时：每查询成本为 `2000 + 1024 + 512 = 3536 个键`。全量注意力为 `128000 个键`。36 倍缩减。收益随序列长度增长，这正是重点。

### 对比

| 方法 | 可微分 | 真实推理加速 | 长程召回 |
|------|-------|------------|---------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 步长 / 块稀疏 | 是 | 是 | 部分 |
| KV 裁剪（H2O、StreamingLLM） | 不适用（推理时） | 是 | 部分 |
| MoBA（Moonshot） | 部分 | 是 | 良好 |
| NSA | 是（原生） | 是（64k 时 9 倍） | 匹配全量注意力 |

MoBA（Moonshot，arXiv:2502.13189）同期发表，采用类似的三合一方案，将 MoE 原理应用于注意力块。NSA 和 MoBA 是 2026 年长上下文预训练需要了解的两种架构。

## 开始构建

`code/main.py` 在短合成序列上实现三个分支并展示：

- 压缩 MLP（为教学清晰使用简单的均值池化基线；真正的 NSA 使用学习 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 最后 `w` 个 token 上的滑动窗口注意力。
- 门控组合。
- 与全量注意力的计算量对比打印。

### 第 1 步：将 token 压缩为块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 第 2 步：压缩分支注意力

对压缩键运行查询的 softmax 注意力。压缩分支分数同时作为 top-k 选择的信号。

### 第 3 步：top-k 块选择

选取 `k` 个最高分压缩块的索引。加载这些块的原始未压缩 token 并在其上运行注意力。

### 第 4 步：滑动窗口注意力

取最后 `w` 个 token 并在其上运行标准注意力。

### 第 5 步：门控 + 组合

查询上的小型 MLP 产出三个门控权重。最终输出是三个分支输出的加权和。

### 第 6 步：计算量统计

打印每个分支每查询关注的键数和总计。与 `N`（全量注意力）比较。在 1024 token 合成序列上，`l = 32, k = 4, w = 128`，NSA 每查询看到 `32 + 128 + 128 = 288` 个键，全量注意力为 1024——减少 3.5 倍。

## 使用它

NSA 在 DeepSeek 自己的长上下文预训练流水线中发布。截至 2026 年 4 月公开推理栈的集成状态：

- **DeepSeek 内部**：原生，发布的权重使用 NSA 或其后继 DSA（Deepseek Sparse Attention）。
- **vLLM**：针对 DeepSeek-V3.x 权重的实验性 NSA 支持正在开发中。
- **SGLang**：NSA 基准测试已发布；生产路径跟随 vLLM。
- **llama.cpp / CPU**：不支持；kernel 分解的开销在 CPU 吞吐下不值得。

何时使用 NSA：

- 预训练或继续训练运行，目标 64k 以上上下文，有充足的计算预算。
- 推理 DeepSeek 自己的长上下文检查点。权重是 NSA 原生的。

何时不用：

- 服务现有的稠密注意力预训练模型。没有继续训练就无法改装 NSA。
- 上下文低于 16k。三分支开销主导了节省。
- Batch-1 交互式聊天。延迟敏感的解码有收益，但只在长上下文时。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| 压缩分支 | "粗粒度视图" | 在块平均键上的注意力，以每查询 O(N/l) 个键提供全局上下文 |
| 选择分支 | "top-k 块" | 在具有最高压缩分支分数的 `k` 个块上的细粒度注意力 |
| 滑动窗口 | "局部上下文" | 最后 `W` 个 token 上的注意力，用于短程模式 |
| 原生可训练性 | "带着稀疏性预训练" | 稀疏模式在预训练期间学习，而非推理时嫁接 |
| 压缩块大小 l | "粗粒度视图的组大小" | 多少 token 合并为一个摘要；典型值 32-64 |
| Top-k | "保留的块数" | 其未压缩 token 被读取的压缩块数量；典型值 16 |
| 滑动窗口 W | "局部注意力半径" | 典型值 512；更短损害局部连贯性，更长浪费计算 |
| 分支门控 | "如何混合三者" | 逐位置 MLP 输出，加权三个分支的贡献 |
| 硬件对齐 | "kernel 友好的稀疏性" | 稀疏模式的选择使实际 GPU kernel 能实现理论加速 |
| DSA | "NSA 的后继" | Deepseek Sparse Attention，DeepSeek 谱系中紧随 NSA 的架构 |

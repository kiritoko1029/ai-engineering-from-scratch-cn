## 问题所在

70B 模型上的自回归解码在 H100 上大约跑 35 token 每秒。GPU 远未饱和。内存带宽是天花板：每个 token 从 HBM 加载 70B 权重，做一步运算，产出一个浮点数。计算单元大部分时间在空转。

推测解码将此转化为一个你真正能解决的吞吐问题。一个廉价的草稿模型在 N 次小型前向传播中提出 N 个 token。验证器在前缀加上所有 N 个草稿上运行一次。如果验证器在位置 i 的分布与草稿一致（我们将精确定义统计意义上的一致），就接受；如果不一致，就拒绝并从残差分布中采样修正。一次大模型前向传播可以产出最多 N+1 个被接受的 token，而不是一个。

关键定理是 Leviathan、Kalman、Matias（ICML 2023）：输出分布与直接从验证器采样完全相同。不是近似，是完全相同。这就是推测解码能在生产中使用的全部原因——它是纯粹的延迟优化，没有质量权衡。

第 7 阶段 · 第 16 课给你的数学。本课程给你的是训练栈。一个好的草稿比廉价草稿多带来 2 倍加速。EAGLE、EAGLE-2 和 EAGLE-3（Li 等，2024-2025）将"草稿 = 同一模型的更小版本"变成了精确的工程学科。2026 年的生产推理服务器默认使用 EAGLE-3。

## 概念说明

### 不变量：Leviathan 拒绝采样

令 `p(t)` 为草稿在给定前缀下的下一个 token 分布，`q(t)` 为验证器的分布。采样草稿 token `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受。拒绝时，从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。结果样本服从 `q` 分布。无论 `p` 多差这都成立——越差拒绝越多，但输出始终精确。

使用一次验证器前向传播对 `prefix + d_1 + ... + d_N` 的输入，将 N 次这样的调用堆叠在一起。验证器同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历。在位置 j 首次拒绝时，从 `residual(q_j, p_j)` 中采样并停止。全部接受时，从 `q_{N+1}` 中采样一个额外 token。

### 决定加速的因素

令 `α` 为每个草稿 token 的预期接受率。令 `c = cost(draft) / cost(verifier)` 为成本比。每次验证器前向传播的预期接受 token 数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个被接受 token 的预期总时钟时间为 `(N * c + 1) / E[accepted]`。对 N 最小化就能得到甜蜜点。对于 `α = 0.8, c = 0.05`：最优 N 约 5-7，加速 3.2 倍。对于 `α = 0.95, c = 0.02`：最优 N 约 8-10，加速可达 5 倍。

最大的杠杆是 `α`。在固定 N = 5 的情况下，从 `α = 0.6`（原始草稿）提升到 `α = 0.9`（EAGLE-3），每次验证器前向传播的预期接受 token 数从 2.2 增加到 4.1。相同的验证器带来近 2 倍的吞吐提升。

### 两年演进历程

**原始推测解码（Leviathan，2023）。** 草稿模型是同一家族中独立训练的更小 LLM。易于接入，`α ≈ 0.6`，最好情况约 2 倍加速。

**EAGLE-1（Li 等，2024）。** 草稿是一个小型 Transformer——通常一到两层——接收验证器最后一层的隐藏状态作为输入，直接预测下一个 token。由于草稿能看到验证器的特征表示，其分布更接近验证器。`α` 提升到 0.7-0.8。

**EAGLE-2（Li 等，2024）。** 添加动态草稿树：不是提出 N 个 token 的单一序列，而是提出一个小的候选树，用验证器在一次前向传播中为每个分支打分（树注意力），然后走最高概率路径。草稿长度变为每步自适应。每接受路径 token 的 `α` 攀升至 0.85 以上。

**EAGLE-3（Li 等，2025，NeurIPS）。** 又做了两个改变。首先，完全去掉特征预测损失——EAGLE-1/2 训练草稿来匹配验证器的隐藏状态，这限制了数据能带来多少帮助。EAGLE-3 直接在 token 预测上训练。其次，训练时测试（TTT）：在草稿训练期间，将草稿自身的先前预测作为输入反馈回去，就像它在推理时运行一样。这对齐了训练和测试分布，阻止了误差累积。实测加速：聊天场景最高 6.5 倍，H100 上 SGLang batch 64 时吞吐提升 38%。

### KV 缓存回滚

验证在一次传播中将验证器的 KV 缓存扩展了 N 个条目。如果在位置 j 发生拒绝，位置 j-1 之后的缓存内容就是错误的。两种常见实现：写入临时缓冲区，接受后提交（vLLM、TensorRT-LLM）；或保留物理 KV 缓存加逻辑长度，拒绝时截断。无论哪种方式，回滚成本都是每层每头的字节数，与前向传播成本相比可以忽略不计。

对于 EAGLE-2 树搜索，验证器使用尊重树拓扑的非因果掩码进行注意力计算。工程实现比较繁琐，但计算是带自定义掩码的标准 flash-attention 调用。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速 | 训练成本 |
|------|---------|-----|------|---------|
| 原始 | 独立的小 LLM | 0.55-0.70 | 1.8-2.3 倍 | 无（复用现有小模型） |
| Medusa | 验证器上的额外 LM 头 | 0.65-0.75 | 2-3 倍 | 约 1B SFT token |
| EAGLE-1 | 隐藏状态上的 1 层 Transformer | 0.70-0.80 | 2.5-3 倍 | 约 60B token |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80-0.88 | 3-4 倍 | 约 60B token |
| EAGLE-3 | 多层特征融合 + TTT | 0.88-0.92 | 3.5-6.5 倍 | 约 60-200B token |
| 前瞻解码 | 无草稿（Jacobi 迭代） | 不适用 | 1.3-1.6 倍 | 无 |

2026 年生产环境：vLLM 和 SGLang 在可用时默认使用 EAGLE-3，否则使用 EAGLE-2。TensorRT-LLM 对 Meta 和 NVIDIA 公开模型有最快的 Medusa 路径。llama.cpp 为 CPU 部署提供原始草稿。

## 开始构建

见 `code/main.py`。这是完整的 Leviathan 推测循环，包含所有组件：N 长草稿、验证器并行传播、逐位置拒绝、残差采样、额外 token、KV 回滚，以及输出分布与直接从 `q` 采样一致的实证验证。

### 第 1 步：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 第 2 步：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 第 3 步：完整的推测步骤

`spec_step` 函数从 `p` 草拟 N 个 token，然后在一次并行 `q` 评估中验证所有 token。对每个草拟的 token 应用拒绝规则，在首次拒绝时从残差中采样修正。如果全部接受，则从 `q_{N+1}` 输出一个额外 token。

### 第 4 步：KV 回滚记账

模拟器为每个 worker 跟踪逻辑 `kv_length`。接受 k 个草稿时，`kv_length += k`。在位置 j 拒绝时，缓存已经写过 j，但逻辑长度被设置为 `prefix_length + j + 1`——修正 token 之后的一个位置。后续读取截断到逻辑长度。

### 第 5 步：Leviathan 检查

运行 50,000 次推测步骤。统计接受 token 的经验分布。与 50,000 次从 `q` 直接采样比较。卡方统计量应远低于临界值。定理在实践中成立。

### 第 6 步：加速与 α 的关系

通过以不同幅度扰动 `p` 远离 `q` 来扫描草稿质量。度量 `α`，然后绘制每次验证器调用的预期 token 数作为 `α` 和 `N` 的函数。代码打印一个表格，展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何解锁每次验证器调用 4-5 个 token。

## 使用它

生产级别的 `vllm serve` 配合 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

SGLang 配合 EAGLE-3 在 H100 上 batch 64：根据 EAGLE-3 论文，比 batch 64 的原始解码大约多 1.38 倍吞吐。

何时使用推测解码：

- 任何交互式聊天场景，其中 p50 延迟比峰值吞吐更重要。
- 代码生成和结构化输出（JSON、SQL）。`α` 超过 0.9，因为目标分布高度可预测。
- 长文本生成（数千 token）。摊销加速持续有效。

何时不用：

- 非常小的模型（< 3B）。草稿并不比验证器便宜多少。
- 极小的 batch-1 CPU 部署。草稿模型的内存开销可能不值得。
- 非常高的温度创意采样，`α` 会崩溃。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| Leviathan 规则 | "min(1, q 除以 p)" | 以概率 `min(1, q(d)/p(d))` 的伯努利接受/拒绝，拒绝时从残差采样精确保持验证器分布 |
| 残差分布 | "(q 减 p) 取正，归一化" | `(q - p)_+` 截断为零后重新归一化——拒绝时正确的采样分布 |
| 接受率 α | "草稿正确的频率" | 拒绝规则下每 token 的伯努利成功概率；决定所有加速计算 |
| EAGLE-1 | "隐藏状态草稿" | 以验证器最后一层隐藏状态为条件的小型 Transformer 草稿（Li 等，2024） |
| EAGLE-2 | "动态草稿树" | EAGLE-1 加候选延续的树，用树注意力在一次验证器传播中打分 |
| EAGLE-3 | "训练时测试" | 去掉特征预测损失，直接在 token 预测上训练，训练时给草稿喂入自己的输出 |
| 训练时测试（TTT） | "曝光偏差修复" | 在训练期间自回归地运行草稿，使训练和测试输入分布匹配——计划采样的直接类似 |
| KV 回滚 | "撤销被拒绝的草稿" | 在拒绝后将验证器的 KV 缓存重置为已接受前缀长度的记账操作 |
| 额外 token | "免费的那个" | 当所有 N 个草稿被接受时，从 `q_{N+1}` 额外采样一个，无需额外验证器成本 |
| 树注意力 | "一次验证多个候选" | 使用尊重草稿树拓扑的非因果掩码的注意力；在一次前向传播中计算树中每个节点的 `q_i` |

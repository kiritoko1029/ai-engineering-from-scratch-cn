# 评估与协调基准测试

> 五项 2025-2026 基准测试覆盖了多智能体评估领域。**MultiAgentBench / MARBLE**（ACL 2025，arXiv:2503.01935）评估星型/链型/树型/图型拓扑，使用里程碑 KPI；**图型最适合研究场景**，认知规划增加约 3% 的里程碑达成率。**COMMA** 评估多模态非对称信息协调；包括 GPT-4o 在内的最先进模型在该基准上难以超越随机基线。**MedAgentBoard**（arXiv:2505.12371）覆盖四个医疗任务类别，经常发现多智能体并不优于单 LLM。**AgentArch**（arXiv:2509.10769）对结合工具使用 + 记忆 + 编排的企业智能体架构进行基准测试。**SWE-bench Pro**（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）包含 41 个代码库的 1865 个问题，涵盖商业应用、B2B 服务和开发者工具；前沿模型在 Pro 上得分约 23%，在 Verified 上得分 70%+——这是对数据污染的现实检验。Claude Opus 4.7（2026 年 4 月）在 Pro 上使用显式智能体团队协调达到 **64.3%**（尚无 Anthropic 主要来源发表——视为初步数据）；Verdent（智能体脚手架）在 Verified 上达到 **76.1% pass@1**（[Verdent 技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026 Bridge Program WMAC**（https://multiagents.org/2026/）是 2026 年社区焦点。本课基于 MARBLE 的指标构建，运行拓扑与指标的扫描，并确立"仅仅通过 SWE-bench Verified 不是泛化能力的证据"这一规则。

**类型：** 学习
**语言：** Python（标准库）
**前置要求：** Phase 16 · 15（投票与辩论拓扑）、Phase 16 · 23（失效模式）
**所需时间：** 约 75 分钟

## 问题

当一篇论文声称"我们的多智能体系统更好"时，问题是：比什么好，在什么上好，如何衡量？2023-2024 年的多智能体评估时代是一片混乱——每个人都选择自己的指标、自己的基线和自己的任务集。2025-2026 年的基准测试带来了结构。

没有共享基准，你就无法有意义地比较两个多智能体系统。更糟的是，没有留出基准测试，前沿模型就会受到数据污染。SWE-bench Verified 到 2025 年中期在训练语料库中部分被污染；前沿分数虚高；Pro 被设计为未受污染的现实检验。

本课列举了五项 2026 年标准基准测试，说明每项衡量什么，并教你以批判性眼光阅读基准测试声明。

## 概念

### MultiAgentBench（MARBLE）——ACL 2025

arXiv:2503.01935。评估四种协调拓扑（星型、链型、树型、图型）在研究、编码和规划任务上的表现。基于里程碑的 KPI 跟踪部分进展，而非仅关注最终成功。

测量结果：

- **图型**拓扑最适合研究场景；支持任意对任意的批评。
- **链型**最适合逐步精炼的编码。
- **星型**最适合快速事实整合。
- **协调税**在图型上超过约 4 个智能体时出现。
- **认知规划**在各拓扑上增加约 3% 的里程碑达成率。

适用场景：你想公平地比较协调拓扑。MARBLE 仓库（https://github.com/ulab-uiuc/MARBLE）提供了评估器。

### COMMA——多模态非对称信息

覆盖智能体具有不同观测模态且必须在不完全共享信息的情况下进行协调的任务。报告的结果令人不安：包括 GPT-4o 在内的前沿模型在 COMMA 的智能体间协作上难以超越**随机基线**。信号是多模态协调能力训练不足且评估不足——LLM 在单模态合作上表现尚可；多模态协调则崩溃。

适用场景：你的系统具有多模态或非对称信息协调。COMMA 的空结果是一个警示：先测量再宣称。

### MedAgentBoard——领域压力测试

arXiv:2505.12371。四个医疗任务类别：诊断、治疗计划、报告生成、患者沟通。比较多智能体 vs 单 LLM vs 传统基于规则的系统。

发现：多智能体在大多数类别上并不优于单 LLM。多智能体的优势很窄——当子任务可清晰分离时（诊断 + 治疗），任务分解有帮助；当协调开销超过专业化收益时（报告生成），反而有害。

适用场景：你的领域有明确的单 LLM 基线。如果 MedAgentBoard 的结论具有普遍性，许多提出的多智能体系统都是过度工程化的。

### AgentArch——企业架构

arXiv:2509.10769。企业场景中工具使用、记忆和编排分层叠加。基准测试隔离了每一层的贡献：添加工具能提升多少？添加记忆呢？添加多智能体编排呢？

适用场景：你正在设计企业智能体技术栈，需要为每一层的价值提供依据。AgentArch 帮助你避免购买无法衡量价值的功能。

### SWE-bench Pro——现实检验

arXiv:2509.16941。41 个代码库的 1865 个问题，涵盖商业应用、B2B 服务和开发者工具。设计为**未受污染**，晚于后续训练截止日期。前沿模型在 Pro 上得分约 23%，在 Verified 上得分 70%+。差距就是污染信号。

2026 年 4 月得分：
- Claude Opus 4.7 在 Pro 上：**64.3%**（使用显式智能体团队协调报告；尚无 Anthropic 主要来源发表——视为初步数据）。
- Verdent（智能体脚手架）在 Verified 上：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。
- 前沿模型在 Pro 上不使用智能体脚手架的原始得分：约 23-35%（[SWE-bench Pro 论文](https://arxiv.org/abs/2509.16941)）。

关键结论："我们击败了 SWE-bench Verified"不再是能力的证据。Pro 是当前的门槛测试。智能体团队脚手架在 Pro 上产生了可衡量的提升（约 30-40 分差距），这是 2026 年多智能体协调最有力的实证论据之一。

### AAAI 2026 WMAC

AAAI 2026 Bridge Program——多智能体协调研讨会（https://multiagents.org/2026/）。2026 年多智能体 AI 研究的社区焦点。已接收论文和研讨会论文集是评估新方法的标准渠道；在生产决策中，优先参考 WMAC 接收的声明而非 arXiv 预印本。

### 批判性阅读基准测试声明——2026 年检查清单

当有人声称多智能体结果时：

1. **哪个基准，哪个划分？** SWE-bench Verified vs Pro 差别很大。在错误划分上报告的数字毫无价值。
2. **污染检查。** 基准测试是在模型训练截止日期之后发布的吗？如果不是，谨慎对待。
3. **基线比较。** vs 单 LLM 基线、vs 随机、vs 之前的多智能体工作。不是"vs 同一系统的未调优版本"。
4. **统计显著性。** N 次试验、p 值、置信区间。前沿模型方差大；单次运行具有误导性。
5. **任务多样性。** 一个任务还是多个？泛化能力对生产很重要。
6. **成本披露。** 每任务 token 数、墙钟时间。一个 90% 准确率的方案如果成本是 20 倍，那是商业决策，不是能力声明。

### 基准测试未能很好衡量的方面

- **长周期协调。** 数天的墙钟交互。当前所有基准测试运行时间都很短。
- **对抗性韧性。** 当一个智能体是恶意的或被入侵时会怎样？
- **部署下的漂移。** 基准测试是静态的；生产分布会变化。
- **成本归一化性能。** 大多数基准测试报告原始准确率，而非每美元准确率。

为你真正关心的维度构建内部基准测试通常是正确的做法。

## 开始构建

`code/main.py` 是一个非交互式演示：

- 在玩具任务上模拟 3 个多智能体系统。
- 为每个系统计算 MARBLE 风格的里程碑指标。
- 通过从"训练"集中保留任务来运行污染检查。
- 与随机基线进行显式比较。
- 打印基准测试声明记分卡。

运行：

```bash
python3 code/main.py
```

预期输出：系统记分卡，包含原始准确率、里程碑达成率、每任务成本、与随机基线的差距，以及污染检查说明。

## 实际应用

`outputs/skill-benchmark-reader.md` 阅读任何多智能体基准测试声明并应用审查检查清单。输出：评级和注意事项。

## 投入生产

生产评估纪律：

- **构建内部基准测试**，反映你实际的生产分布。公共基准测试有参考价值但不能替代。
- **每次比较都包含随机基线。** 如果你在协调任务上不能大幅超越随机，任务可能定义不当。
- **同时报告成本和准确率。** Token 成本和墙钟时间。运维团队两者都需要。
- **每季度重建基准测试。** 生产分布会变化；过时的基准测试具有误导性。
- **避免过拟合已发布的基准测试。** 如果你的团队专门针对 SWE-bench Pro 数字进行优化，你将在生产上退步。

## 练习

1. 运行 `code/main.py`。找出三个模拟系统中哪个具有最佳的每里程碑成本。它与最高原始准确率的系统匹配吗？
2. 阅读 MultiAgentBench（arXiv:2503.01935）。对于你自己的任务领域，决定 MARBLE 会推荐四种拓扑中的哪一种。根据论文结果进行论证。
3. 阅读 SWE-bench Pro 论文。具体是什么使它具有抗污染性？同样的技术能否应用到你关心的其他基准测试？
4. 阅读 COMMA 关于多模态协调的发现。设计一个你可以添加到内部基准测试的简单多模态协调任务。什么算作有用的信号？
5. 将基准测试声明检查清单应用于一篇近期多智能体论文的头条结果。你会给这个声明什么评级？

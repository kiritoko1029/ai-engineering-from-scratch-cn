# 多智能体强化学习 — MADDPG，QMIX，MAPPO

> 多智能体协调的强化学习传承，在2026年仍然影响着大语言模型智能体系统。**MADDPG**（Lowe等人，NeurIPS 2017，arXiv:1706.02275）引入了集中训练、分散执行（CTDE）：每个评论家在训练时可以看到所有智能体的状态和行动；测试时仅运行本地执行者。适用于合作、竞争和混合场景。**QMIX**（Rashid等人，ICML 2018，arXiv:1803.11485）是带有单调混合网络的价值分解；每智能体Q值组合为联合Q值，使得`argmax`可以干净地分散执行——在星际争霸多智能体挑战（SMAC）上占主导地位。**MAPPO**（Yu等人，NeurIPS 2022，arXiv:2103.01955）是带有集中价值函数的PPO；在粒子世界、SMAC、谷歌研究足球、Hanabi上以最少的调优实现"出人意料的有效性"。这些算法支撑着必须分散执行的智能体团队的训练策略。MAPPO是**2026年合作多智能体强化学习的默认基线**。本课从一个小型网格世界玩具出发，逐一构建这些算法，在接触大语言模型智能体训练之前将这三种模式内化为肌肉记忆。

**类型：** 学习
**语言：** Python（标准库，无NumPy的小型实现）
**前置要求：** Phase 09（强化学习），Phase 16 · 09（并行群体网络）

## 问题

大语言模型智能体系统越来越多地训练用于智能体间协调的策略：何时让步、何时行动、调用哪个同伴。告诉你如何训练此类策略的文献是多智能体强化学习（MARL），它早于大语言模型浪潮，拥有一小批主导算法。

不掌握模式词汇就阅读多智能体强化学习论文是痛苦的。集中训练与分散执行（CTDE）、价值分解和集中评论家不是流行词——它们是对特定问题的具体回答：

- 独立强化学习（每个智能体单独学习）从每个智能体的角度来看是非平稳的。很糟糕。
- 集中强化学习（一个智能体控制所有）无法扩展且违反执行约束。
- CTDE兼得两者优势：用全局信息训练，用本地策略部署。

## 概念

### 论文使用的三个环境

- **粒子世界（多智能体粒子环境）。** 简单的2D物理，包含合作/竞争任务。MADDPG的原始测试平台。
- **星际争霸多智能体挑战（SMAC）。** 合作微操，部分可观察。QMIX的测试平台。离散动作，连续状态。
- **谷歌研究足球、Hanabi、MPE。** MAPPO的基线。

不同环境有不同的动作/观察类型。算法据此选择。

### MADDPG（2017）— CTDE模式

每个智能体`i`有一个执行者`mu_i(o_i)`，将自身观察映射到动作。每个智能体还有一个评论家`Q_i(x, a_1, ..., a_n)`，在训练时可以看到所有观察和所有动作。执行者通过策略梯度根据评论家的评估进行更新。

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

为什么使用CTDE：在训练时，我们知道所有人的行动；我们利用这一点来减少每个评论家的方差。部署时，每个智能体只能看到`o_i`并调用`mu_i(o_i)`。

失败模式：评论家随N个智能体增长（输入包括所有动作）。没有近似的情况下无法扩展到约10个智能体以上。

### QMIX（2018）— 价值分解

仅适用于合作场景。全局奖励是每智能体Q值的单调函数之和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证了`argmax_a Q_tot`可以通过每个智能体独立选择`argmax_{a_i} Q_i`来计算。这正是你所需要的**分散执行特性**。在训练时，混合网络从每智能体Q值产生`Q_tot`。

为什么QMIX在SMAC上获胜：合作星际争霸微操具有同构智能体、局部观察、全局奖励——完美适合价值分解。

失败模式：单调性约束是限制性的；某些任务的奖励结构不是单调可分解的（一个智能体为团队牺牲）。扩展（QTRAN，QPLEX）放宽了这一约束。

### MAPPO（2022）— 被忽视的默认方案

多智能体PPO：带有集中价值函数的PPO。每个智能体有自己的策略；所有智能体共享（或拥有每智能体的）价值函数，可以看到完整状态。Yu等人2022年在五个基准上将MAPPO与MADDPG及其扩展进行了比较，发现：

- MAPPO在粒子世界、SMAC、谷歌研究足球、Hanabi、MPE上匹配或超越离策略多智能体强化学习方法。
- 最少的超参数调优。
- 训练稳定；跨种子可复现。

在MAPPO之前，社区低估了在策略多智能体强化学习。2026年，MAPPO是合作多智能体强化学习的默认基线；任何新方法都必须超越它。

### 为什么大语言模型智能体工程师应该关注

三个直接用途：

1. **路由器训练。** 元智能体选择哪个子智能体处理任务。这是一个多智能体强化学习问题，有N个分散的子智能体和一个集中路由器。MAPPO很适合。
2. **角色涌现。** 在生成式智能体模拟中，训练智能体随时间采用互补角色是一个伪装的多智能体强化学习问题。QMIX风格的价值分解通过构造强制互补性。
3. **多智能体工具使用。** 当智能体共享工具并竞争预算时，通过CTDE训练它们会产生可部署的本地策略，这些策略遵守资源约束。

实际注意事项：在2026年，大多数生产环境的大语言模型智能体系统通过提示而非训练来生成策略。多智能体强化学习适用于当你有（a）大量交互数据、（b）清晰的奖励信号、（c）愿意投资训练基础设施时。

### CTDE作为超越强化学习的设计模式

即使不进行训练，CTDE也是一个有用的架构模式：

- 在*设计*阶段，假设团队完全可见。
- 在*运行时*，强制分散执行：每个智能体只能看到`o_i`。

该模式迫使你保持每智能体状态的显式化，并提前考虑部分可观察性。许多生产环境多智能体系统隐式假设到处共享状态——CTDE纪律可以防止这种情况。

### 非平稳性问题

当多个智能体同时学习时，每个智能体的环境（包括其他智能体的策略）是非平稳的。经典单智能体强化学习的证明不再成立。本课中的多智能体强化学习算法都解决了这个问题：

- MADDPG：全局评论家看到所有行动，因此其价值估计是平稳的。
- QMIX：价值分解将学习转移到联合Q空间，其中最优性是良好定义的。
- MAPPO：集中价值函数抑制了其他智能体策略变化带来的方差。

在大语言模型智能体系统中，非平稳性表现为"我的智能体上个月还正常工作，现在上游那个智能体变了，我的就出问题了。"用CTDE训练多智能体强化学习是原则性的修复；提示级修复更快但不够持久。

### 本课不涵盖的内容

训练实际网络是Phase 09的主题。本课构建脚本化策略版本，展示CTDE、价值分解和集中价值模式，无需梯度更新。目标是在你使用完整的多智能体强化学习库（PyMARL、MARLlib、RLlib multi-agent）之前内化这些模式。

## 开始构建

`code/main.py` 实现了三个模式演示，全部在2个智能体的合作小型网格世界上：

- 环境：2个智能体在4×4网格上，一个奖励颗粒。如果任何智能体到达颗粒，奖励 = 1；任务完成。
- `IndependentAgents` — 每个智能体将其他智能体视为环境。基线。
- `MADDPGStyle` — 集中评论家计算联合价值；执行者策略据此更新。脚本化的策略改进。
- `QMIXStyle` — 带有单调混合器的价值分解。
- `MAPPOStyle` — 集中价值函数；策略根据共享基线更新。

四种方法运行相同的回合并报告平均到达目标步数。CTDE变体比独立基线收敛到更短的路径。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均约6步；CTDE变体收敛到约3.5步（4×4网格的最优解是3）。模式差异在脚本化策略下仍然可见。

## 投入生产

多智能体强化学习在生产中很少见。当你确实使用时：

- **从MAPPO开始。** 2022年的论文将其确立为基线；先复现它可以节省数周追逐更花哨方法的时间。
- **记录每个智能体的观察和行动流。** 没有每智能体的追踪记录，调试多智能体强化学习毫无希望。
- **将训练代码与执行代码分离。** CTDE是一种纪律；让执行路径真的只能看到`o_i`。
- **奖励塑形警告。** 多智能体强化学习对奖励设计极为敏感。塑形中的一个协调缺陷就会让智能体学会利用它。运行对抗性测试。
- **对于大语言模型智能体**，优先考虑提示级策略。只有在交互数据 + 奖励信号 + 基础设施都具备时，才投资多智能体强化学习训练。

## 练习

1. 运行`code/main.py`。测量独立智能体与MAPPO风格智能体之间的到达目标步数差距。在6×6网格上，差距是增大还是缩小？
2. 实现一个竞争变体：两个智能体，一个颗粒，只有先到达的获得奖励。哪种模式能干净地处理竞争？MADDPG在历史上表现最佳。
3. 阅读MADDPG（arXiv:1706.02275）第3节。用自己的话在伪代码中符号化地实现确切的评论家更新规则。
4. 阅读MAPPO（arXiv:2103.01955）。为什么作者认为集中价值 + PPO在他们的基准上击败了离策略多智能体强化学习？列出三个最有力的论点。
5. 将CTDE作为设计模式应用于假设的大语言模型智能体系统（例如，研究智能体 + 摘要智能体 + 编码智能体）。设计时可用的联合信息中，哪些在运行时不可用？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------------|------------------------|
| MARL | "多智能体强化学习" | 多智能体系统的强化学习。 |
| CTDE | "集中训练，分散执行" | 用全局信息训练；用本地策略部署。 |
| MADDPG | "多智能体DDPG" | 带有能看到所有观察+动作的每智能体评论家的CTDE。 |
| QMIX | "价值分解" | 每智能体Q值的单调混合。合作场景。 |
| MAPPO | "多智能体PPO" | 带有集中价值函数的PPO。2026年默认基线。 |
| 价值分解 | "个体Q值之和" | 联合Q值表示为每智能体Q值的单调函数。 |
| 非平稳性 | "移动的目标" | 每个智能体的环境随其他智能体学习而改变。多智能体强化学习的核心问题。 |
| 在策略 / 离策略 | "从当前 / 回放中学习" | PPO是在策略的（MAPPO）；DDPG和Q-learning是离策略的。 |
| SMAC | "星际争霸多智能体挑战" | 合作微操基准；QMIX的发源地。 |

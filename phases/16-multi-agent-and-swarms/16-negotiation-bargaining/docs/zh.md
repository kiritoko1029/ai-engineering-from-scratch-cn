# 协商与议价

> 智能体之间就资源、价格、任务分配和条款进行协商。2026年的基准测试集已经给出了明确结论：NegotiationArena（arXiv:2402.05863）表明大语言模型可以通过人格操控（"表现急迫"）将收益提升约20%；"Measuring Bargaining Abilities"（arXiv:2402.15813）表明买方比卖方更难胜任，且模型规模并不能解决问题——其**OG-Narrator**（确定性报价生成器 + 大语言模型叙述者）将成交率从26.67%提升至88.88%；大规模自主协商竞赛（arXiv:2503.06416）运行了约18万次协商，发现**隐藏思维链**的智能体通过向对手隐藏推理过程而获胜；Bhattacharya等人2025年基于哈佛谈判项目的指标评估显示，Llama-3最有效，Claude-3最具攻击性，GPT-4最公平。本课实现了合同网协议（FIPA的前身，第02课），接入大语言模型风格的买方/卖方，运行OG-Narrator风格的分解，并衡量每种结构选择如何影响成交率。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置要求：** Phase 16 · 02（FIPA-ACL遗产），Phase 16 · 09（并行群体网络）
**所需时间：** 约75分钟

## 问题

两个智能体需要就价格达成一致。如果仅凭纯语言提示让它们自行协商，2024-2026年的大语言模型在严格参数化的议价场景中成交率出人意料地低（约27%，参见arXiv:2402.15813）。模型规模无法解决这个问题：GPT-4在议价能力上并不比GPT-3.5更具结构性优势；它只是在议价的*语言表达*上更出色。

根本问题在于大语言模型混淆了两项任务——决定报价和叙述报价。OG-Narrator将两者分离：一个确定性报价生成器计算数值变动；大语言模型只负责叙述。成交率跃升至约89%。

这印证了一个经典的多智能体发现：将机制层与通信层解耦是制胜之道。合同网协议（FIPA，1996；Smith，1980）是参考性的任务市场机制。将大语言模型接入叙述环节，你就得到了一个现代化的大语言模型驱动的任务市场。

## 概念

### 合同网协议，一段话概括

Smith 1980年的合同网协议：一个**管理者**广播**招标公告（cfp）**；**竞标者**回复包含报价的**提案**消息；管理者选择中标者，向中标者发送**接受提案**，向落选者发送**拒绝提案**。中标者执行工作。可选消息：**拒绝**（竞标者拒绝提出提案）。FIPA将其规范化为`fipa-contract-net`交互协议。

### 为什么OG-Narrator更胜一筹

"Measuring Bargaining Abilities of Language Models"（arXiv:2402.15813）观察到：

- 大语言模型经常违反议价规则（以荒谬的价格报价，忽略对方的ZOPA）。
- 它们的锚定能力差（接受不利的首次报价；反报价是象征性的而非策略性的）。
- 模型规模本身无法解决这些问题。更大的模型产生更合理的语言表达，但策略性错误相似。

OG-Narrator的分解方式：

```
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ offer generator  │ price → │  LLM narrator    │ → message
           │  (deterministic) │        │  (writes the     │
           │                  │        │   human-style    │
           └──────────────────┘        │   accompaniment) │
                                       └──────────────────┘
```

报价生成器是经典的协商策略：鲁宾斯坦议价模型、泽森策略，或简单的以牙还牙价格策略。大语言模型负责叙述。消息包含确定性价格和自然语言框架。

成交率之所以跃升，原因在于：
- 价格始终保持在议价区间内。
- 锚定是策略性的，而非情绪性的。
- 大语言模型做它擅长的事：写作。

### NegotiationArena的发现

arXiv:2402.05863提供了权威基准。主要发现：

- 大语言模型采用人格设定（"我急需在周五前卖掉这个"）可以将收益提升约20%——人格操控是一种真实的策略。
- 公平/合作型智能体会被对抗性智能体利用；防御需要明确的反制姿态。
- 在约40%的基准场景中，对称配对会收敛到不公平的结果。

这并不意味着"大语言模型不擅长谈判"。而是"大语言模型太像人类了，包括那些可被利用的部分"。

### 思维链隐藏

大规模自主协商竞赛（arXiv:2503.06416）在多种大语言模型策略上运行了约18万次协商。获胜者向对手隐藏了自己的推理过程：

- 如果智能体在公开可见的草稿纸上写出"我只会出到75美元；我的保留价格是70美元"，对手就能看到。
- 获胜者在私密状态下计算策略；输出渠道仅包含报价和最低限度的必要叙述。

这是经典博弈论（Aumann 1976关于理性与信息）在2026年的回响：暴露你的私人估值会损失收益。大语言模型不会直觉感知这一点，它们会愉快地在推理轨迹中输入自己的保留价格，而这些信息对手可以看到。

工程要点：将私密草稿纸上下文与公开消息上下文分开。这不是可选的。

### Bhattacharya等人2025 — 模型排名

基于哈佛谈判项目的指标（原则性谈判、BATNA尊重、利益互惠）：

- **Llama-3** 在达成交易方面最有效（成交率 + 收益）。
- **Claude-3** 是最具攻击性的谈判者（高锚定、迟让步）。
- **GPT-4** 是最公平的（不同配对中收益方差最小）。

这是2025年的快照。重点不是2026年4月哪个模型获胜——而是不同的基础模型具有持久的协商风格。异构集成（第15课）将其作为多样性来源。

### 通过合同网协议 + 大语言模型进行任务分配

合同网协议在大语言模型多智能体中的现代复用：

1. 管理者智能体将任务分解为若干单元。
2. 向工作者智能体广播带有任务描述的`cfp`。
3. 每个工作者返回一个报价：`(price, eta, confidence)`，其中price可以是token、计算单元或美元。
4. 管理者选择中标者（单个或多个，取决于任务）并授标。
5. 落选的工作者可以自由竞标其他任务。

这种模式在超过100个工作者时仍然表现良好，因为协调是广播-响应式的，而非同步对话。已在生产中使用：微软智能体框架的编排模式，部分LangGraph实现。

### 大语言模型利益相关者交互式协商

NeurIPS 2024 (https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf) 引入了多方可评分博弈，具有**隐秘评分**和**最低接受阈值**。每个利益相关者拥有私有效用；大语言模型必须从消息中推断这些效用。这是将双方议价推广到N方联盟形成。对于具有异构工作者能力的生产任务市场具有参考价值。

### 叙述与机制的规则

在所有2024-2026年的协商基准中，一致的工程规则是：

> 让大语言模型叙述。不要让大语言模型计算报价。

如果报价需要是一个数字（价格、预计时间、数量），则从协商状态确定性地生成它，让大语言模型负责框架表述。如果报价需要是一个提案结构（任务分解、角色分配），则让大语言模型起草，但在发送前根据模式进行验证和约束检查。

## 开始构建

`code/main.py` 实现了：

- `ContractNetManager`、`ContractNetTask`、`Bid` — 管理者 + 竞标者，广播cfp，收集提案，授标。
- `og_narrator_bargain(state, rng)` — OG-Narrator买方：确定性泽森式向中点让步。
- `seller_response(state, rng)` — 确定性卖方反报价策略（两种风格的结构性真实基准）。
- `naive_llm_bargain(state, rng)` — 模拟纯大语言模型议价者：以高方差选择价格，经常超出ZOPA。
- 测量：在1000次试验中，每次试验采样新的保留价格，统计成交率。

运行：

```
python3 code/main.py
```

预期输出：朴素大语言模型成交率约65-75%；OG-Narrator成交率约85-95%；15-25个百分点的差距体现了将报价生成与叙述分离的结构性优势。另外还有一个合同网协议任务市场分配示例，包含三个竞标者和一个任务。

## 投入生产

生产环境议价清单：

- **分离草稿纸。** 私有状态绝不能出现在对手的上下文中。这是不可谈判的。
- **确定性报价生成。** 价格、数量、预计时间：计算得出，而非提示生成。
- **验证所有传入报价** 是否符合模式。在协议边界拒绝超出ZOPA的报价。
- **限制轮次。** 最多3-5轮；僵局时升级到调解人。
- **持续测量成交率和收益方差。** 成交率下降是一个症状——通常是提示漂移或对手端攻击。
- **记录所有被拒绝的提案** 及其确定性理由。对于合同网协议的管理者，落选的竞标者需要了解原因。

## 练习

1. 运行`code/main.py`。确认OG-Narrator在成交率上击败朴素大语言模型。差距有多大？
2. 实现**基于人格的收益提升**（arXiv:2402.05863）——买方仅在叙述中采用"急需本周购买"的人格，报价生成器不变。成交率或收益是否发生变化？
3. 实现思维链**隐藏**：维护一个不传递给对手的私密草稿纸字符串。如果不小心泄露了会怎样（通过交换渠道来模拟）？
4. 将合同网协议扩展为带保留价的N竞标者拍卖。当所有出价都超过保留价时，管理者如何在最低价和最高质量之间做出选择？你选择哪种授标规则，为什么？
5. 阅读Bhattacharya等人2025年关于哈佛谈判项目指标的论文。实现两个具有不同风格（攻击型 vs 公平型）的议价者。在对称和非对称配对下测量收益方差。

# 失效模式——MAST、群体思维、单文化与级联错误

> 2026 年的参考分类体系是 **MAST**（Cemri 等人，NeurIPS 2025，arXiv:2503.13657），基于 7 个最先进的开源多智能体系统的 1642 条执行轨迹推导而来，显示**41-86.7% 的失败率**。三大根因类别：**规格问题**（41.77%）——角色模糊、任务定义不清；**协调失败**（36.94%）——通信中断、状态失步；**验证缺口**（21.30%）——缺少验证、质量检查缺失。**群体思维**系列（arXiv:2508.05687）补充了：单文化崩溃（相同基础模型导致相关性失败）、从众偏差（智能体相互强化错误）、心智理论缺陷、混合动机动态、级联可靠性失败。级联示例：重试风暴，其中支付失败触发订单重试，订单重试触发库存重试，最终压垮库存服务（数秒内负载增长 10 倍——需要断路器）。记忆投毒：一个智能体的幻觉进入共享记忆，下游智能体将其视为事实；准确率逐渐衰减，使根因诊断变得困难。**STRATUS**（NeurIPS 2025）报告通过专门的检测/诊断/验证智能体将缓解成功率提高了 1.5 倍。本课将失效模式作为一等工程目标来对待。

## 问题

多智能体系统在真实任务上的失败率为 41-86.7%（Cemri 等人 2025 年在 7 个开源多智能体系统上测量得出）。这不是"再加几个智能体"就能调试的。失败有结构性原因。MAST 分类体系为你提供了类别。本课将每个类别映射到具体的检测、诊断和缓解模式，让这些数字不再看起来随意。

2026 年的生产实践是将失效模式视为设计输入。你的架构在你能指出每个 MAST 类别并说出你部署的缓解措施之前，都不算"足够好"。

## 概念

### MAST 类别

**规格问题（41.77% 的失败）。** 智能体的任务定义不够严密。示例：

- 角色模糊：两个智能体都认为自己是审查者。
- 任务规格不足：用户想要特定角度时只说了"总结一下"。
- 成功标准隐含：智能体无法判断自己是否成功。

缓解措施：
- 编写显式的角色合约。每个智能体的提示词说明它做什么*以及不做什么*。
- 每个任务的验收测试。在智能体开始前，定义"完成的样子是 X"。
- 预检规格检查：一个单独的智能体在分发前审查任务定义。

**协调失败（36.94%）。** 通信或状态中断。

示例：
- 两个智能体在没有同步的情况下更新共享状态。
- 智能体之间的消息丢失（队列失败、超时）。
- 状态漂移：智能体 A 认为任务已完成；智能体 B 仍在执行。

缓解措施：
- 带乐观并发的版本化共享状态。
- 关键消息的显式确认（重试直到收到确认）。
- 定期状态同步检查点；尽早检测漂移。

**验证缺口（21.30%）。** 没有对输出进行独立检查。

示例：
- 一个智能体声称成功；没有人验证。
- 智能体链中每个都信任前一个的输出。
- 涌现的组合行为缺少测试覆盖。

缓解措施：
- 独立的验证者智能体（第 13 课）。只读，独立的源访问权限。
- 显式的交接合约："A 的输出必须通过检查器 C 才能让 B 开始。"
- 结果日志用于事后分析。

### 群体思维系列（arXiv:2508.05687）

当智能体同质化或相互模仿时出现的五种相关失败：

**单文化崩溃。** 相同的基础模型或训练数据导致相关性错误。当三个智能体共享一个 LLM 时，它们共享其幻觉。

**从众偏差。** 智能体向声音最大或最自信的同伴靠拢，即使对方是错的。

**心智理论缺陷。** 智能体无法建模彼此的信念；协调瓦解（第 18 课）。

**混合动机动态。** 激励部分对齐的智能体漂移向折中方案，结果无法满足任何人。

**级联可靠性失败。** 一个组件的错误模式触发依赖组件的错误模式。

### 级联示例——重试风暴

2026 年的经典事故模式：

```
payment service fails 10% of requests
   ↓
order agent retries payment (exponential backoff but naive)
   ↓
each retry is a new order-inventory check
   ↓
inventory service sees 2x normal load
   ↓
inventory service starts timing out
   ↓
every order retries inventory check
   ↓
inventory service sees 10x normal load
   ↓
cluster goes down
```

修复方法是经典的：**断路器**。当下游错误率超过阈值时，使用缓存或默认结果进行短路。加上每次请求的重试预算上限。

断路器是少数几个可以直接从分布式系统借用而无需修改的多智能体失败缓解措施之一。

### 记忆投毒（再探）

来自第 13 课：一个智能体的幻觉成为共享记忆中的事实；下游智能体基于被投毒的事实进行推理。在 MAST 术语中，这是共享记忆层的验证缺口。

准确率逐渐衰减是症状。你不会看到崩溃；你看到的是难以定位根因的缓慢漂移。

缓解措施：仅追加日志、来源追踪、不可写验证者。已在第 13 课中涵盖。

### STRATUS——专门的失败检测智能体

STRATUS（NeurIPS 2025）报告在部署以下组件时缓解成功率提高了 1.5 倍：

- **检测智能体。** 监控症状模式（高分歧率、重试峰值、准确率漂移）。
- **诊断智能体。** 根据症状，从 MAST 分类体系推断可能的根因。
- **验证智能体。** 缓解措施应用后，检查症状是否消除。

这是 SRE 风格的事件响应，应用于智能体系统。这三个角色都可以是带有专门提示词的 LLM 智能体。

### 失效模式审计

2026 年的最佳实践是每年（或每次重大发布）进行一次失效模式审计：

1. **轨迹采样。** 收集约 1000 条真实执行轨迹。
2. **分类。** 对每条轨迹的失败，映射到 MAST + 群体思维类别。
3. **计算各类别的失败率。** 哪些类别在你的系统中占主导？
4. **缓解措施排名。** 哪个修复能消除最多的失败？
5. **选择 2-3 个缓解措施。** 实施；下个季度重新审计。

纪律比具体选择更重要。没有审计，失败会混入噪声中，永远不会被系统性地解决。

### 静默失效的系统

最危险的失败类别是静默正确性失败。大声失败的系统（崩溃、异常、告警）可以被监控。产生看似合理但错误输出的系统无法通过异常日志检测。这就是为什么验证缺口虽然仅占 21.30% 的数量，却是每次失败成本最高的类别。

投入：
- 基于抽样的人工审查。
- 黄金数据集回归测试。
- 重要输出的跨智能体交叉检查。

### 失败与缓慢失败

有些失败是即时的；有些是缓慢的。即时失败（超时、模式不匹配、认证错误）检测成本低。缓慢失败（记忆投毒、单文化漂移、角色模糊）检测和预防成本高。

2026 年的工程手段：为缓慢失败的代理指标埋点，以便在漂移变成可见错误之前捕获它。一致率、重试率、输出长度分布和连续智能体版本之间的编辑距离都是有用的代理指标。

## 投入生产

生产中的失效模式纪律：

- **每季度一次 MAST 审计。** 不是每年。类别随系统增长而变化。
- **处处使用断路器。** 每个对外部依赖服务的出站调用。默认打开阈值设在 5-10% 错误率。
- **黄金数据集。** 小型、高质量、人工审核。每周对它们进行回归测试。
- **STRATUS 三件套。** 检测 + 诊断 + 验证智能体监控生产环境。先从检测智能体开始；当症状嘈杂时再加诊断。
- **失败预算。** 按类别的显式失败率 SLO。超出预算触发停止发布讨论。

## 练习

1. 运行 `code/main.py`。确认断路器限制了重试风暴。改变失败阈值并观察权衡。
2. 实现一个**缓慢失败代理指标**：3 个并行智能体之间的一致率。当它急剧下降时，触发告警。通过逐渐关联智能体输出来模拟单文化漂移。
3. 阅读 Cemri 等人的论文（arXiv:2503.13657）。选择他们的 7 个多智能体系统之一，映射其前 3 个失败类别。这些与 MAST 的预测相比如何？
4. 阅读群体思维论文（arXiv:2508.05687）。找出五种模式中哪一种在生产中最难检测。提出一个代理指标。
5. 为你熟悉的特定多智能体系统设计一个 STRATUS 风格的检测-诊断-验证三件套。检测监控哪些症状？诊断推荐哪些缓解措施？验证如何确认它们有效？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|---------|---------|
| MAST | "2026 年分类体系" | Cemri 2025；3 个根因类别 + 14 个失败子类型。 |
| 规格问题 | "角色模糊" | 任务或角色定义不足；智能体不知道该做什么。 |
| 协调失败 | "状态漂移" | 智能体之间的通信或同步中断。 |
| 验证缺口 | "没人检查" | 输出未经独立验证即被接受。 |
| 群体思维系列 | "同质化失败" | 单文化、从众、心智理论缺陷、混合动机、级联。 |
| 单文化崩溃 | "同一模型，同一幻觉" | 来自共享基础模型或训练数据的相关性错误。 |
| 重试风暴 | "级联错误放大" | 一个失败触发重试，重试放大下游负载。 |

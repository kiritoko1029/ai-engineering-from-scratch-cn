# 指令跟随作为对齐信号

> 后续所有对 RLHF 的批评都在反驳这条流程。在你研究优化压力如何扭曲代理之前，你必须先看到这个代理。InstructGPT（Ouyang 等，2022）定义了参考架构：在指令-回答对上进行监督微调，在成对偏好排序上训练奖励模型，以及带 KL 惩罚的 PPO 以保持与 SFT 策略的距离。一个 13 亿参数的 InstructGPT 在人类偏好评估中击败了 1750 亿参数的 GPT-3。这一个结果就是 2026 年所有前沿实验室仍然采用 RLHF 形式后训练流程的原因。

**类型：** 学习
**语言：** Python（标准库，玩具三阶段流程）
**前置要求：** 第 10 阶段 · 06（SFT），第 10 阶段 · 07（RLHF），第 10 阶段 · 08（DPO）
**所需时间：** 约45分钟

## 学习目标

- 说出 InstructGPT 流程的三个阶段以及每个阶段使用的损失函数。
- 解释为什么一个 13 亿参数的指令微调模型能在人类偏好评估中击败原始的 1750 亿参数 GPT-3。
- 说明第 3 阶段中的 KL 惩罚保护的是什么，以及为什么移除它会导致模式坍缩行为。
- 描述对齐税以及 Ouyang 等人用来缓解它的 PPO-ptx 方法。

## 问题所在

预训练语言模型补全文本。它们不回答问题。问 GPT-3 "写一个反转列表的 Python 函数"，你通常会得到另一个提示续写，因为训练分布中的大部分是网络文本，模型会继续生成更多网络文本。模型在做它的工作——只不过这个工作本身是错的。

每个严肃实验室用来修复这个问题的代理是人类偏好。两个补全发送给标注者；标注者选择更好的那个；奖励模型学习标注者的偏好。然后 RL 循环将策略推向奖励模型评分更高的输出。这就是 InstructGPT 论文的全部核心，三句话就能概括。论文的其余部分都是工程实现。

## 概念说明

### 第 1 阶段：监督微调（SFT）

收集提示-回答对，其中的回答是一个善意的人类会写出的内容。Ouyang 等人使用了来自标注者和 OpenAI API 的 13,000 条提示。使用标准交叉熵损失在这些数据上微调基础模型。

SFT 给你的是：模型现在会回答问题而不是续写问题。SFT 不给你的是：当多个回答都看似合理时，标注者更偏好哪个回答的信号。

### 第 2 阶段：奖励模型（RM）

对于每个提示，从 SFT 模型中采样 K 个补全。标注者对它们进行排序。训练一个奖励模型，使其对任意提示-回答对进行评分，使得当 `y_w` 被偏好于 `y_l` 时：

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

这是 Bradley-Terry 成对偏好损失。RM 通常从 SFT 模型初始化，将语言模型头替换为标量头。

奖励模型很小：60 亿参数就足以支撑 1750 亿参数的 InstructGPT。它们也很脆弱——论文的第 5 节主要讨论了在小规模上出现的奖励黑客行为。

### 第 3 阶段：带 KL 惩罚的 PPO

定义目标：

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

使用 PPO 进行最大化。KL 项使 `pi` 不会偏离 SFT 策略太远。没有它的话，优化器会找到对抗样本——那些在 RM 下得分很高的字符串，因为 RM 从未见过它们，而不是因为人类真正偏好它们。

KL 系数 `beta` 是 RLHF 最重要的超参数。太低：奖励黑客。太高：相比 SFT 没有改善。

### 对齐税

经过 RLHF 后，模型在人类偏好上更优，但在标准基准（SQuAD、HellaSwag、DROP）上退步。Ouyang 等人将此称为对齐税，并用 PPO-ptx 来修复：将预训练梯度混入 RL 目标，使模型不会遗忘它从未获得奖励的下游任务能力。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx 成为标准做法。Anthropic、DeepMind 和 Meta 都使用了某种变体。

### 结果

一个 13 亿参数的 InstructGPT（SFT + RM + PPO-ptx）在约 70% 的情况下被标注者偏好于 1750 亿参数的基础 GPT-3。在来自生产流量的隐藏测试提示上，差距更大。从这个数字中可以读出两点：

1. 对齐与能力是不同的维度。1750 亿参数的模型有更多能力；13 亿参数的模型有更多对齐；标注者偏好对齐的那个。
2. 能力下限由基础模型决定。你无法通过 RLHF 让基础模型知道它从未见过的事实。

### 为什么这是第 18 阶段的参考点

后续课程中的每个批评——奖励黑客（第 2 课）、DPO（第 3 课）、谄媚（第 4 课）、CAI（第 5 课）、潜伏代理（第 7 课）、对齐伪装（第 9 课）——都在反驳这条流程的某个部分。奖励黑客攻击第 2 阶段。DPO 合并第 2 和第 3 阶段。CAI 替换人类标注者。谄媚表明标注者是带有偏见的信号。对齐伪装表明策略可以完全绕过第 3 阶段。如果你脑中没有这条流程，就无法理解这些批评中的任何一个。

需要关注的内容：

- `beta = 0.1` 与 `beta = 0.0` 时的奖励轨迹。
- 训练步骤中的 KL(pi || pi_SFT)。
- 与标注者偏好相比的最终动作分布。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------|---------|
| SFT | "指令微调" | 第 1 阶段：在提示-回答对上进行交叉熵微调 |
| 奖励模型 | "RM" | 对（提示，回答）的标量回归器，使用 Bradley-Terry 在成对标签上训练 |
| Bradley-Terry | "成对偏好损失" | -log sigmoid(r_w - r_l)；将成对排序简化为二分类 |
| KL 惩罚 | "正则化器" | `beta * KL(pi \|\| pi_SFT)`——使 RL 策略保持在 SFT 锚点附近 |
| PPO-ptx | "带预训练混合的 PPO" | 在 PPO 目标中加入一部分预训练对数似然以抵消对齐税 |
| 对齐税 | "RLHF 退步" | RLHF 后在未被 RLHF 针对的标准基准上的性能下降 |
| 标注者偏好 | "真实标签" | 人类排序的样本；RM 是其统计代理，而非"人类价值"的代理 |
